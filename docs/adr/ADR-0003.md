# ADR-0003: `ng` and `ng-bootstrap` release together under fixed versioning and ship as tarballs on GitHub Releases

**Status:** accepted (2026-07-22) · **Scope:** every publishable ngkit library

## Decision

`ng` and `ng-bootstrap` release together under **fixed/grouped versioning** (Nx's default `projectsRelationship`), the model Angular uses for `@angular/*`: every release bumps and republishes both, even if only one changed. A new publishable library is added to the group.

Internal peer dependencies between these libraries (for example `ng-bootstrap`'s peer on `ng`) are rewritten to an **exact pin** on release, not a `^` range. Don't widen them by hand.

Releases distribute as tarballs attached to GitHub Releases (a versioned tag plus a rolling `latest` release), not as npm packages. npm publishing is disabled by a hardcoded `dryRun: true` on both libraries' `nx-release-publish` targets. The route back is npm Trusted Publishing (GitHub Actions OIDC, no long-lived token), configured per package.

Hotfixes to an older major are cut from `release/<major>.x`, made from the last tag of that major. The fix lands on `main` first and is cherry-picked back. The release uses `dist-tag: v<major>-lts`, never `latest`, which only moves on releases from `main`.

## Consequences

- A release republishes a library that did not change.
- Consumers install a matched pair and never mix versions.
- Consumers fetch tarballs from GitHub Releases instead of a registry.
- Re-enabling npm means removing `dryRun` and setting up Trusted Publishing; see [Releasing](../runbooks/releasing.md).

## Alternatives considered

- **Independent versions per library.** Consumers would have to track which `ng-bootstrap` works with which `ng`; the exact peer pin makes that automatic under one version.
- **Version bumps derived from conventional commits** (commitlint, semantic-release, `nx release plan` version plans). The person running a release picks `patch`, `minor`, `major` or an exact version instead; see [Releasing](../runbooks/releasing.md#2-breaking-changes) for what that means for the changelog.
- **Prerelease or canary channels** (a `next` dist-tag). Out of scope; `latest` and `v<major>-lts` are the only tags.
- **npm with a long-lived token.** A stored publish token is a standing credential; Trusted Publishing needs none.
