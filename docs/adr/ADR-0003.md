# ADR-0003: The publishable libraries release together under fixed versioning and ship as tarballs on GitHub Releases

**Status:** accepted (2026-07-22, amended 2026-11-14) · **Scope:** every
publishable ngkit library

## Decision

`ng`, `ng-bootstrap` and `ng-tailwind` release together under **fixed/grouped
versioning** (Nx's default `projectsRelationship`), the model Angular uses for
`@angular/*`: every release bumps and republishes all of them, even if only one
changed. A new publishable library is added to the group.

Internal peer dependencies between these libraries (for example `ng-bootstrap`'s
peer on `ng`) are declared `workspace:^` and publish as a **caret range** on the
released version. Before 1.0, `^0.x.y` admits only that minor, so a breaking
minor still forces a matched upgrade.

Releases distribute as tarballs attached to GitHub Releases (a versioned tag
plus a rolling `latest` release), not as npm packages. npm publishing is
disabled by a hardcoded `dryRun: true` on both libraries' `nx-release-publish`
targets. The route back is npm Trusted Publishing (GitHub Actions OIDC, no
long-lived token), configured per package.

## Consequences

- A release republishes a library that did not change.
- Consumers install a matched set; within one pre-1.0 minor, a patch of `ng`
  satisfies the peer of any other patch.
- Consumers fetch tarballs from GitHub Releases instead of a registry.
- Re-enabling npm means removing `dryRun` and setting up Trusted Publishing; see
  [Releasing](../runbooks/releasing.md).

## Alternatives considered

- **Independent versions per library.** Consumers would have to track which
  `ng-bootstrap` works with which `ng`; one fixed version makes that
  automatic, and the caret peer range keeps it so until 1.0.
- **Version bumps derived from conventional commits** (commitlint,
  semantic-release, `nx release plan` version plans). The person running a
  release picks `patch`, `minor`, `major` or an exact version instead; see
  [Releasing](../runbooks/releasing.md#2-breaking-changes) for what that means
  for the changelog.
- **Prerelease or canary channels** (a `next` dist-tag). Out of scope; `latest`
  is the only tag.
- **npm with a long-lived token.** A stored publish token is a standing
  credential; Trusted Publishing needs none.

## Background

- 2026-11-14: internal peers were exact pins; they are now caret ranges. kiln's
  internal-ranges check (kiln F15.4) rejects `workspace:*`, and the owner
  plans independent versions and npm publishing, deferred as
  [E18](../specs/epics/E18-npm-publishing-and-independent-versions/index.md),
  where a caret range is the form that survives.
- 2026-11-02: kiln's generated release runs from the default branch only (kiln's
  S9.1.7, 2026-10-29), so the `release/<major>.x` rule and the `v<major>-lts`
  tag are retired until a hotfix line is needed and decided in a new ADR.
  ngkit has no `release/**` branch.
