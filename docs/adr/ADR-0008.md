# ADR-0008: `ng-tailwind` ships prebuilt, scoped CSS on namespaced tokens; Tailwind is an optional bridge

**Status:** accepted (2026-10-24) · **Scope:** `@rn-forge/ng-tailwind` and every component in it

## Decision

- **Components ship their own CSS.** Each component styles in its emulated-encapsulation stylesheet, inside `@layer rnf`, and reads only `--rnf-*` custom properties. Templates use no Tailwind utility, so no consumer scans the package or safelists a class, and an application without Tailwind renders every component.
- **Tokens are the only global the package defines by default.** `tokens.css` declares `--rnf-*` on `:root` inside `@layer rnf`; it sets no element style, no `color-scheme`, no font and no brand palette. `base.css` (element defaults) and `tailwind.css` (the bridge) are opt-in files.
- **Light and dark come from `color-scheme`.** Colour tokens are `light-dark(<light>, <dark>)` pairs, so they follow the `color-scheme` the application sets on any ancestor: `dark` on `html`, `light dark` to follow the OS, or a value on one subtree. With none set, the light values apply.
- **The bridge maps, it does not import.** `tailwind.css` is one `@theme inline` block mapping Tailwind's colour, radius, font and size namespaces onto `var(--rnf-*)`, and clearing Tailwind's default colour palette. The application imports Tailwind itself, with or without preflight, and owns `@source`.

## Consequences

- An application re-themes in one bridge file of `--rnf-*` values, and a theme switch is a `color-scheme` change, which the [E7](../specs/epics/E7-theme-controller/index.md) service can drive.
- Unlayered application CSS beats every package rule without specificity tricks; Tailwind's `utilities` layer wins when Tailwind is imported after the package sheets.
- With the bridge, `bg-slate-500` and other default-palette utilities produce nothing; an application that wants them re-declares the palette after the bridge.
- `light-dark()` needs Chrome 123, Firefox 120 or Safari 17.5, inside the browsers Angular 22 supports.

## Alternatives considered

- **Tailwind utilities in component templates.** Every consumer must run Tailwind and scan `node_modules`, and dynamically composed classes need a safelist; a consumer without Tailwind gets unstyled components.
- **Dark tokens under `@media (prefers-color-scheme: dark)` on the toolkit's scope.** An application that pins one scheme, as each surveyed application does, must override every colour token to escape the OS; a dark subtree inside a light page needs a second mechanism.
- **A bridge that imports Tailwind's layers with `source(none)`.** It turns off the application's own source detection and imports Tailwind a second time beside the application's import, and a package file cannot name the application's `@source` path.
- **Preflight or element resets by default.** They restyle every element of the host application, including ones the package never renders.

## Background

E8's design before 2026-10-24 selected dark tokens by `prefers-color-scheme` and had the bridge import Tailwind's theme and utilities with `source(none)`. A 2026-10-24 survey of three applications to be rebuilt on this package found each pinning a dark scheme, and one needing the bridge to name its own `@source`; both rules changed to the ones above. The owner accepted it on 2026-10-24 ([S8.2.1](../specs/epics/E8-tailwind-package/F8.2-css-contract.md#s821--accept-adr-0008)).
