# ADR-0005: The resource screen targets published wire standards, not a backend

**Status:** accepted (2026-09-23) · **Scope:** `@rn-forge/ng/crud`, `@rn-forge/ng-bootstrap/crud` and any future renderer

## Decision

The screen is a client of the wire standards: RFCs first, then Google's API Improvement Proposals where no RFC applies. It works against any backend that follows them, and nothing in it names or detects a backend.

Order of authority: the published standard, then Angular's own mechanism, then an ngkit wrapper.

## Consequences

- A backend with its own envelope (for example DRF's `{count, next, previous, results}`) maps into the screen's contract inside the app's own data source. ngkit ships no adapter for one framework's envelope.
- `standardDataSource()` is the implementation for standards-following backends (decided 2026-09-23; revisit if usage drifts across apps).
- AIP + RFC is a published convention, not a backend dialect. That is why the screen's interface belongs in ngkit while a generic REST client doesn't ([ADR-0004](ADR-0004.md)).
- The standards the screen relies on are tabled in [the resource screen architecture](../architecture/resource-screen.md).

## Influences

[Resource screen architecture](../architecture/resource-screen.md) and [E4](../specs/epics/E4-standard-resource-screen/index.md).

## Alternatives considered

- **An envelope adapter for one framework in ngkit.** It encodes one backend's dialect in a shared library, which ADR-0004 rules out.
- **A generic `RestResource<T>`.** It hides list envelope, ID type and PUT-versus-PATCH choices in the library instead of naming a standard.
