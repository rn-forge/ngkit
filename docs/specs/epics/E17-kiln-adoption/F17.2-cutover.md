ngkit adopts kiln's `node-lib` archetype in place. kiln's files are overlaid
from a `kiln new` reference; kiln's generated workflows, setup action, Nx Cloud
agent template and `ci:*` tasks then replace ngkit's copies; and the owner
reviews the applied change against the verdicts on this page. ngkit's libraries,
apps, manifests and lock file are not touched. This page keeps the reasons, the
verdicts and each story's acceptance; the build steps and scripts are in git
history.

out the findings from the other repositories it builds, and nothing here waits

## S17.2.6 — Upgrade Nx to kiln's pin

**State:** Closed (2026-11-08) · **Depends on:** none · pre-cutover: needs no
kiln, lands on `feature/kiln-cutover` before S17.2.1

Run 2026-11-08: every build step exited 0 and the acceptance block exits 0
(`@angular/core` 22.2.5, Nx 24.0.4); git history keeps the run.

Added 2026-11-07 from kiln's rehearsal
([kiln S7.2.4](https://github.com/rn-forge/kiln/blob/main/docs/specs/epics/E7-pykit-release-pin-flip/F7.2-kiln-release-and-config-upgrade.md)).
kiln's `NX_VERSION` is `24.0.4`; ngkit is on Nx `23.1.0` and Angular `~22.1.7`.
The rehearsal on ngkit `0c2cd2a` ended with `task validate` exit 201, caused
only by `node:lint:audit` (`pnpm audit --prod --audit-level moderate`), which
reported these advisories:

| Package | Advisories | Vulnerable range | Patched at |
| -- | -- | -- | -- |
| `@angular/router` | three, high | `>=22.0.0 <22.2.0`, `<22.2.1` twice | `22.2.0`, `22.2.1` twice |
| `zod` | one, high (via `@angular/forms`) | `<4.6.6` | `4.6.6` |
| `browserslist` | two, high (via `@angular/localize`) | `<=4.28.6` | `4.28.7` |
| `baseline-browser-mapping` | one, moderate (via `@angular/localize`) | `>=2.0.0 <2.11.0` | `2.11.0` |

The same seven were reported again on 2026-11-07, on a scratch copy of
`feature/release-3`, with one low advisory that `--audit-level moderate`
ignores.

The upgrade is safe on ngkit's current CI: it runs `lint`, `test`, `build`,
`e2e` and the `package` job's `pack`, `verify-dist` and `verify-consumer`
through Nx, and this story's acceptance runs the same targets.

**Revised 2026-11-08 (owner decision).** The libraries' Angular devDependencies
follow the workspace version ([ADR-0002](../../../adr/ADR-0002.md)), so the
first run, which left `libs/*/package.json` as they were, was wrong: it said
`^22.1.7` "already admits `22.2.1`", but pnpm keeps a lockfile resolution that
still satisfies its range, so Angular split into 22.1.7 and 22.2.5 and
`ng-bootstrap:build` failed. `pnpm update -r` re-resolved every dependency
within its range and also raised the specifiers in the root and library
`package.json` files to the resolved versions (the libraries' Angular
devDependencies to `^22.2.5`, cdk to `^22.2.6`), matching what a repository
created today gets. Peers are unchanged.

**Revised 2026-11-08 (owner decision).** Angular stays on 22.x.
`@nx/angular@24.0.4` declares its peers `@angular/build`, `@angular-devkit/*`,
`@schematics/angular` and `ng-packagr` as `>= 20.0.0 < 23.0.0` (checked with
`pnpm view @nx/angular@24.0.4 peerDependencies` on 2026-11-08), so Nx 24.0.4
needs no Angular major. If `nx migrate 24.0.4` writes any `@angular/*` or
`@angular-devkit/*` entry in the root `package.json` outside 22.x, stop and
report it (ADR-0002 sets the tested floor `^22.0.6`). A move within 22.x is
fine, and it may fix the `@angular/router` advisories without a pinned override.

**Acceptance:**

```bash
set -euo pipefail
test ! -e migrations.json
test "$(pnpm exec nx --version | grep -Eo '[0-9]+\.[0-9]+\.[0-9]+' | head -n 1)" = 24.0.4
node -e 'const p=require("./package.json");const d={...p.dependencies,...p.devDependencies};const bad=Object.entries(d).filter(([k,v])=>(k==="nx"||k.startsWith("@nx/"))&&v!=="24.0.4");if(bad.length){console.error(bad);process.exit(1)}'
node -e 'const p=require("./package.json");const d={...p.dependencies,...p.devDependencies};const bad=Object.entries(d).filter(([k,v])=>(k.startsWith("@angular/")||k.startsWith("@angular-devkit/"))&&!/^[~^]?22\./.test(v));if(bad.length){console.error(bad);process.exit(1)}'
pnpm audit --prod --audit-level moderate
pnpm exec nx run-many -t lint test build
pnpm exec nx run-many -t pack verify-dist verify-consumer
```

- Every command above exits 0.
- On GitHub, ngkit's own CI is green on the `feature/release-3` → `main` pull
  request (S17.2.5), which carries this story (not checkable inside the
  repository).

## S17.2.1 — Overlay the kiln reference

**State:** Closed (2026-11-14) · **Depends on:** S17.2.6, S17.1.5, S17.2.7,
S17.2.9, S17.2.10, S17.2.11

The method is an overlay of a reference repository that `kiln new` built:
ngkit's git history is kept, kiln's files are copied, and ngkit's nuances are
explicit steps, each with its reason.

A difference ngkit needs inside a managed file or block is a kiln finding, never
an edit of the copy.

**The rule that decides every difference.** The reference's `state.json` names
each path's class (31 managed, 3 blocks, 17 seeded).

| Class | What the overlay does |
| -- | -- |
| Managed | Copied from the reference, byte for byte (step 1); `mkdocs.yml`'s nav is then derived from ngkit's tree (step 10). |
| Managed block | The block is the reference's, byte for byte; ngkit's text around it stays (step 3). |
| Seeded | ngkit's page wins where ngkit has one; a seeded file ngkit lacks is the reference's (step 4). |
| Repository-owned | ngkit's wins; configuration kiln shapes is aligned by a named step. |

**The nuances ngkit keeps on top of the reference**, each one a step:

| Step | Nuance | Why |
| -- | -- | -- |
| 3 | `.gitignore` adds `.nx/polygraph`, `storybook-static`, `documentation.json` and the two `sqlite3` lines before kiln's block | Nx Cloud scratch, Storybook and Compodoc output, the Django fixture's database |
| 3 | `AGENTS.md` is ngkit's instructions (today's `CLAUDE.md`: the Nx-managed section and the project guidelines) above kiln's block; `CLAUDE.md` is the reference's `@AGENTS.md` | kiln's standard keeps instructions in `AGENTS.md` (F17.3, Removed into this step) |
| 4 | ngkit's seeded pages and `ngkit.code-workspace` stay; `docs/_areas.yml` is the reference's | `_areas.yml` takes `specs` as `nav: work` (S17.1.4) |
| 6 | `nx.json`'s `pack` and `verify-dist` call `task ci:dist:resolve` and `task ci:dist:verify` | step 5 deletes `tools/ci`; the rest of `nx.json` is ngkit's |
| 7 | The pages that name a deleted file or the retired CI shape say what replaced it | `kiln doctor` and `mkdocs --strict` fail on a link to a deleted page; S17.2.3 rewrites the rest |

**Steps.** Run every command from the repository root, in order. An exit code
other than 0 stops the run. Nothing is committed until step 14.

| Step | What it does |
| -- | -- |
| 0 | Checkout named `ngkit`, origin, branch, the S17.2.6, S17.2.9, S17.2.10 and S17.2.11 commits in history, clean tree, no `.rn-forge/kiln`, the reference at `9dfd134` and clean, kiln's pushed `feature/v1` holding `3ee1af6`. Prints `BASE`. |
| 1 | The 31 managed files, `state.json`, `config.toml`. |
| 2 | Asserts the config holds `ngkit-new.toml`'s values. Edits nothing. |
| 3 | `.gitignore`, `.prettierignore` (the reference's whole), `AGENTS.md`, `CLAUDE.md`. |
| 4 | `.mdformat.toml`, `.taplo.toml`, `.yamlfmt.yaml`, `.python-version`, the root `pyproject.toml`, `recovering-from-drift.md`, the epics and ideas indexes; `docs/_areas.yml`. `uv.lock` is not copied. |
| 5 | `release.yml`, `docs/architecture/ci-template.md`, the five `tools/ci` helpers. |
| 6 | The two `nx.json` commands. |
| 7 | Edits to `docs/architecture/index.md`, `release-pipeline.md`, F11.1 and `AGENTS.md`, matched across line wraps. |
| 8 | `task setup`; `package.json` and `pnpm-lock.yaml` unchanged; `uv.lock` equals the reference's. |
| 9 | `task format`. |
| 10 | `task docs:generate` (the nav, the epic list); a second run changes nothing. |
| 11 | `task kiln:diff`, `task kiln:apply`; `config.toml` and `state.json` stay the reference's. |
| 12 | `task validate`, `KILN_DOCTOR_FULL=1 task lint`, `task docs:build`, `pnpm audit --prod --audit-level moderate`. |
| 13 | The acceptance below. Prints nothing. |

**Acceptance:** the cutover's final assertion script asserts:

- `release.yml`, `tools/ci` and `ci-template.md` are gone, and `nx.json` names
  no `tools/ci` helper;
- nothing is staged; `apps`, `libs`, `tools/scripts`, the manifests, the lock

  under `apps`, `libs` or `tools`;

**Findings for kiln:**

- kiln S16.9.14 (Closed 2026-11-13): the derived board copied a deferred epic's
