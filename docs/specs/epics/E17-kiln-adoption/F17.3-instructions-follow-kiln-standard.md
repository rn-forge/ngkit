ngkit's developer and agent instructions move to the shape kiln's standard gives
every repository: `README.md` is the single prose home, `CLAUDE.md` is a pointer
to it plus kiln's generated block, and `AGENTS.md` is a pointer to `CLAUDE.md`.

## Context

**Owner decision, 2026-11-09:** ngkit follows kiln's standard for instruction
files. Developer instructions live in `README.md`; `CLAUDE.md` holds only the
reference's pointer text and the kiln block; `AGENTS.md` is the reference's
pointer. Passages that matter only to AI agents still go to `README.md`: kiln's
own repository does the same, and one prose home is the point
([kiln ADR-0003](https://github.com/rn-forge/kiln/blob/main/docs/adr/ADR-0003.md)).

This supersedes the S17.2.1 decision that ngkit's agent guide stays in
`CLAUDE.md` (its step 6 and the appendix line "Moving it is a docs-model change,
not part of the cutover; the owner may ask for it later"). The owner has now
asked.

The reference is `../_reference/ngkit` (`README.md`, `CLAUDE.md`, `AGENTS.md`),
read-only. Its `CLAUDE.md` and `AGENTS.md` are exactly what ngkit's become, so
the story copies them rather than retyping them.

   claude = pathlib.Path("CLAUDE.md").read_text()
   readme = pathlib.Path("README.md").read_text()

   def one(text, needle):
       if text.count(needle) != 1:
           sys.exit(f"FAIL: expected exactly one {needle[:50]!r}, found {text.count(needle)}")

       one(claude, start)
       i = claude.index(start) + len(start)
       return claude[i:claude.index(end, i)].strip("\n")

   ci = cut("### CI\n", "### Docs site\n")

       "These principles apply to every current and future entry point and package. When\n"

       "conflicts with one of them, the principle wins, unless the plan or change records\n"
       "the deviation and its reason, in the feature's Design or the doc comment.\n"

- Run everything through `task`. `task validate` is the gate.

  it has patterns for querying projects, targets and dependencies.
- You have access to the Nx MCP server and its tools; use them to help the user.
- To scaffold anything (apps, libraries, project structure, setup), always
  invoke the `nx-generate` skill first, before exploring or calling MCP tools.
  It handles generator discovery itself, so do not call `nx_docs` just to look
  up generator syntax. See also
  [Scaffolding projects](docs/guides/development.md#scaffolding-projects).
- For Nx plugin best practices, check `node_modules/@nx/<plugin>/PLUGIN.md`. Not

## Conflicts with the standard, recorded and not resolved here

- Nx writes and updates the block between `<!-- nx configuration start-->` and
  `<!-- nx configuration end-->` in `CLAUDE.md` (its AI-agent configuration
  command). If someone runs that command, Nx re-adds the block and `CLAUDE.md`
  has prose outside the pointer. Nothing in the repository runs it; if the owner
  wants it prevented, that is a separate decision.
- `README.md` and `docs/guides/development.md` still show direct
  `pnpm nx ...` commands (Getting started, Packing libraries, Commands). The
  kiln block forbids a direct `nx` or `pnpm` in a document. S17.2.3 owns that
  rewrite and lists the commands that have no `task` verb; this story neither
  adds nor rewrites one. The new `README.md` text names no direct command.
- `docs/_structure.md` (managed by kiln, so not editable here) says `CLAUDE.md`
  "links to the specs board and the ADR log and says what each is for". After
  this story the `README.md` does. The sentence is kiln's, to be corrected in
  kiln, not in ngkit.
