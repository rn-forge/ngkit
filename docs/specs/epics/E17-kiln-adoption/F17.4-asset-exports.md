`ng-bootstrap` and `ng-tailwind` export plain asset files (Sass, CSS) next to
their compiled entry points. A post-build script adds those subpaths to the dist
`package.json`; ng-packagr can carry them itself when they are declared in the
source `package.json`. This feature retires the script and its two Nx targets.

## Context

**Why in E17:** the script is the last piece of ngkit-specific build tooling
that kiln's generated `preVersionCommand` has to know about (`nx.json:93`,
rendered from kiln:
`nx run-many -t build patch-package-exports -p tag:publishable`). Removing it
leaves ngkit with nothing but the standard `build`, `pack` and `verify-dist`
targets. Placed in E17 (Active, Release 3) because it is cutover-adjacent; no
other open epic fits.

**What exists (checked 2026-11-10 at `54ad8a7`).**

- `tools/scripts/patch-package-exports.mjs:21-28` reads
  `dist/<projectRoot>/package.json` and sets
  `pkg.exports = { ...added, ...pkg.exports }`, so the added subpaths come
  first.
- `libs/ng-bootstrap/project.json:37-45` defines the `patch-package-exports`
  target (`./assets/*=./assets/*`, `dependsOn: ["build"]`) and `:46-48` makes
  `pack` depend on it. `libs/ng-tailwind/project.json:37-47` does the same for
  `./tokens.css`, `./base.css`, `./tailwind.css` (targets under `./assets/`).
  `libs/ng` has neither.
- Both libraries' `ng-package.json` already copy `assets/**` into dist
  (`"assets": ["assets/**"]`); only the `exports` entry is missing.
- Neither `libs/ng-bootstrap/package.json` nor `libs/ng-tailwind/package.json`
  has an `exports` field.
- ng-packagr's `generatePackageExports`
  (`node_modules/ng-packagr/src/lib/utils/package-json.js`) starts from the
  source `exports`, then adds `./package.json`, `.` and the secondary entry
  points; it warns only about conditions it generates itself.
- Other references: `sonar-project.properties:10` and
  `.rn-forge/kiln/config.toml:120` (`sonar_coverage_exclusions`);
  `CLAUDE.md:80`; `docs/architecture/workspace.md:59-61`;
  `docs/architecture/release-pipeline.md:9-24` and `:58-70`. Older specs (E8
  F8.1, E13, E11 design, F17.2) name the script as history and are not edited.

**The script's comment is only half right.** It says a source `exports` breaks
local dev through the pnpm workspace symlink. The only workspace package that
depends on either library through `workspace:` is `apps/ng-demo`
(`apps/ng-demo/package.json:7`, `ng-bootstrap`; nothing depends on
`ng-tailwind`). TypeScript imports from both go through `tsconfig.base.json`
paths (`:22-29`), not node resolution, and Storybook aliases them
(`libs/*/.storybook/main.ts`). But `apps/ng-demo/src/styles.scss:8` does
`@use '@rn-forge/ng-bootstrap/assets/theme'`, which Sass resolves through
`node_modules/@rn-forge/ng-bootstrap` (a symlink to `libs/ng-bootstrap`) and so
through its `exports`. With the plain `"./assets/*": "./assets/*"` the import
has no extension and `nx build ng-demo` fails with "Can't find stylesheet to
import". So `ng-demo` is the one case, and the `sass` condition below is the
fix. That extensionless form is the one documented to consumers
(`docs/guides/building-an-app.md:112`), so the import is kept and the export
changes, not the import.

**What was proved (2026-11-10).** In a scratch worktree of `54ad8a7`
(`git worktree add --detach <path> HEAD`, removed afterwards), after
`pnpm install --frozen-lockfile` (`--offline` failed on a missing metadata
cache; online succeeded):

1. Baseline, with the script:
   `pnpm exec nx run-many -t build patch-package-exports -p ng-tailwind ng-bootstrap --skipNxCache`
   exit 0; dist `exports` saved.
1. With the `exports` below in both source `package.json` files (ng-bootstrap
   first as the plain string), the script deleted, both
   `patch-package-exports` targets deleted and `pack` reset to `{}`:
   `pnpm exec nx run-many -t build -p ng-tailwind ng-bootstrap --skipNxCache`
   exit 0, no ng-packagr warning. The dist `exports` of `ng-tailwind` were
   identical to the baseline, including key order. `ng-bootstrap`'s were
   identical too, key order included, with the plain string.
1. `pnpm exec nx run-many -t pack verify-dist verify-consumer --skipNxCache`
   exit 0 (`ng-tailwind:verify-consumer`, 1m 17s, ran).
1. `pnpm exec nx build ng-demo --skipNxCache` with the plain string: exit 1, the
   Sass error above. Without any source `exports`: exit 0. With
   `{"sass": "./assets/*.scss", "default": "./assets/*"}`: exit 0, and
   `nx run-many -t build pack verify-dist -p ng-bootstrap` exit 0 with the
   dist entry `{"sass":"./assets/*.scss","default":"./assets/*"}`.

The one difference from the old dist, then, is `ng-bootstrap`'s `./assets/*`: a
condition object instead of a string. `default` is the old target, so every
import that resolved before still resolves to the same file; the `sass`
condition only lets Sass add the `.scss` extension.

## S17.4.1 — Declare the asset subpaths in each library's `package.json`

**State:** New · **Depends on:** S17.2.1, committed

Run from the repository root. `task` is the entry point for every verb that has
one; `pack`, `verify-dist` and `verify-consumer` have none, so the acceptance
block names the Nx line the guide already documents. Tests come first: write the
acceptance block's checks before the edits, and see them fail.

### Build

1. `libs/ng-tailwind/package.json`: add, after `publishConfig`:

    ```json
    "exports": {
      "./tokens.css": "./assets/tokens.css",
      "./base.css": "./assets/base.css",
      "./tailwind.css": "./assets/tailwind.css"
    },
    ```

1. `libs/ng-bootstrap/package.json`: add, after `publishConfig`:

    ```json
    "exports": {
      "./assets/*": {
        "sass": "./assets/*.scss",
        "default": "./assets/*"
      }
    },
    ```

1. `libs/ng-bootstrap/project.json` and `libs/ng-tailwind/project.json`: delete
   the `patch-package-exports` target and replace
   `"pack": { "dependsOn": ["patch-package-exports"] }` with `"pack": {}` (the
   `nx.json` target default supplies `dependsOn: ["build"]`).

1. Delete `tools/scripts/patch-package-exports.mjs`. If `tools/scripts/` holds
   nothing else the repository's tooling references, leave the directory
   alone: `verify-consumer.mjs` lives there.

1. `.rn-forge/kiln/config.toml:120`: drop
   `"tools/scripts/patch-package-exports.mjs"` from
   `sonar_coverage_exclusions`; run `task kiln:apply` so
   `sonar-project.properties` follows. Do not edit the generated file by hand.

1. Docs: delete the `patch-package-exports` bullet in
   `docs/architecture/workspace.md:59-61`; in
   `docs/architecture/release-pipeline.md` replace the
   `## patch-package-exports` section (`:58-70`) with a short
   `## Asset subpaths` section saying that asset subpaths are declared in the
   library's source `package.json` `exports`, which ng-packagr merges into the
   dist manifest, and why `ng-bootstrap` carries the `sass` condition; drop
   "and runs `patch-package-exports` where a project defines it" (`:11-13`)
   and ", including `patch-package-exports`" (`:22`). Replace the `CLAUDE.md:80`
   bullet (in `README.md` once
   [S17.3.1](F17.3-instructions-follow-kiln-standard.md) has moved it) with:
   "A library shipping non-TS assets declares their subpaths in its source
   `package.json` `exports`."

1. `nx.json:93` (`preVersionCommand`) is rendered by kiln and keeps naming
   `patch-package-exports`; Nx skips a project that lacks the target, so the
   command stays correct. Dropping the name from kiln's default is a kiln
   change, not this story.

### Acceptance

```bash
set -euo pipefail
absent() { local rc=0; rg -q --hidden --glob '!.git' --glob '!docs/specs/**' "$@" </dev/null || rc=$?; [ "$rc" -eq 1 ]; }
# the source declares the subpaths
node -e "
const t=require('./libs/ng-tailwind/package.json').exports;
const b=require('./libs/ng-bootstrap/package.json').exports;
const eq=(x,y)=>JSON.stringify(x)===JSON.stringify(y);
if(!eq(t,{'./tokens.css':'./assets/tokens.css','./base.css':'./assets/base.css','./tailwind.css':'./assets/tailwind.css'}))process.exit(1);
if(!eq(b,{'./assets/*':{sass:'./assets/*.scss',default:'./assets/*'}}))process.exit(1)"
# the script and its targets are gone
test ! -e tools/scripts/patch-package-exports.mjs
absent 'patch-package-exports' libs tools docs/architecture CLAUDE.md README.md sonar-project.properties .rn-forge/kiln/config.toml
# the gate and the packaging pipeline still pass
task lint KILN_DOCTOR_FULL=1
pnpm exec nx run-many -t pack verify-dist verify-consumer   # no task verb wraps pack; see docs/guides/development.md:93
# the dist exports equal the old ones
node -e "
const t=require('./dist/libs/ng-tailwind/package.json').exports;
const b=require('./dist/libs/ng-bootstrap/package.json').exports;
const k=(o)=>Object.keys(o).slice(0,3).join();
if(k(t)!=='./tokens.css,./base.css,./tailwind.css'||t['.']===undefined)process.exit(1);
if(Object.keys(b)[0]!=='./assets/*'||b['./assets/*'].default!=='./assets/*'||b['./auth']===undefined)process.exit(1)"
# the demo still resolves the theme through the workspace symlink
task build   # builds ng-demo, which @use's the theme through the symlink
```

The check that `ng-tailwind`'s dist `exports` are byte-for-byte the old ones,
and that `ng-bootstrap`'s differ only in the `./assets/*` value, was made once
by diffing `dist/libs/*/package.json` against a build with the script (see "What
was proved"); the block above keeps the part that cannot rot.

Not scriptable: the release dispatch on GitHub (dry run) builds through
`preVersionCommand`; confirm it completes after the merge.
