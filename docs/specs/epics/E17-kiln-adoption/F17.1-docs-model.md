Every rn-forge repository keeps its docs in one structure, so ngkit's specs,
releases and board take kiln's work model rather than ngkit's own. This is the
conversion every rn-forge repository makes, by the same prompt and the same
standard: `kiln prompt --name adopt`, section 7, which applies the rules of
`kiln prompt --name port-docs`, and the `_structure.md` files `init` writes
(`docs/_structure.md` and one per area). It is the first thing ngkit does to
itself after `init`, and it changes no CI.

## Context

**Depends on:** [S17.2.1](F17.2-cutover.md#s1721-overlay-the-kiln-reference)
(kiln's docs commands run only once `init` has written
`.rn-forge/kiln/config.toml`); kiln's release-1 tag.

**Revised 2026-11-07
([kiln S7.2.4](https://github.com/rn-forge/kiln/blob/main/docs/specs/epics/E7-pykit-release-pin-flip/F7.2-kiln-release-and-config-upgrade.md)).**
The tag is no longer a dependency: ngkit cuts over on kiln's `feature/v1` before
the tag ([F17.2](F17.2-cutover.md)). [S17.1.5](#s1715-links) needs no kiln, so
it moves ahead of S17.2.1 and lands on `feature/kiln-cutover` first. Since
`init` itself runs `task format` and `task docs:generate`, three things this
feature planned by hand now happen inside S17.2.1: the Markdown rewrite
([S17.1.6](#s1716-markdown-is-mdformat-clean) reduces to its `.prettierignore`
line and its check), the derived regions on epic and feature pages, and the
`docs/_areas.yml` change ([S17.1.4](#s1714-areas-nav-and-adr-0007)). Their
acceptance still holds as written.

What the conversion is, in ngkit's terms. kiln's model replaces three things
ngkit does by hand:

| ngkit today | kiln's model |
| -- | -- |
| A status line: `**Status:** done · **Implemented:** <date> (`<hash>`) · **Owner:** ngkit · **Release:** …` | A metadata table under the title with keys `State`, `Parent`, `Iteration`, `Tags`, `Start Date`, `Closed Date`, `Predecessors`, `Source`, `Entry criteria`; states `New`, `Active`, `Closed`, `Removed` |
| `### S<n>.<m>.<k>` story headings under a `## Stories` heading, `**Status:** planned` | `## S<n>.<m>.<k> — <Title>` headings, no `## Stories` heading, `**State:** New` |
| A hand-kept board in `docs/specs/index.md`, hand-kept feature tables in each epic, and a Scope table in each release | Derived regions between `BEGIN derived …` and `END derived …` fences that `task docs:generate` writes; never edited by hand |

What does not change: epic and feature IDs, story IDs, the epic directory names,
every ADR number, and the words of every spec. Content moves verbatim apart from
heading levels, the status line's becoming a table, and links.

## S17.1.1 — Agree the mapping

**State:** Closed (2026-11-03) · **Depends on:** S17.2.1

A decision story, so the conversion can depend on it. `port-docs` step 2
requires the mapping to be agreed before anything moves.

**Build:**

- Write the mapping table into the pull request description, with these rows,
  which are the answer unless the owner changes one:

    | ngkit | kiln |
    | -- | -- |
    | `**Status:** elaborating` / `planned` | `State` `New`; `planned` also carries `Iteration` |
    | `**Status:** in progress` | `Active`, with `Start Date` |
    | `**Status:** done · **Implemented:** <date>` | `Closed`, `Closed Date` = `<date>` |
    | `**Status:** deferred` and its `**Entry criteria:**` | `New`, `Tags` = `deferred`, `Entry criteria` |
    | `**Release:** [Release n](…)` | `Iteration` |
    | `**Owner:** ngkit` | dropped: it is the same on every page; listed in the report as dropped |
    | `**Source:**` | `Source` |
    | `**Depends on:**` on a feature | `Predecessors` |
    | `**Retired:**` | the retired item is kept with `State` `Removed` and one line saying why |
    | an epic with no start date | `Start Date` = the date of the first commit that added the epic's directory: the first line of `git log --diff-filter=A --format=%as --reverse -- <dir>` |
    | an epic or feature that cites a commit hash with its date | the hash goes to a plain line under the table, as "Implemented in commit `0c2cd2a`"; the table value is the date only |
    | done epics whose features are rows in `index.md` | they stay rows, with a `State` column (kiln's model keeps pre-taxonomy epics this way); no feature files are created |
    | `docs/specs/backlog.md` | none exists; `ideas/index.md` stays as `init` seeded it, with no rows |

- The owner agrees the table, or edits a row, in the pull request before S17.1.2
  starts.

**Acceptance:**

- The table is in the pull request description, and the owner's agreement is
  recorded there with its date.

## S17.1.2 — Epics, features and stories

**State:** Active · **Depends on:** S17.1.1

**Build:**

- For each of the 17 epic directories under `docs/specs/epics/` (E1 to E16, and
  this epic, which converts itself), in epic-number order, and for each
  feature file in it: replace the status line with the metadata table of
  `docs/specs/_structure.md` (keys in its fixed order, applying S17.1.1's
  table); keep the `[Back to the board]` line as a plain line under the table.
- Every `### S<n>.<m>.<k> — <Title>` becomes `## S<n>.<m>.<k> — <Title>`, a
  `## Stories` heading above them goes, and each story's `**Status:** <s>`
  becomes `**State:** <New|Active|Closed (<date>)>`; a `**Depends on:**` stays
  on the same line after `·`.
- Each epic with feature files gets `<!-- BEGIN derived features -->` /
  `<!-- END derived features -->` where its hand-written features table was,
  and the table goes. First, for every row, check that the `Scope` cell is
  said in the feature file: a feature whose file has no summary paragraph
  takes the cell as its summary paragraph, under its table, and any other cell
  content goes to the feature's `## Context`. Each feature file gets
  `<!-- BEGIN derived stories -->` / `<!-- END derived stories -->` under its
  table.
- Sections go in `_structure.md`'s order: `## Context` and `## Design` before
  the first story; `## Acceptance`, `## Considered and rejected` and
  `## Open questions` after the last.
- Run `task docs:generate`. Fix every `docs.state-contradicts-work` finding on
  the page it names (an epic or feature state its features or stories
  contradict) by correcting the state to what the stories say, and list each
  correction in the report; never edit inside a derived region.
- Content moves verbatim. Compare words: `git diff --word-diff --stat` shows
  only headings, status lines and the removed tables.

**Acceptance:**

- `rg -c '^### S[0-9]+\.[0-9]+\.[0-9]+' docs/specs` finds nothing, and
  `rg -c '^\*\*Status:\*\*' docs/specs/epics` finds nothing.
- Every epic and feature file opens with `# `, then a metadata table whose first
  key is `State`.
- The number of `## S<n>.<m>.<k>` headings equals the number of `### S…`
  headings before the conversion (recorded in the pull request).
- `task docs:generate` followed by `git diff --exit-code` shows no change, and
  `kiln doctor . --full` reports no `docs.state-contradicts-work` finding.

## S17.1.3 — Releases and the board

**State:** New · **Depends on:** S17.1.2

**Build:**

- Each `docs/releases/release-<n>/index.md` takes kiln's release shape
  (`docs/releases/_structure.md`): metadata table with `Status`, `Start Date`
  and `Finish Date`; sections in the order that file sets (Entry criteria,
  Scope, Decisions, Breaking changes, Progress, Commits, Exit criteria,
  Shipped). The hand-written Scope table becomes the derived region; a
  release's content that fits no section goes under the nearest one, and
  anything with no home is listed as dropped in the report.
- The features each Scope row listed are now recorded by the feature's
  `Iteration`. Check each shipped release's derived Scope names the same
  features as its old table (record any difference in the report; a feature
  moved between releases keeps the release the old table named).
- `docs/specs/index.md`: the Board section becomes kiln's derived board region;
  the paragraph above the board ("As of 2026-10-26, …") becomes a plain
  paragraph under the intro, trimmed to what the derived board does not say;
  the Conventions section is replaced by a link to `_structure.md`; the board
  links `epics/index.md` and `ideas/index.md` ("Every epic, by number, is on
  the epic list" and "Ideas not yet agreed as work are parked in the ideas
  list"). Revised 2026-11-07: the replacement for the Conventions section
  names `docs/specs/_structure.md` as a code span and does not link it
  ([S17.1.5](#s1715-links), kiln's `underscore-referenced` rule).
- Run `task docs:generate`.

**Acceptance:**

- `docs/specs/index.md` has exactly one derived board region, and no
  hand-written epic table.
- Each release page's Scope region lists the features whose `Iteration` names
  it; `docs/releases/release-3/index.md` lists F17.1, F17.2 and F11.1.
- `kiln doctor . --full` reports no release finding.
