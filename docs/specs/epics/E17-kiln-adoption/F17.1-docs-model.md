Every rn-forge repository keeps its docs in one structure, so ngkit's specs, releases and board take kiln's work model rather than ngkit's own. This is the conversion every rn-forge repository makes, by the same prompt and the same standard: `kiln prompt --name adopt`, section 7, which applies the rules of `kiln prompt --name port-docs`, and the `_structure.md` files `init` writes (`docs/_structure.md` and one per area). It is the first thing ngkit does to itself after `init`, and it changes no CI.

## Context

**Depends on:** [S17.2.1](F17.2-cutover.md#s1721--prepare-and-run-kiln-init) (kiln's docs commands run only once `init` has written `.rn-forge/kiln/config.toml`); kiln's release-1 tag.

What the conversion is, in ngkit's terms. kiln's model replaces three things ngkit does by hand:

| ngkit today                                                                                                 | kiln's model                                                                                                                                                                                         |
| ----------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A status line: `**Status:** done · **Implemented:** <date> (`<hash>`) · **Owner:** ngkit · **Release:** …` | A metadata table under the title with keys `State`, `Parent`, `Iteration`, `Tags`, `Start Date`, `Closed Date`, `Predecessors`, `Source`, `Entry criteria`; states `New`, `Active`, `Closed`, `Removed` |
| `### S<n>.<m>.<k>` story headings under a `## Stories` heading, `**Status:** planned`                       | `## S<n>.<m>.<k> — <Title>` headings, no `## Stories` heading, `**State:** New`                                                                                                                       |
| A hand-kept board in `docs/specs/index.md`, hand-kept feature tables in each epic, and a Scope table in each release | Derived regions between `BEGIN derived …` and `END derived …` fences that `task docs:generate` writes; never edited by hand                                                                          |

What does not change: epic and feature IDs, story IDs, the epic directory names, every ADR number, and the words of every spec. Content moves verbatim apart from heading levels, the status line's becoming a table, and links.

### The 2026-11-02 trial

Run in a throwaway copy of ngkit at `0c2cd2a` (`git archive HEAD`, a scratch `git init`; no real checkout was touched), with kiln `feature/v1`. The result that shapes this feature: after `kiln init`, `kiln doctor . --full` reports 54 findings, none of them in CI.

| Kind                                                   | Count | Cause                                                                                                                                                                                                                                                                  | Story    |
| ------------------------------------------------------ | ----- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| `docs.broken-anchor`                                   | 52    | 26 distinct links, each reported twice. 25 use GitHub's heading slug, which keeps the double hyphen of `S8.2.1 — Accept ADR-0008` (`#s821--accept-adr-0008`); MkDocs collapses it (`#s821-accept-adr-0008`), so the links are broken on the published site too. 1 is dead: `releases/release-1/index.md#breaking-changes-to-announce`, whose heading is `## Breaking changes` | S17.1.5  |
| `docs.orphan-page`                                     | 2     | `docs/specs/epics/index.md` and `docs/specs/ideas/index.md`, which `init` seeds, are not in the nav because `docs/_areas.yml` makes `specs` `index-only` and `docs/specs/index.md` links neither                                                                    | S17.1.4  |
| Markdown not mdformat-clean (`task lint`, not doctor)  | 86 of 95 | Padded tables and wrapping differ from `mdformat` with kiln's `.mdformat.toml`; `task format` rewrites them                                                                                                                                                         | S17.1.6  |
| `task docs:build` (`mkdocs --strict`)                  | 12 warnings | `docs/reference/index.md` (10 links to `libs/**/README.md`) and `docs/guides/development.md` (links to `libs/ng/project.json` and `.github/workflows/ci.yml`) point outside `docs/`. `doctor` does not report them; the build aborts on them                         | S17.1.5  |

In the same copy, applying the three fixes (25 slug rewrites and the dead anchor, `specs` as `nav: work`, the 12 links as GitHub URLs) and `mdformat` gave `kiln doctor . --full` 0 findings, `task docs:build` exit 0 and every Markdown file mdformat-clean. That copy did not convert the spec structure (S17.1.2, S17.1.3), so `docs.state-contradicts-work` and the derived-region findings are not yet measured; S17.1.2 and S17.1.3 record them.

Two facts from the same run that the stories rely on:

- `kiln docs-generate .` refuses a repository with no `.rn-forge/kiln/config.toml` (`not a kiln repo`), which is why S17.2.1 comes first.
- `mdformat` run with only `mdformat` installed collapses ngkit's tables; the `docs` dependency group must carry kiln's full list (S17.2.1), and `mdformat` is only ever run through `task format`.

## S17.1.1 — Agree the mapping

**State:** Closed (2026-11-03) · **Depends on:** S17.2.1

A decision story, so the conversion can depend on it. `port-docs` step 2 requires the mapping to be agreed before anything moves.

**Build:**

- Write the mapping table into the pull request description, with these rows, which are the answer unless the owner changes one:

  | ngkit | kiln |
  | -- | -- |
  | `**Status:** elaborating` / `planned` | `State` `New`; `planned` also carries `Iteration` |
  | `**Status:** in progress` | `Active`, with `Start Date` |
  | `**Status:** done · **Implemented:** <date>` | `Closed`, `Closed Date` = `<date>` |
  | `**Status:** deferred` and its `**Entry criteria:**` | `New`, `Tags` = `deferred`, `Entry criteria` |
  | `**Release:** [Release n](…)` | `Iteration` |
  | `**Owner:** ngkit` | dropped: it is the same on every page; listed in the report as dropped |
  | `**Source:**` | `Source` |
  | `**Depends on:**` on a feature | `Predecessors` |
  | `**Retired:**` | the retired item is kept with `State` `Removed` and one line saying why |
  | an epic with no start date | `Start Date` = the date of the first commit that added the epic's directory: the first line of `git log --diff-filter=A --format=%as --reverse -- <dir>` |
  | an epic or feature that cites a commit hash with its date | the hash goes to a plain line under the table, as "Implemented in commit `0c2cd2a`"; the table value is the date only |
  | done epics whose features are rows in `index.md` | they stay rows, with a `State` column (kiln's model keeps pre-taxonomy epics this way); no feature files are created |
  | `docs/specs/backlog.md` | none exists; `ideas/index.md` stays as `init` seeded it, with no rows |

- The owner agrees the table, or edits a row, in the pull request before S17.1.2 starts.

**Acceptance:**

- The table is in the pull request description, and the owner's agreement is recorded there with its date.

## S17.1.2 — Epics, features and stories

**State:** Active · **Depends on:** S17.1.1

**Build:**

- For each of the 17 epic directories under `docs/specs/epics/` (E1 to E16, and this epic, which converts itself), in epic-number order, and for each feature file in it: replace the status line with the metadata table of `docs/specs/_structure.md` (keys in its fixed order, applying S17.1.1's table); keep the `[Back to the board]` line as a plain line under the table.
- Every `### S<n>.<m>.<k> — <Title>` becomes `## S<n>.<m>.<k> — <Title>`, a `## Stories` heading above them goes, and each story's `**Status:** <s>` becomes `**State:** <New|Active|Closed (<date>)>`; a `**Depends on:**` stays on the same line after ` · `.
- Each epic with feature files gets `<!-- BEGIN derived features -->` / `<!-- END derived features -->` where its hand-written features table was, and the table goes. First, for every row, check that the `Scope` cell is said in the feature file: a feature whose file has no summary paragraph takes the cell as its summary paragraph, under its table, and any other cell content goes to the feature's `## Context`. Each feature file gets `<!-- BEGIN derived stories -->` / `<!-- END derived stories -->` under its table.
- Sections go in `_structure.md`'s order: `## Context` and `## Design` before the first story; `## Acceptance`, `## Considered and rejected` and `## Open questions` after the last.
- Run `task docs:generate`. Fix every `docs.state-contradicts-work` finding on the page it names (an epic or feature state its features or stories contradict) by correcting the state to what the stories say, and list each correction in the report; never edit inside a derived region.
- Content moves verbatim. Compare words: `git diff --word-diff --stat` shows only headings, status lines and the removed tables.

**Acceptance:**

- `rg -c '^### S[0-9]+\.[0-9]+\.[0-9]+' docs/specs` finds nothing, and `rg -c '^\*\*Status:\*\*' docs/specs/epics` finds nothing.
- Every epic and feature file opens with `# `, then a metadata table whose first key is `State`.
- The number of `## S<n>.<m>.<k>` headings equals the number of `### S…` headings before the conversion (recorded in the pull request).
- `task docs:generate` followed by `git diff --exit-code` shows no change, and `kiln doctor . --full` reports no `docs.state-contradicts-work` finding.

## S17.1.3 — Releases and the board

**State:** New · **Depends on:** S17.1.2

**Build:**

- Each `docs/releases/release-<n>/index.md` takes kiln's release shape (`docs/releases/_structure.md`): metadata table with `Status`, `Start Date` and `Finish Date`; sections in the order that file sets (Entry criteria, Scope, Decisions, Breaking changes, Progress, Commits, Exit criteria, Shipped). The hand-written Scope table becomes the derived region; a release's content that fits no section goes under the nearest one, and anything with no home is listed as dropped in the report.
- The features each Scope row listed are now recorded by the feature's `Iteration`. Check each shipped release's derived Scope names the same features as its old table (record any difference in the report; a feature moved between releases keeps the release the old table named).
- `docs/specs/index.md`: the Board section becomes kiln's derived board region; the paragraph above the board ("As of 2026-10-26, …") becomes a plain paragraph under the intro, trimmed to what the derived board does not say; the Conventions section is replaced by a link to `_structure.md`; the board links `epics/index.md` and `ideas/index.md` ("Every epic, by number, is on the epic list" and "Ideas not yet agreed as work are parked in the ideas list").
- Run `task docs:generate`.

**Acceptance:**

- `docs/specs/index.md` has exactly one derived board region, and no hand-written epic table.
- Each release page's Scope region lists the features whose `Iteration` names it; `docs/releases/release-3/index.md` lists F17.1, F17.2 and F11.1.
- `kiln doctor . --full` reports no release finding.

## S17.1.4 — Areas, nav and ADR-0007

**State:** New · **Depends on:** S17.1.3

**Build:**

- `docs/_areas.yml` keeps ngkit's seven areas in order; `specs` changes from `nav: index-only` to `nav: work`. The trial showed this alone clears both orphan pages, since the work nav lists the epic and ideas indexes. Nothing else in the file changes.
- ngkit's own area rules that kiln's `_structure.md` files do not carry are kept: `init` writes kiln's `_structure.md` over ngkit's (a generated file; its backup is under `.rn-forge/kiln/backups/`), so before that file is lost to review, move the original `docs/specs/_structure.md`'s "Other repositories" section (acceptance is checkable inside this repository; other repositories' pages and IDs are not cited, kiln excepted) and its "Checking removed behaviour" paragraph into `docs/specs/index.md` under a new `## How this repository differs` heading, verbatim. Do not edit the generated `_structure.md`.
- [ADR-0007](../../../adr/ADR-0007.md) gains a dated amendment line under its Decision: since 2026-11-02 the docs are built as a MkDocs site (`task docs:build`), published once with Compodoc and Storybook under it; the sentence "there is no docs site build" is replaced by that, and the sentence that the docs are plain Markdown read on GitHub stays true and stays. Its Consequences paragraph's "Nothing checks links automatically" is replaced by "`kiln doctor` and `mkdocs --strict` check links and anchors".

**Acceptance:**

- `rg 'nav: work' docs/_areas.yml` finds the `specs` area; `kiln doctor . --full` reports no `docs.orphan-page`.
- ADR-0007 contains "2026-11-02" and no longer says "no docs site build".

## S17.1.5 — Links

**State:** New · **Depends on:** S17.1.2

**Build:**

- Anchors. For each `docs.broken-anchor` finding `kiln doctor . --full` reports (26 distinct links): rewrite the fragment to MkDocs' slug by collapsing each run of hyphens in it to one (`#s821--accept-adr-0008` becomes `#s821-accept-adr-0008`). Heading conversions in S17.1.2 do not change any heading's text, so the slugs are unchanged. Then change `#breaking-changes-to-announce` in `docs/runbooks/releasing.md` to `#breaking-changes`. Edit only the fragments `doctor` reports, never a link that already resolves.
- Out-of-tree links. `mkdocs --strict` cannot resolve a link from `docs/` to a file outside it. In `docs/reference/index.md` and `docs/guides/development.md`, each link whose target starts with `../../libs/` or `../../.github/` becomes a link to `https://github.com/rn-forge/ngkit/blob/main/<that path without the leading ../../>`. The link to `.github/workflows/ci.yml` in `development.md` is rewritten again by S17.2.3.
- New links written from now on use MkDocs' slug (no double hyphen).

**Acceptance:**

- `kiln doctor . --full` reports no `docs.broken-anchor`.
- `task docs:build` exits 0 (`mkdocs --strict` aborts on a single warning).
- `rg '\]\(\.\./\.\./(libs|\.github|apps|tools)' docs` finds nothing.

## S17.1.6 — Markdown is mdformat-clean

**State:** New · **Depends on:** S17.1.2, S17.1.3, S17.1.4, S17.1.5

**Build:**

- Run `task format`, once, last. It rewrites about 86 of the 95 tracked Markdown files (padded tables, wrapping). Commit it as its own commit, so the conversion commits stay reviewable and the formatting commit is mechanical.
- `.prettierignore` gains the line `*.md` (it lists `README.md` only today), so Prettier and `mdformat` never both format a Markdown file.
- Do not hand-edit `.rn-forge/kiln/standard.md`; `.mdformat.toml` already excludes it.

**Acceptance:**

- `task lint` exits 0 (this runs the Markdown and TOML format checks, `kiln doctor`, workflow lint and the Nx lint targets).
- `task format` followed by `git diff --exit-code` shows no change.
- `rg -n '^\*\.md$' .prettierignore` finds the line.
