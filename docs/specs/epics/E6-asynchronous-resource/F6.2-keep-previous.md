# F6.2 — `keepPrevious`

**Status:** deferred · **Owner:** ngkit · **Epic:** [E6](index.md)

**Entry criteria:** `resourceFromSnapshots` is `@publicApi`, no longer `@experimental`, in the lowest Angular version `@rn-forge/ng` declares as a peer; and the owner schedules it.

**Depends on:** none.

When a resource's request changes, Angular 22.1 puts it in `loading` and its `value()` returns to the default, so a list empties while the next page loads. Angular's documented answer is resource composition with snapshots: a `linkedSignal` over `resource.snapshot()` that keeps the last resolved value while the status is `loading`, turned back into a `Resource` by `resourceFromSnapshots`. It is a few lines, but `resourceFromSnapshots` is `@experimental` in 22.1, and ngkit's peer range is `^22`, so a minor release could change it under a published ngkit version. Until it is stable, an application that needs this writes the composition itself.

## Design

```ts
/** A view of `resource` that keeps its last resolved value while a new request loads. */
export function keepPrevious<T>(resource: Resource<T>, options?: { readonly injector?: Injector }): Resource<T>;
```

The result keeps the source's `status`, so `isLoading()` is true while the old value shows; on `error` it reports the error, not the old value. It wraps no loader, so the source stays reachable, and it lives in `@rn-forge/ng/core`.

## Stories

### S6.2.1 — The composition

**Status:** deferred

**Acceptance:**

- Over a `resource()` whose params change: while the new request loads, `value()` is the previous resolved value and `status()` is `loading`; when it resolves, `value()` is the new value.
- After an error, `status()` is `error` and `error()` is the source's error; a following success resolves normally.
- When the params become `undefined`, the result is `idle` with the default value, not the previous one.
- `keepPrevious` is exported from `@rn-forge/ng/core`; `pnpm nx run-many -t lint test build -p ng` and `pnpm nx run ng:verify-consumer` pass.
