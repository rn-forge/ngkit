# S6.1.1 — The signals and their timers

Brief for
[S6.1.1](../F6.1-loading-timings.md#s611-the-signals-and-their-timers), at
`282f4f2`.

## Goal

Add `loadingTimings(loading, options?)` to `@rn-forge/ng/core`: it turns one
`Signal<boolean>` into three signals, `show`, `slow` and `stalled`, that become
`true` after configurable delays, so a view can skip a skeleton for a fast load
and say a load is slow or stalled. Angular's `isLoading` flips at once and has
no such timing.

## Settled

Each decision below is final; the brief never asks you to decide.

- **The interface** (F6.1 Design, `../F6.1-loading-timings.md` lines 25-47):

    ```ts
    export interface LoadingTimings {
      /** ms of loading before `show` turns true. */
      readonly delay: number; // 300
      /** ms of loading before `slow` turns true. */
      readonly slow: number; // 1000
      /** ms of loading before `stalled` turns true. */
      readonly stalled: number; // 10000
      /** ms `show` stays true once it turned true, even after `loading` is false. */
      readonly minDuration: number; // 0
    }
    export interface LoadingState {
      /** True once the current load has lasted `delay`; a load that ends sooner never shows. */
      readonly show: Signal<boolean>;
      readonly slow: Signal<boolean>;
      readonly stalled: Signal<boolean>;
    }
    /** Application-wide defaults; provide it to change them. */
    export const RNF_LOADING_TIMINGS: InjectionToken<LoadingTimings>;
    export function loadingTimings(
      loading: Signal<boolean>,
      options?: Partial<LoadingTimings> & { readonly injector?: Injector },
    ): LoadingState;
    ```

- **Defaults:** `delay` 300, `slow` 1000, `stalled` 10000, `minDuration` 0.
  `minDuration` defaults to 0 by the owner's decision of 2026-11-18 (F6.1
  Design, Decisions, lines 65-72); with 0 the behaviour is the plain one, and
  callers opt in, typically with 200 to 500 ms.

- **Injection:** `loadingTimings` runs in an injection context or takes
  `injector` (F6.1 Design, lines 55-60). It reads only the boolean and knows
  nothing about HTTP; it shows no text.

- **Precedence:** per-call options override `RNF_LOADING_TIMINGS`, whose factory
  returns the defaults (F6.1 Design, lines 58-59). A provided
  `RNF_LOADING_TIMINGS` is a full `LoadingTimings` and replaces the defaults.

- **A load** starts when `loading` turns `true` and ends when it turns `false`.
  A `loading` that stays `true` (a `reload()`, or a changed request) does not
  restart the clock; one that turns `false` and then `true` does (F6.1 Design,
  lines 61-63).

- **`minDuration` semantics** (F6.1 Design lines 65-72 and S6.1.1 acceptance
  lines 90-94): with 0, `show` turns `false` when `loading` does. With a value
  above 0, a load that ends after `show` turned `true` keeps `show` `true`
  until `show` has been `true` for `minDuration` in total (measured from the
  moment it turned `true`), then turns it `false`; if that time has already
  passed, `show` turns `false` at once. `slow` and `stalled` turn `false` when
  `loading` does, hold or not. A new load that starts during the hold keeps
  `show` `true`, cancels the hold timer, and starts its own clock for `slow`
  and `stalled` only (`show` is already `true`, so no `delay` timer starts);
  when that load ends, the `minDuration` rule applies again, still measured
  from the moment `show` first turned `true`.

- **Thresholds are timers, so a threshold of 0 is a timer of 0 ms.** Every
  threshold is a `setTimeout` started when the load starts; `show` with
  `delay: 0` therefore turns `true` after `vi.advanceTimersByTime(0)`, not
  synchronously. A load that ends before the timer fires never sets the
  signal.

- **Validation:** the merged timings (defaults, then the token, then the call's
  options) must satisfy `0 <= delay <= slow <= stalled` and
  `minDuration >= 0`. Otherwise `loadingTimings` throws, at the call, an
  `Error` whose message starts `[rn-forge.ng.core]` and names every value, in
  the form
  `[rn-forge.ng.core] loadingTimings needs 0 <= delay <= slow <= stalled and minDuration >= 0; got delay=<n>, slow=<n>, stalled=<n>, minDuration=<n>`.
  A `NaN` fails the check as well.

- **Hand-rolled under ADR-0001** (`docs/adr/ADR-0001.md`, "On #1", which also
  requires checking npm before deciding). The exemption is the third case in
  ADR-0001's list ("the needed slice really is a few lines, and the candidate
  is unmaintained or much heavier"), which E6 and F6.1 call exemption 3. E6's
  Design (`../index.md` lines 66-72) records the npm check: `ngxtension` 7.3.1
  `derive-loading` is an RxJS operator, has no slow or stalled state, and
  would add `ngxtension` and a peer for one operator; `spin-delay` 2.0.1 is a
  React hook; `@ngneat/loadoff` 2.1.0 was last published 2024-08 and is
  RxJS-based; checked on npm 2026-10-24. The doc comment on `loadingTimings`
  must name "ADR-0001 exemption 3" and the npm check (see Rules).

- **No new entry point:** it lives in `@rn-forge/ng/core` (E6 Design, lines
  54-57); there is no `libs/ng/resource/`.

## Tests first

Write `libs/ng/core/src/lib/core.loading.spec.ts` first and run it to see it
fail (the missing `./core.loading` import, as described in Current behaviour).
Then add `core.loading.ts` until it passes. Every test uses
`vi.useFakeTimers()`, never a real sleep, and `TestBed.tick()` after each
`loading.set`. Set up: a `loading = signal(false)`, a child
`EnvironmentInjector` (so a test can `destroy()` it) and a helper
`create(options?)` returning
`loadingTimings(loading, { injector, ...options })`. Defaults used below: delay
300, slow 1000, stalled 10000, minDuration 0.

`describe('loadingTimings')`, one `it` per line below, in this order:

1. `it('is false for all three while loading is false')`: after a tick, and
   after advancing 20000 ms, `show`, `slow` and `stalled` are `false`.
1. `it('turns each signal true at its threshold, and not a tick earlier')`: set
   `loading` true; at 299 ms `show` is `false`, at 300 ms `true`; at 999 ms
   `slow` is `false`, at 1000 `true`; at 9999 `stalled` is `false`, at 10000
   `true`; `show` and `slow` stay `true` throughout.
1. `it('never shows a load that ends before delay')`: loading true, advance 299,
   loading false, tick, advance 20000: `show` is `false` throughout.
1. `it('resets all three at once when a load ends after a threshold')`: load for
   10000 ms (all three `true`), set loading false, tick: all three `false`
   with no clock advance (`minDuration` 0).
1. `it('starts a second load from zero')`: load 10000 ms, end it, start another,
   advance 299: all three `false`; advance 1: `show` `true`, `slow` and
   `stalled` still `false`; advance 700: `slow` `true`.
1. `it('does not restart the clock while loading stays true')`: loading true,
   advance 200; `loading.set(true)` again and tick (no change); advance 100:
   `show` is `true` (clock from the first start).
1. `it('clears every threshold timer when loading turns false')`: loading true,
   advance 100, loading false, tick; `vi.getTimerCount()` is 0 and advancing
   20000 changes no signal.
1. `it('clears every pending timer when the injector is destroyed')`: loading
   true, advance 100, `injector.destroy()`; `vi.getTimerCount()` is 0; advance
   20000: all three still `false`.
1. `it('clears a pending minDuration hold when the injector is destroyed')`:
   `minDuration: 500`; load 400 ms (`show` `true`), end the load (hold
   pending), `injector.destroy()`; `vi.getTimerCount()` is 0; advance 1000:
   `show` is still `true`.
1. `it('turns show false when loading does, with minDuration 0')`: load 400 ms,
   end it, tick: `show` is `false` at once and `vi.getTimerCount()` is 0.
1. `it('holds show true until it has been true for minDuration, then turns it false')`:
   `minDuration: 500`, other timings default; load 400 ms (`show` true since
   300 ms); end the load: `show` still `true`, `slow` and `stalled` `false`.
   `show` has been true for 500 ms at 800 ms after the load started, which is
   400 ms after the end: advance 399, `show` `true`; advance 1, `show`
   `false`.
1. `it('turns show false at once when the load ends after minDuration has passed')`:
   `minDuration: 500`; load 900 ms (`show` true for 600 ms); end the load:
   `show` is `false` at once.
1. `it('turns slow and stalled false at once while show is held')`:
   `{ delay: 100, slow: 200, stalled: 400, minDuration: 2000 }`; load 300 ms
   (`slow` `true`); end the load: `slow` and `stalled` are `false` and `show`
   is `true`; advance 1799: `show` `true`; advance 1: `show` `false` (2100 ms
   after the load started).
1. `it('keeps show true across a new load during the hold and gives it its own slow clock')`:
   same timings as test 13; load 150 ms (`show` true since 100); end the load;
   advance 100 (clock 250); start a new load: `show` still `true`,
   `vi.getTimerCount()` is 2 (the `slow` and `stalled` timers; the hold timer
   is gone); advance 199: `slow` `false`; advance 1: `slow` `true`; advance
   200: `stalled` `true`. End the load (clock 650): `slow` and `stalled`
   `false`, `show` `true`; advance 1449: `show` `true`; advance 1: `show`
   `false` (2100 ms after the first load started, `minDuration` measured from
   when `show` first turned true).
1. `it('overrides the defaults with a provided RNF_LOADING_TIMINGS')`: configure
   `TestBed` with
   `{ provide: RNF_LOADING_TIMINGS, useValue: { delay: 50, slow: 60, stalled: 70, minDuration: 0 } }`
   before creating the child injector; `show` turns true at 50 ms, `slow` at
   60, `stalled` at 70.
1. `it('overrides the provided timings with per-call options')`: the same
   provider, plus `{ delay: 10 }` in the call: `show` turns true at 10 ms,
   `slow` still at 60 ms.
1. `it('has the documented defaults')`: `TestBed.inject(RNF_LOADING_TIMINGS)`
   equals `{ delay: 300, slow: 1000, stalled: 10000, minDuration: 0 }`.
1. `it.each(...)('throws a [rn-forge.ng.core] error for %j')` over
   `{ delay: 500, slow: 400 }` (slow before delay), `{ slow: 20000 }` (stalled
   before slow, via the default `stalled` 10000), `{ delay: -1 }`,
   `{ minDuration: -1 }` and `{ delay: Number.NaN }`. Each asserts
   `expect(() => create(opts)).toThrow('[rn-forge.ng.core]')` and that the
   message contains the merged values (for example `delay=500` and `slow=400`
   for the first).
1. `it('accepts equal thresholds')`: `{ delay: 100, slow: 100, stalled: 100 }`
   does not throw and all three turn `true` at 100 ms.
1. `it('runs in an injection context without an injector option')`: inside
   `TestBed.runInInjectionContext`, `loadingTimings(loading)` works (a load
   turns `show` true at 300 ms).
1. `it('throws outside an injection context when no injector is given')`:
   `expect(() => loadingTimings(loading)).toThrow()` (Angular's
   `assertInInjectionContext` error, passed through unchanged).
1. `it('returns read-only signals')`: `'set' in result.show` is `false`, and the
   same for `slow` and `stalled`.
1. `it('exports the API from the @rn-forge/ng/core entry')`: import
   `loadingTimings` and `RNF_LOADING_TIMINGS` from `'@rn-forge/ng/core'`
   (mapped to `libs/ng/core/src/index.ts` in `tsconfig.base.json`) and assert
   both are defined; this fails before the `index.ts` change even once

## Result
