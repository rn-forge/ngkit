# S19.4.2 — A failed source schedules one replacement

Brief for
[S19.4.2](../F19.4-core-and-permissions.md#s1942-a-failed-source-schedules-one-replacement),
at `91d9713`.

## Goal

Make `createEventStream` own at most one source and one reconnect timer at a
time, so a repeated or stale `error`/`open` notification cannot multiply timers,
leak open sources, flip `connected` for the wrong source, or reopen a stream
after `close()` or injector destruction. A small lifecycle fix in one file; no
public behaviour changes.

## Settled

- The story's acceptance (F19.4, S19.4.2) and S19.3.1's outcome: each case gets
  a regression through the public API (`createEventStream`, the
  `RNF_EVENT_SOURCE_FACTORY` fake, fake timers) that fails before the fix and
  passes after.
- ADR-0001: the wrapper stays hand-rolled over `EventSource`; no new transport
  abstraction and no dependency.
- Epic scope constraints: public imports, `EventStream` shape (`connected`,
  `source`, `close`), `RNF_EVENT_SOURCE_FACTORY`, and the documented reconnect
  contract (browser retries while `CONNECTING`; a new source only after
  `CLOSED`, delay `min(baseMs * 2^attempt, maxMs)` with equal jitter) are
  preserved.
- No decision is open: every observed failure below is a defect against the
  documented contract ("at most one reconnect timer and one current source").

## Current behaviour

Line numbers are at `91d9713`, `libs/ng/core/src/lib/core.eventstream.ts`.
Observed with a scratch spec (deleted) using the existing spec's
`FakeEventSource`, fake timers and `Math.random() = 0` (first delay 500 ms):

1. **Repeated `CLOSED` errors on one source.** `a.fail(2)` three times leaves 3
   pending timers and `a.close()` called 3 times; running the timers opens 3
   new sources (4 in total, 1 of them current in `source()`, 2 orphaned and
   still open). Cause: the `error` listener (`:93-104`) re-runs for the same
   `es`; nothing marks `es` as already handled. `es.readyState` stays `CLOSED`
   (`:95` passes), and `timer = setTimeout(...)` (`:100`) overwrites the
   handle without clearing the previous timer. `attempt++` (`:99`) also
   advances once per notification.
1. **Stale `error` after replacement.** After `a` fails, the timer opens `b` and
   `b` opens (connected `true`, `source()` is `b`), a late `a.fail(2)` sets
   `connected` to `false` (`:94`), sets `source` to `null` (`:97`, `b` stays
   open, unowned) and schedules another timer (`:100`); running it creates a
   third source (3 in total). Cause: the listener does not check that `es` is
   still the current source.
1. **Stale `open`.** A late `a.open()` while `b` is still `CONNECTING` sets
   `connected` to `true` and resets `attempt` (`:89-92`), though the current
   source is not open. Same cause: no current-source check.
1. **`close()` after repeated errors.** With two `a.fail(2)` calls then
   `s.close()`: 1 timer remains (`close` clears only the last handle, `:120`);
   running timers opens a second source (`open` has no `closed` guard, `:86`),
   `source()` is non-null and the new source is never closed (`closeCalls` 0).
1. **Injector destroy after repeated errors.** Same as 4 through
   `injector.destroy()` (`:126` runs `close`): after `runAllTimers`, 2 sources
   exist, 1 still open, `source()` non-null.
1. **Already correct (must keep):** a late `error` after `close()` schedules
   nothing (`closed` guard at `:95`); one `CLOSED` error with `close()` before
   the timer fires leaves 0 timers (existing tests).

## Change

- **Change:** `libs/ng/core/src/lib/core.eventstream.ts`, inside `open`. Treat
  `source()` as the one current source:
    - at the top of the `open` and `error` listeners,
      `if (source() !== es) return;` (a stale, replaced, already-failed or
      closed source is ignored; this runs before `connected.set(false)` and
      before `attempt` changes). `close()` and the failed-source path already
      set `source` to `null`, so a repeated error on the same source is also
      ignored.
    - in the timer callback, return without opening when `closed` is set (belt and
      braces for a timer that fires in the same tick as `close()`).
    - keep `source.set(es)` after listener registration; keep everything else.
      Update the doc comment only if it contradicts the change (it should not).
- **Leave alone:** `CONNECTING` handling (the `readyState !== CLOSED` return),
  `DEFAULT_BASE_MS`/`DEFAULT_MAX_MS`, the delay formula and jitter, named
  handler dispatch and its `try/catch` into `ErrorHandler`, the inert path
  (`factory` `null`), `RNF_EVENT_SOURCE_FACTORY`, the exported interfaces and
  every other file. Do not add handler-side stale guards: a closed source
  delivers no events.

## Tests first

All in `libs/ng/core/src/lib/core.eventstream.spec.ts`, using the existing
`FakeEventSource`, `stream()` helper and fake timers (random mocked to `0`), in
a new `describe('a failed source')` inside `describe('createEventStream')`.
Write them first and run them: tests 1-5 must fail on `91d9713` as stated.

1. `schedules one timer for repeated CLOSED errors from one source`: `fail(2)`
   three times; expect `vi.getTimerCount()` `1` and `closeCalls` `1`; advance
   500 ms; expect 2 sources, `s.source()` is `latest()`, the first closed, the
   second not. Before: 3 timers, `closeCalls` 3, 4 sources.
1. `ignores a stale error after the replacement opened`: `a.fail(2)`, advance
   500, `b.open()`, then `a.fail(2)`; expect `connected()` `true`, `source()`
   is `b`, `b.closeCalls` `0`, 0 timers; `runAllTimers`; still 2 sources.
   Before: `connected` false, `source` null, 1 timer, 3 sources.
1. `ignores a stale open while the replacement is connecting`: `a.fail(2)`,
   advance 500, `a.open()`; expect `connected()` `false`. Before: `true`.
1. `close() after repeated errors cancels pending work`: `a.fail(2)` twice,
   `s.close()`; expect 0 timers, `runAllTimers`, 1 source, `source()` `null`.
   Before: 1 timer, 2 sources, `source()` non-null.
1. `destroying the injector after repeated errors opens nothing`: same with
   `injector.destroy()`; expect no source left open
   (`instances.every(i => i.readyState === 2)`), `source()` `null`, 0 timers
   after `runAllTimers`. Before: one open source remains.
1. Preserved, passing before and after (guard the fix against over-reach):
   `ignores a stale error after close()` (late `a.fail(2)` after `s.close()`:
   0 timers, 1 source);
   `a CLOSED error on the current source still reconnects once` (single
   `fail(2)`, one timer, 2 sources, `connected` follows `open`); the existing
   `CONNECTING`, jitter/backoff, handler, `ErrorHandler` and inert-path tests
   stay unchanged and green.
