# S19.2.1 — Repair inventories and command guidance

Brief for
[S19.2.1](../F19.2-current-documentation.md#s1921-repair-inventories-and-command-guidance),
at `7373431`.

## Goal

Make the root and docs landing pages, the library READMEs and the architecture
and guide pages agree with the repository as it is: every publishable library is
named and linked to its owning README, command guidance uses `task` verbs or a
project-scoped native command (or records a tooling gap with its owner), and the
consumer matrix, the workspace Angular version and the published peer floor are
stated as three distinct facts, each pointing at its owner.

## Settled

- **"All publishable libraries", not "all three".** The story's acceptance says
  "all three publishable libraries"; it predates F11.1. Four projects carry
  the `publishable` tag in their `project.json`: `ng` (`libs/ng`),
  `ng-bootstrap` (`libs/ng-bootstrap`), `ng-tailwind` (`libs/ng-tailwind`) and
  `ng-plugin` (`tools/ng-plugin`, package `@rn-forge/ng-plugin`). All four are
  at version `0.5.0`. This brief treats the acceptance as "all publishable
  libraries" and names all four. Source: `project.json` tags, verified at
  `7373431`.
- **One entrypoint.** Source: `AGENTS.md` and `.rn-forge/kiln/standard.md` §1.
  Workflows and the gate never invoke `uv`, `mkdocs`, `pnpm`, `npx`, `nx`,
  `ng` or `kiln` directly. A document may name a native command scoped to one
  project that no verb covers, "such as `pnpm exec nx serve <app>`,
  `pnpm exec nx g …` or `pnpm exec nx show project <name>`", saying what it is
  for. This brief settles three consequences:
    - The spelling is `pnpm exec nx …` (the standard's form), not `pnpm nx …`, for
      every command this repository's own documents tell a contributor to run.
    - A workspace-wide native command (`run-many`, `nx release publish`) is not
      project-scoped, so no document recommends it as the way to do something.
      The operation is recorded as a tooling gap (below) and the document points
      at the gap.
    - Commands a document gives to a _consumer_ in their own Nx workspace
      (`pnpm add @rn-forge/ng-tailwind`; `pnpm nx g @rn-forge/ng-plugin:…` in
      `tools/ng-plugin/README.md` and in the `libs/ng-bootstrap/README.md` note)
      are not this repository's commands and stay as written.
- **Tooling gaps, with owner.** The verb set is kiln's
  (`.rn-forge/kiln/standard.md` §1: "The developer surface for this repo is
  exactly" the listed verbs; the generated release workflow is kiln's). So the
  owner of each gap is kiln. The gaps, each verified at `7373431`:
    1. **No local verb packs and verifies the publishable projects.**
       `task ci:smoke` does it
       (`pnpm exec nx run-many -t pack verify-dist verify-consumer`) but is
       labelled "CI only". Used at `README.md:64`,
       `docs/guides/development.md:120`, `docs/guides/building-an-app.md:126`.
    1. **The generated release runs no npm publish step.** `_release.yml` calls
       `ci:release:state`, `author`, `tag`, `verify`, `sbom`, `push`, `github`,
       `finalize`, `latest`; there is no `ci:release:publish` (it is not in
       `task --list-all`). `docs/architecture/release-pipeline.md:39-41`,
       `docs/runbooks/releasing.md:80-82,86-87` and
       `docs/guides/development.md:177-180` claim one. The per-project
       `nx-release-publish` targets with `dryRun: true` still exist, so npm
       stays disabled; re-enabling it needs kiln's release workflow to gain a
       publish step.
    1. **No verb for a maintainer's one-off first npm publish**
       (`docs/runbooks/releasing.md:95`, `nx release publish --first-release`).
       Same owner, same gap as 2.
- **Three version facts, three owners.** The documents state them separately and
  name the owner instead of repeating a number where they can:
    - _Workspace Angular version:_ what the repository builds and develops
      against; owner is the root `package.json` (`@angular/*` at `~22.2.x`, set
      by `~22.2.5` for `@angular/core`; `@angular/cdk` `~22.2.6`).
    - _Published peer floor:_ what a consumer must satisfy; owner is each
      `libs/*/package.json` `peerDependencies` (`@angular/core` `^22.0.6` in all
      three libraries; `@angular/cdk` `^22.0.4` in `ng-bootstrap`; see
      [ADR-0002](../../../../adr/ADR-0002.md)). `ng-plugin` peers on `@nx/*` and
      `typescript`, not Angular.
    - _Consumer matrix:_ what the release proves; owner is each library's
      `package.json#workspace-ci.consumer.cells`. At `7373431`: `ng` four cells
      (`22.0-zone`, `22.0-zoneless`, `22.1-zone`, `22.1-zoneless`),
      `ng-bootstrap` four (the same), `ng-tailwind` eight (those four times
      `plain` and `tailwind`), `ng-plugin` none (it has `verify-dist` only).
- **README Projects table.** The root `README.md` lists the four publishable
  libraries, each linked to its owning README. The full project list (apps,
  e2e projects, backend fixtures) is owned by
  `docs/architecture/workspace.md`, and the root README links to it instead of
  repeating it.
- **Release set.** Every `publishable` project releases at one version
  (`task version` fails with "Expected one version across the publishable
  projects" otherwise; `nx.json#release.projects` is `["tag:publishable"]`;
  [ADR-0003](../../../../adr/ADR-0003.md)). Prose that says "`ng` and
  `ng-bootstrap` release together" or "both libraries" is stale and says
  "every publishable library" or names all four.
- **Not a decision for this story.** ADR-0002 line 22 still says the workspace
  `devDependencies` are `^22.1.7`, and `AGENTS.md` ("Release invariants",
  first bullet) still says `ng` and `ng-bootstrap` release together. Both are
  binding or instruction files outside this story's audit; they are listed
  under Out of scope and reported to the owner, not edited.

## Tests first

One script runs all checks; run it before the edits (it must fail) and after
(must exit 0). Save it outside the repository, for example in the scratchpad; do
not commit it. `absent` is the helper from `docs/specs/_structure.md`.

```bash
set -euo pipefail
cd "$(git rev-parse --show-toplevel)"
unset NX_WORKSPACE_ROOT_PATH
absent() { local rc=0; rg -q --hidden --glob '!.git' "$@" </dev/null || rc=$?; [ "$rc" -eq 1 ]; }
t=$(mktemp -d)

# Audited documents: repository-facing, not specs, ADRs or kiln-generated pages.
audited=(README.md docs/index.md docs/guides/building-an-app.md
  docs/guides/development.md docs/guides/http.md docs/architecture/workspace.md
  docs/architecture/release-pipeline.md docs/runbooks/releasing.md
  docs/runbooks/recovering-from-drift.md libs/ng/README.md
  libs/ng-bootstrap/README.md libs/ng-tailwind/README.md tools/ng-plugin/README.md)

# 1. Every `task <verb>` and every ci:<verb> named exists. Fails before:
#    ci:release:publish (release-pipeline.md:39).
task --list-all --json | jq -r '.tasks[].name' | sort >"$t/verbs"
{ rg -oPN --no-filename '`task ([a-z][a-z:-]*[a-z])(?![a-z:*-])' -r '$1' "${audited[@]}" || true
  rg -oPN --no-filename '^task ([a-z][a-z:-]*[a-z])(?=  | --|$)' -r '$1' "${audited[@]}" || true
  rg -oPN --no-filename '\bci:[a-z][a-z:-]*[a-z](?![a-z:*-])' "${audited[@]}" || true; } \
  | sort -u >"$t/named"
missing=$(comm -23 "$t/named" "$t/verbs")
```
