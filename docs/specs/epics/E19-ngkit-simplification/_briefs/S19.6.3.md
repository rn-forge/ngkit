# S19.6.3 — Wire multi-typeahead to one reactive-form value

Brief for
[S19.6.3](../F19.6-forms-and-crud.md#s1963-wire-multi-typeahead-to-one-reactive-form-value),
at `16e15df`.

## Goal

Make the parent `FormGroup` control the only authority for the multi-typeahead
field's value, touched and disabled state, so chips, filtering, selection,
removal, reset, blur and disable all work through a real reactive form. Today
the field keeps a second, disconnected copy of the value and a text box bound to
the same control as the array.

## Settled

- **Integration: the parent `FormGroup` input, as every sibling field does.** No
  field in the repository implements `ControlValueAccessor` or provides
  `NG_VALUE_ACCESSOR` (`grep -rl ControlValueAccessor libs apps` finds
  nothing). Each field takes `name` and `formGroup` inputs from
  `ParentFieldComponent` (`form-field/form-field.component.ts:79-80`), reads
  its control through `getControl()` (`:112-114`), and binds its native
  element with `[formControlName]="fieldFormControlName"` inside a
  `[formGroup]` template (`typeahead-field.component.html:2,8`,
  `dropdown-field.component.html:2,7`, `input-field.component.html:2,9,19`,
  `rich-text-field.component.html:2,5`). Consumers place fields in the
  `rnf-form` template and pass `[formGroup]="ctx.formGroup"`
  (`form.stories.ts:249-253`,
  `apps/ng-demo/src/app/forms/forms.page.html:58-62`); `FormComponent` does
  not instantiate fields. Multi-typeahead keeps that shape: its value
  authority is `getControl()`. It does not become a `ControlValueAccessor`.
  The one difference from siblings is forced by the data: the control holds an
  array, so the text box cannot be bound with `formControlName`; the field
  reads and writes the control itself.
- **Public inputs and outputs do not change.** The inputs (`name`, `formGroup`,
  `id`, `label`, `formControlName`, `values`, `type`, `itemFilter`,
  `itemFormatter`, `formatFields`, plus inherited `options`/`htmlAttributes`)
  and the `selectItem` output are untouched; `rnf-multi-typeahead-field` still
  takes `[formGroup]` and `name`.
- **One intentional type-level contract change.** These public members of the
  exported `MultiTypeaheadFieldComponent` are removed because nothing ever
  called them (the class does not declare `implements ControlValueAccessor`
  and has no provider, so Angular never invoked them): `onChange`,
  `onTouched`, `writeValue`, `registerOnChange`, `registerOnTouched`,
  `setDisabledState`. The `protected` members `selectedOptions`, `inputValue`
  and `filteredOptions` are replaced. Import paths are unchanged.
    - Changelog entry (under "Breaking Changes" of the release that ships it):
      "`@rn-forge/ng-bootstrap/form`: `MultiTypeaheadFieldComponent` no longer
      exposes `onChange`, `onTouched`, `writeValue`, `registerOnChange`,
      `registerOnTouched` or `setDisabledState`. They were never connected to
      Angular forms; the field now reads and writes its control in the parent
      `FormGroup`."
    - Versioning assessment: pre-1.0 and fixed/grouped
      ([ADR-0003](../../../../adr/ADR-0003.md)), so the change ships in the next
      minor, not a patch (a pre-1.0 minor already forces a matched upgrade). It
      reaches `CHANGELOG.md` through the closing commit's `BREAKING CHANGE:`
      footer or an edit in the release pull request
      ([releasing runbook](../../../../runbooks/releasing.md)); this brief does
      not edit it. The reviewer adds the acceptance line when closing the story:
      "the removed members are listed in the changelog".
- **Typed text goes to the filter as typed.** `typeahead-field.component.ts:175`
  passes the raw text to `filterFn()`; multi-typeahead does the same instead
  of lowercasing first (`multi-typeahead-field.component.ts:58`). The default
  filter lowercases itself (`typeahead-field.component.ts:41-57`).
- **Value shape:** the control holds `unknown[]`. Any non-array value (`null`,
  `undefined`, `''`) renders no chips and never throws. A write never mutates
  the array in the control; it sets a new array.
- Source: F19.6 S19.6.3 acceptance; F19.3 S19.3.1 (each correctness case gets a
  failing pre-fix regression through the rendered host, then passes);
  `design.md` (review table and "Choose one reactive-form integration, remove
  disconnected state"); epic Scope constraints (preserve public imports,
  accessibility; intentional contract change needs acceptance, changelog,
  versioning assessment).

## Current behaviour

All references are at `16e15df`, in
`libs/ng-bootstrap/form/src/lib/form/fields/multi-typeahead-field/`.

- `multi-typeahead-field.component.ts:28` extends `TypeaheadFieldComponent`
  (single-value typeahead) and keeps its own state: `selectedOptions`,
  `filteredOptions`, `inputValue` (`:30-32`) and no-op `onChange`/`onTouched`
  callbacks (`:34-39`).
- `:41-55` `writeValue`, `registerOnChange`, `registerOnTouched`,
  `setDisabledState` exist, but the class declares no `NG_VALUE_ACCESSOR` and
  `implements` nothing, and the template binds `formControlName` to a plain
  `<input>` (`.html:17-23`), so Angular wires the input's own default
  accessor, never these methods.
- `:57-60` `onInputChange` filters on `this.inputValue`, which nothing binds, so
  it is always `''` and the list shows every value.
- `:62-74` `addValue`/`removeValue` `push`/`splice` the private
  `selectedOptions` array, call the dead `onChange`, and never touch the
  parent control (`:76-78`).
- `.html:4-13` renders chips from `selectedOptions`; the close button
  (`aria-label="Remove"`, `:10`) is never disabled. `.html:17-23` binds the
  text input to the parent control with `[formControlName]`, so typing writes
  the typed string into the control that should hold an array. There is no
  blur handler of its own.
- `:28` inherits `@HostListener('focusout')` `onFocusOut`
  (`typeahead-field.component.ts:138-160`). With `type="string"` it compares
  an array to each value, finds no match, and patches the control to `null`.
- Existing spec: `multi-typeahead-field.component.spec.ts:31-33` calls
  `writeValue` directly; `:47-125` (added by S19.3.1) is a reactive-form suite
  that passes today only because the text box is bound to the control (typing,
  blur and reset-clears-text pass for that reason).

Observed failures, reproduced on a scratch spec at `16e15df` (since deleted)
through a host with `[formGroup]="fg"` and a control initialised to `['alpha']`,
`values = ['alpha','beta','gamma']`:

| Case | Expected | Observed |
| -- | -- | -- |
| Initial control value renders chips | `['alpha']` | `[]` (`writeValue` never called) |
| Typing `be` filters the options | `['beta']` | `['alpha','beta','gamma']` (`.ts:58`, `inputValue` always `''`) |
| Typing `be` leaves the parent value alone | `['alpha']` | `'be'` (`.html:22`) |
| Choosing `beta` | control `['alpha','beta']` | `'be'` |
| `control.setValue(['gamma'])` | chips `['gamma']` | `[]` |
| Removing a chip | control `[]` | `['alpha']` (chip not rendered, nothing removed) |
| Disabling the control | chip close buttons disabled | no chip buttons rendered (`0` vs `1`); `.html:7-11` has no disabled binding |
| `type="string"` plus `focusout` with `['alpha']` | `['alpha']` | control set to `null` |
| Blur marks touched; `reset()`; input disabled | pass today | pass today (guards) |

## Change

- **Change:** `multi-typeahead-field.component.ts` and `.html`.
    - Remove `selectedOptions`, `inputValue`, `onChange`, `onTouched`,
      `writeValue`, `registerOnChange`, `registerOnTouched`, `setDisabledState`
      and `propagateChange`.
    - Make the control the single authority. Read it through `getControl()` and
      expose its value and disabled state to the template as signals that follow
      the control's `valueChanges` and `statusChanges` (and re-follow if the
      `formGroup` or `formControlName` input changes). Suggested shape:
      `toSignal(toObservable(control).pipe(switchMap(...)))`; an equivalent is
      fine as long as the signal is a read-through of the control, not a second
      copy. The chip list is that value if it is an array, else `[]`.
    - `addValue(option)`: no-op when disabled;
      `control.setValue([...chips, option])` and `markAsDirty()`.
      `removeValue(option)`: no-op when disabled; set a new array without the
      first `indexOf(option)` match, and `markAsDirty()`. Never mutate the
      existing array.
    - `onInputChange`: no-op when disabled; read the text from the input event
      target and set `filteredOptions` to `this.filterFn()(text, this)`. The
      typed text is local to the field and is never written to the control.
    - Any change of the control's value (choose, remove, `setValue`, `reset`)
      clears the typed text and closes the list. Choosing clears the text and
      closes the list as today.
    - Blur on the text input calls `getControl().markAsTouched()`.
    - Override `onFocusOut` as a no-op: the partial-input clearing it inherits is
      for a single scalar value and would null the array.
    - Template: drop `[formControlName]` from the text input and bind `[disabled]`
      to the control's disabled state plus `(blur)`; bind `[disabled]` on each
      chip close button; keep `[id]="fieldId"` (the `<label for>` in
      `form-field.component.html:20` points at it), keep `aria-label="Remove"`
      and the `rnfHtmlAttributes` binding. Remove the `[formGroup]` binding on
      the `ng-template` and `ReactiveFormsModule` from the component's `imports`
      only if nothing in the template still needs them (lint or the Angular
      compiler warns on an unused import).
    - `multi-typeahead-field.component.spec.ts`: delete the `writeValue()` test
      (`:31-33`; the member is removed) and extend the reactive-form suite as
      described below.
- **Leave alone:**
    - The other fields (`typeahead-field`, `dropdown-field`, `input-field`,
      `rich-text-field`, `form-field`) and `form.component.ts`, including
      S19.6.2's form-group rebuild (`form.component.ts:86-106`).
    - The inheritance from `TypeaheadFieldComponent` and its inherited members
      (`selectItem`, `focus$`, `click$`, `typeaheadListener`, `onItemSelect`,
      `formatter`); do not restructure the class hierarchy.
    - `multi-typeahead-field.component.scss`, `form.config.ts`, the stories and
      the demo page (they pass `[formGroup]` and `name`, which still work).
    - Duplicate selection (the list still offers selected values; choosing one
      again adds it again, as today).

## Tests first

Write these in the second `describe` of
`multi-typeahead-field.component.spec.ts` ("inside a reactive form"), through
the rendered host and a real parent `FormGroup`. Give the host a control
initialised to a caller-owned array (`initial = ['alpha']`) and inputs for
`type`, `itemFilter` and `itemFormatter`. Chip close buttons are
`.badge .btn-close`; a bare `.btn-close` also matches the form field's clear
button. Run them before the change and record which fail; the ones marked
"fails" must.

1. `renders chips for the initial control value` - chips are `['alpha']`. Fails
   (`[]`).
1. `typing filters the options by the typed text` - typing `be` lists only
   `beta`. Fails (all three).
1. `typing does not write to the parent control` - after typing `be` the control
   is still `['alpha']`. Fails (`'be'`).
1. `choosing writes a new array to the control` - after typing `be` and choosing
   `beta`, the control is `['alpha','beta']`, the control is dirty, the text
   box is empty and the list is closed. Fails.
1. `selecting and removing never mutate the caller's array` - `host.initial` is
   still `['alpha']` after choosing and removing, and the control holds a
   different array instance. Guard: passes before the change for lack of any
   write, so it only protects the fix.
1. `a parent setValue updates the chips` - `setValue(['gamma'])` shows
   `['gamma']`. Fails.
1. `a parent reset clears the chips and the typed text` - with a chip and typed
   text present, `fg.reset()` leaves no chips and an empty text box. The text
   half passes today (replaces the existing "resetting the form clears the
   typed text"); the chip half is only meaningful after the fix.
1. `removing a chip writes the remaining array` - from `['alpha','beta']`,
   removing the first leaves `['beta']`. Fails.
1. `blur marks the control touched` - keep the existing test; it must keep
   passing once the text box no longer uses `formControlName`.
1. `disabling the control blocks typing, selecting and removing` - with a chip
   present, `disable()` disables the text box and every chip close button;
   typing, `addValue` and `removeValue` leave the control unchanged;
   `enable()` restores them. Fails on the close buttons.
1. `passes the typed text to a custom itemFilter and uses itemFormatter` - an
   `itemFilter` spy receives `'Be'` as typed; an `itemFormatter` result is the
   chip and option text. Fails (the filter receives `''`).
1. `focusout does not clear an array when type is "string"` - with
   `type="string"` and `['alpha']`, a `focusout` leaves `['alpha']`. Fails
   (`null`).
1. `keeps accessible labels` - each chip close button has `aria-label="Remove"`,
   and the text box has the id the `<label for>` targets. Guard.
1. `non-array control values render no chips` - controls holding `null` and `''`
   render no chips and do not throw. Guard.

Run in a zone-based and, if the suite already has one, a zoneless host; do not
add a harness for this.
