# S19.8.1 — Enforce the declared dependency direction

Brief for
[S19.8.1](../F19.8-boundaries-and-consumers.md#s1981-enforce-the-declared-dependency-direction),
at `16e15df`.

## Goal

The package direction (`ng` is core; `ng-bootstrap` and `ng-tailwind` render on
top of it and never import each other) is held by review alone, because the one
`@nx/enforce-module-boundaries` constraint allows every tag to depend on every
tag. Give the repository-owned lint config tags and constraints that fail a
forbidden import, then update ADR-0002, which says review is the only guard.

## Settled

- Acceptance (F19.8, S19.8.1): repository-owned lint rejects a
  core-to-presentation import and a Bootstrap-to-Tailwind import in either
  direction; presentation-to-core and demo consumers pass; normal library and
  secondary-entry-point imports pass; existing lint capabilities only, no
  dependency, no parallel boundary framework.
- ADR-0002 ("Consequences", `docs/adr/ADR-0002.md:28-29`): the direction is core
  `ng` below presentation `ng-bootstrap` / `ng-tailwind`. That text is
  rewritten in this story, after the checks pass, and not before.
- The config is repository-owned. `eslint.config.mjs` has no kiln provenance
  header, and `.rn-forge/kiln/standard.md` section 4 says the boundaries
  between a `node-lib` repository's projects are "the repository's own, in the
  `@nx/enforce-module-boundaries` rule of `eslint.config.mjs`, and `task lint`
  runs them". `libs/*/project.json` are also repository-owned (no header). No
  kiln change is needed.
- Tags (decided in this brief, prototyped below): keep the existing `type:core`
  / `type:ui` / `type:app` / `type:tool` tags and add one skin tag to each
  presentation library: `ui:bootstrap` on `ng-bootstrap`, `ui:tailwind` on
  `ng-tailwind`. `type:ui` alone cannot tell the two libraries apart.
- Secondary entry points need no extra rule. They are not projects: every
  `@rn-forge/ng/*` and `@rn-forge/ng-bootstrap/*` alias resolves to a file of
  the same Nx project, which the rule treats as an intra-project import. The
  constraints act on project boundaries, so `@rn-forge/ng/core` from
  `@rn-forge/ng/crud` passes and `@rn-forge/ng-bootstrap/shell` from `ng`
  fails like the top-level alias.

## Current behaviour

At `16e15df`:

- `eslint.config.mjs:19-22`: the only constraint is `sourceTag: '*'` with
  `onlyDependOnLibsWithTags: ['*']`, which allows everything. It lives in the
  root config; each project config (`libs/*/eslint.config.mjs`,
  `apps/*/eslint.config.mjs`, `tools/ng-plugin/eslint.config.mjs`) spreads
  `baseConfig`, so one edit covers every project.
- Tags (`project.json:20` in each library): `libs/ng` is
  `["scope:ngkit", "type:core", "publishable"]`; `libs/ng-bootstrap` and
  `libs/ng-tailwind` are `["scope:ngkit", "type:ui", "publishable"]` (the two
  are indistinguishable); the demo apps and e2e projects are
  `["scope:ngkit", "type:app"]`; `tools/ng-plugin/project.json:19` is
  `["scope:ngkit", "type:tool", "publishable"]`.
- `docs/adr/ADR-0002.md:28-29` says no lint enforces the direction and review
  does.
- No source file currently imports across the forbidden directions
  (`grep -rE "@rn-forge/ng-(bootstrap|tailwind)" libs/ng libs/ng-tailwind` and
  `grep "@rn-forge/ng-tailwind" libs/ng-bootstrap` are empty, so tightening
  fails nothing today). `ng-bootstrap` legitimately imports `@rn-forge/ng/*`.
- Bad imports pass today (single temporary fixture file each, linted with
  `pnpm exec eslint <file>` from the library directory):
    - `libs/ng-bootstrap/src/zz-bad.ts` importing `@rn-forge/ng-tailwind`: passes
      (no output).
    - `libs/ng-tailwind/src/zz-bad.ts` importing `@rn-forge/ng-bootstrap/shell`:
      passes.
    - `libs/ng/core/src/zz-bad.ts` importing `@rn-forge/ng-tailwind`: passes.
    - `libs/ng/core/src/zz-bad.ts` importing `@rn-forge/ng-bootstrap`: fails only
      by accident, with the generic cycle message
      `Circular dependency between "ng" and "ng-bootstrap" detected`, because
      `ng-bootstrap` already imports `ng`. Not a direction rule, and a core to
      Tailwind import is not caught at all.

## Change

- **Change:**
    - `eslint.config.mjs`: in `depConstraints` (currently `:18-23`), keep the `*`
      entry, which gives every project (apps and the tool included) a matching
      constraint (without it, `apps/ng-demo` importing a library fails with "A
      project without tags matching at least one constraint cannot depend on any
      libraries"), and add after it:

        ```js
        {
          sourceTag: 'type:core',
          onlyDependOnLibsWithTags: ['type:core'],
        },
        {
          sourceTag: 'type:ui',
          onlyDependOnLibsWithTags: ['type:core', 'type:ui'],
        },
        {
          sourceTag: 'ui:bootstrap',
          notDependOnLibsWithTags: ['ui:tailwind'],
        },
        {
          sourceTag: 'ui:tailwind',
          notDependOnLibsWithTags: ['ui:bootstrap'],
        },
        ```

        Add a short comment above the list saying the constraints encode ADR-0002's
        direction: core below presentation, and the two presentation libraries
        independent.

    - `libs/ng-bootstrap/project.json:20`: tags become
      `["scope:ngkit", "type:ui", "ui:bootstrap", "publishable"]`.

    - `libs/ng-tailwind/project.json:20`: tags become
      `["scope:ngkit", "type:ui", "ui:tailwind", "publishable"]`.

    - `docs/adr/ADR-0002.md`, "Consequences", first bullet (`:28-29`), replaced

        ```markdown
        - `@nx/enforce-module-boundaries` enforces the direction. `ng` is tagged
        ```

## Tests first

The tests are temporary negative fixtures, deleted by the block itself. Run this
at the unchanged commit first: the three `MUST FAIL` checks that expect a tag
message report `NOT REJECTED` (the `ng-bootstrap` core case fails with the cycle
message, which the block accepts), and `ok` cases pass. Run it again after the
change: every check prints `PASS`. From the repository root, with no file left
behind (a `trap` removes them):

```bash
unset NX_WORKSPACE_ROOT_PATH
set -u
fx=()
trap 'rm -f "${fx[@]}"' EXIT

# check <name> <project dir> <fixture path relative to it> <import> <expected>
# expected: a message fragment the lint must print, or "ok" for a clean file
check() {
  local name=$1 dir=$2 rel=$3 spec=$4 want=$5
  printf "import { x } from '%s';\nexport const a = x;\n" "$spec" > "$dir/$rel"
  fx+=("$dir/$rel")
  local out
  out=$(cd "$dir" && pnpm exec eslint "$rel" 2>&1)
  rm -f "$dir/$rel"
  if [ "$want" = ok ]; then
    if [ -z "$out" ]; then echo "PASS  $name"; else echo "FAIL  $name (rejected)"; echo "$out"; fi
  elif grep -qF "$want" <<<"$out"; then
    echo "PASS  $name (rejected)"
  else
    echo "FAIL  $name NOT REJECTED"; echo "$out"
  fi
}

# forbidden
check core-to-tailwind   libs/ng           core/src/zz-bad.ts @rn-forge/ng-tailwind        'type:core" can only depend on libs tagged with "type:core"'
check core-to-bootstrap  libs/ng           core/src/zz-bad.ts @rn-forge/ng-bootstrap       'Circular dependency between "ng" and "ng-bootstrap"'
check core-to-bs-entry   libs/ng           crud/src/zz-bad.ts @rn-forge/ng-bootstrap/shell 'Circular dependency between "ng" and "ng-bootstrap"'
check bootstrap-to-tw    libs/ng-bootstrap src/zz-bad.ts      @rn-forge/ng-tailwind        'ui:bootstrap" can not depend on libs tagged with "ui:tailwind"'
check tailwind-to-bs     libs/ng-tailwind  src/zz-bad.ts      @rn-forge/ng-bootstrap/shell 'ui:tailwind" can not depend on libs tagged with "ui:bootstrap"'

# allowed
check ok-bootstrap-core  libs/ng-bootstrap src/zz-ok.ts       @rn-forge/ng/core            ok
check ok-tailwind-core   libs/ng-tailwind  src/zz-ok.ts       @rn-forge/ng                 ok
check ok-crud-to-core    libs/ng           crud/src/zz-ok.ts  @rn-forge/ng/core            ok
check ok-bs-entry-to-entry libs/ng-bootstrap crud/src/zz-ok.ts @rn-forge/ng-bootstrap/shell ok
check ok-app-bootstrap   apps/ng-demo      src/zz-ok.ts       @rn-forge/ng-bootstrap/shell ok
check ok-app-tailwind    apps/ng-demo      src/zz-ok.ts       @rn-forge/ng-tailwind        ok
check ok-app-core        apps/ng-demo      src/zz-ok.ts       @rn-forge/ng/core            ok

```
