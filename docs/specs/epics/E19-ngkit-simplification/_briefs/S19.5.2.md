# S19.5.2 — Destroy the table and its deferred work

Brief for
[S19.5.2](../F19.5-configuration-and-widgets.md#s1952-destroy-the-table-and-its-deferred-work),
at `16e15df`.

## Goal

Make the table's plugin instance, selection listeners and highlight timers end
with the Angular component, and make `highlightRow` work for any string or
numeric row ID without building a selector from the ID.

## Settled

- The story's acceptance (F19.5, S19.5.2) and the epic's Scope constraints: keep
  public imports, vendor escape hatches and optional features; no dependency,
  no speculative vendor replacement. ADR-0001 (wrap the proven library; do not
  reimplement it) applies: the fix calls the plugin's own `destroy` method and
  does not patch the vendor.
- F19.3 S19.3.1 (closed): each correctness case gets a failing pre-fix
  regression through the public API or the rendered host, then a passing
  post-fix run. S19.3.1 already added the rendered-host suite in
  `table.component.spec.ts`; this story extends it. Lifecycle cases use fake
  timers, not sleeps.
- Decided here (verified by prototype at `16e15df`): rows are matched by reading
  the `data-uniqueid` attribute and comparing it as a string
  (`$(...).filter(...)`), not by `CSS.escape` or an escaped selector. A
  numeric `1` and a string `"1"` therefore match the same row, as the plugin
  writes the attribute as a string. No loader change is involved:
  `bootstrap-table-loader.ts` and `treegrid-loader.ts` stay as they are.
- Vendor limit, not fixed here: the plugin itself builds
  `tr[data-uniqueid="<id>"]` when it loads rows (`bootstrap-table.js:10057` in
  `bootstrap-table@1.28.0`), so a row whose ID contains a double quote throws
  inside `load` before `highlightRow` can run. Quotes are therefore tested
  with a single quote. Do not work around the vendor.

## Current behaviour

Line numbers are at `16e15df`, in
`libs/ng-bootstrap/src/lib/table/table.component.ts` unless noted. Observed with
a scratch spec (deleted) that rendered the S19.3.1 host, loaded rows, then
inspected jQuery's event data and `data('bootstrap.table')`.

- **No component teardown.** The class has no `ngOnDestroy`. `destroy()`
  (`:199-204`) is a public method nothing calls. The base
  `ConfigurableComponent.ngOnDestroy`
  (`libs/ng-bootstrap/src/lib/bootstrap.component.ts:231-234`) only frees the
  `ConfigurerService` caches. Observed after `fixture.destroy()`:
  `table.rendered` is still `true`, four `.ng-accel` listeners are still bound
  (`check`, `uncheck`, `check-all`, `uncheck-all`, attached at `:299-305`),
  the jQuery plugin data (`data('bootstrap.table')`) is still present and the
  element still holds its 6 rendered rows. After an explicit `destroy()` the
  same probes read 0 listeners, no plugin data, 0 rows, so `destroy()` itself
  works.
- **Highlight timers outlive the component.** `highlightRow` (`:289-298`)
  schedules `window.setTimeout(..., 5000)` and keeps no handle. After
  `highlightRow(1)` then `fixture.destroy()`, `vi.getTimerCount()` is 1; the
  timer later runs `_table.find(...)` on a destroyed table. `updateRow`
  (`:257`) and `deleteRows` (`:282-283`) call `highlightRow`. `destroy()` does
  not cancel timers either.
- **Selector built from the ID.** `highlightRow` interpolates the ID unquoted,
  `tr[data-uniqueid=${id}]` (`:291` and `:294`). Observed, each throwing
  `Error: Syntax error, unrecognized expression: tr[data-uniqueid=<id>]` from
  jQuery and highlighting nothing: `a'b`, `a b`, `a.b`, `a]b`, `a:b`. Numeric
  IDs work only because they happen to be valid unquoted values. Because the
  throw happens in the synchronous part of `highlightRow`, `updateRow` throws
  after the row was already updated, and `deleteRows` throws before
  `bootstrapTable('remove')` runs, so the row is not removed.
- **Already correct (keep, pin where S19.3.1 did not).** Rerender does not
  accumulate listeners: after two extra `render()` calls there are still 4
  (`_attachSelectionListeners` calls `.off('.ng-accel')` first, `:300`;
  `render` calls `bootstrapTable('destroy')` first, `:193`), and the existing
  `rerender keeps a single selection listener` test already pins this.
  `destroying the fixture after destroy() is safe` passes today but does not
  fail before the fix for the reasons above: it never checks the timer count.
  Explicit `destroy()` then `fixture.destroy()` does not throw.
- **Browser coverage.** `apps/ng-demo-e2e/src/products.spec.ts` drives the real
  table through the CRUD screen (load, add, update, delete, batch delete,
  import) against the real plugin; the update and delete paths call
  `updateRow` and `deleteRows`, so they pass through `highlightRow`.
  `loadBootstrapTable` is also used by the unit host
  (`table.component.spec.ts`, `beforeAll`). The loader specs
  (`bootstrap-table-loader.spec.ts`, `treegrid-loader.spec.ts`) pin the import
  order.

## Change

- **Change:** `libs/ng-bootstrap/src/lib/table/table.component.ts` only.

    - Track each pending highlight timer handle in a private `Set<number>`; add a
      handle when `highlightRow` schedules and remove it when the callback runs.
    - Replace both
      `find(\`tr[data-uniqueid=${id}]\`)`calls in`highlightRow`with one private helper that returns`this._table.find('tr[data-uniqueid]').filter((_,
      tr) => tr.getAttribute('data-uniqueid') === String(id))\`. Call it again
      inside the timer callback (rows may have been re-rendered). No selector
      contains the ID.
    - `destroy()` clears every pending timer (and empties the set), then does what
      it does now (`off('.ng-accel')`, plugin `destroy`, selection count 0,
      `rendered` false).
    - Add `override ngOnDestroy(): void { this.destroy(); super.ngOnDestroy(); }`
      with a one-line doc comment. `destroy()` is already safe when the table
      was never rendered (`_table` is optional-chained, and `render` already
      calls the plugin `destroy` on a fresh element), and safe to call twice.
    - Do not use `CSS.escape`, and do not catch the jQuery error.

    `libs/ng-bootstrap/src/lib/table/table.component.spec.ts`: add the tests below
    to the existing `TableComponent rendered host` suite.

- **Leave alone:** `bootstrap-table-loader.ts`, `treegrid-loader.ts` and their
  specs; `bootstrap.component.ts` (option caches are S19.5.1); the `table`
  getter and `bootstrapTable()` proxy (vendor access); the tree `onPostBody`
  wrapper in `configureOptions`; the `disabled` callbacks and the
  `_selectedCount` signal that link toolbar buttons to the selection; the
  `afterNextRender`-driven `delayedAfterViewInit`; `table.component.html`;
  `table.types.ts`; the styles; `apps/*`. Do not change the public method
  names or signatures (`highlightRow(id: unknown, error = false)` stays).

## Tests first

All in `libs/ng-bootstrap/src/lib/table/table.component.spec.ts`, in the
`TableComponent rendered host` suite (fake timers are already on in its
`beforeEach`). Add a small helper there that counts the table's `.ng-accel`
listeners through `$._data(table.table[0], 'events')` (filtering handlers whose
`namespace` contains `ng-accel`; `import $ from 'jquery'` in the spec) and a
helper that lists the `data-uniqueid` of rows carrying `highlight-update`. For
the ID tests, load rows with the IDs `"a'b"`, `"a b"`, `"a.b"`, `"a]b"`,
`"a:b"`, `"a"` and the number `1`. The host's `opts` use `idField: 'id'`, so
rows are `{ id, name }`. Each test except 5 must fail before the change (record
the failure message in `## Result`), then pass after.

1. `fixture destruction releases the plugin, listeners and highlight timers`.
   Click a row checkbox (so selection is non-empty), call
   `table.highlightRow(1)`, keep a reference to `table.table`, assert before:
   4 listeners, `vi.getTimerCount()` is 1,
   `table.table.data('bootstrap.table')` defined. Then `fixture.destroy()` and
   assert `table.rendered` is `false`, 0 listeners, `vi.getTimerCount()` is 0,
   plugin data undefined. Fails before: `rendered` stays `true`, 4 listeners,
   1 timer, plugin data present.
1. `destroy() cancels pending highlight timers`. `table.highlightRow(1)`,
   `table.destroy()`, assert `vi.getTimerCount()` is 0, then advance 5000 ms
   with no error. Fails before: the timer count is 1.
1. `explicit destroy() then fixture destruction is safe`.
   `table.highlightRow(1)`, `table.destroy()`, then
   `expect(() => fixture.destroy()).not.toThrow()`, assert 0 timers and 0
   listeners, and advance 5000 ms. (Passes before for the throw part, fails on
   the timer part; keep both assertions, and keep the existing
   `destroying the fixture after destroy() is safe` test as is.)
1. `highlights rows whose ids contain spaces, quotes or selector punctuation` (a
   `for ... of` over the IDs `a'b`, `a b`, `a.b`, `a]b`, `a:b`, one test
   each). Call `table.highlightRow(id)`: it must not throw, exactly one row
   carries `highlight-update` and its `data-uniqueid` equals the ID; after
   advancing 5000 ms no row carries it. Fails before: jQuery
   `Syntax error, unrecognized expression: tr[data-uniqueid=<id>]`.
1. `highlight matches the whole id only`. With rows `"a"` and `"a b"` loaded,
   `highlightRow('a')` highlights only the `a` row; `highlightRow(1)` and
   `highlightRow('1')` highlight the same row. The `1` assertions pass before
   the change; the rest guards against a prefix or substring match in the
   replacement.
1. `deleteRows with a punctuated id removes the row`. Load `"a'b"` and `"a b"`
   plus the numeric rows, call `table.deleteRows(["a'b"])`, assert that
   `table.getData()` no longer contains it and the others remain. Fails
   before: the jQuery syntax error is thrown from `highlightRow` before the
   plugin `remove` call.
1. `updateRow with a punctuated id updates the row and highlights it`. Call
   `table.updateRow({ id: "a'b", name: 'changed' })`; assert the data holds
   the new name and the row is highlighted, then cleared after 5000 ms. Fails
   before with the same syntax error (after the plugin update ran).

Keep the existing tests unchanged (`rerender keeps a single selection listener`
and `updateRow highlights the row and clears it after 5 s` still pass and cover
rerender and the numeric path).
