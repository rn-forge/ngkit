# S19.3.1 — Exercise public lifecycles and rendered interactions

Brief for
[S19.3.1](../F19.3-behavioral-baselines.md#s1931-exercise-public-lifecycles-and-rendered-interactions),
at `48e181a`.

## Goal

Replace creation-only tests for the table and the multi-typeahead field with
tests that drive them through a rendered host and a real reactive form, and
remove the string-indexed access to `AbstractCrudManager` internals from its
spec. The tests describe what the components do today, so later stories can
change the implementation and see the same tests pass or fail for the right
reason.

## Settled

- **Bullet 1 of the story is not built here.** "Each correctness case in
  F19.4–F19.7 has a failing pre-fix regression ... followed by a passing
  post-fix run" is satisfied by those features' own stories: each writes its
  regression test first, then fixes. S19.3.1 does not write them. Source:
  reviewer ruling on this brief. This brief covers bullets 2 to 4 only.
- **Every test added here passes at `48e181a`.** A case that fails today is a
  defect (see "Found defects"), belongs to the story that fixes it, and is not
  written here, not even as `it.fails` or `it.skip`.
- Table tests render a real `bootstrap-table` in jsdom: calling
  `loadBootstrapTable()` once in `beforeAll` is enough (verified by prototype;
  render, load, check, rerender and destroy all work under Vitest).
- Fake timers (`vi.useFakeTimers()`) and controllable observables stand in for
  sleeps; no `setTimeout`-based waiting and no weakened assertions.
- Source: the story's acceptance (F19.3, S19.3.1) and [design.md](../design.md)
  "Tests and measurements".

### Found defects (not fixed here)

Prototyped tests that fail at `48e181a`, so they are not in this brief. Each
belongs to the story that fixes it, which writes the failing regression first.

- **Multi-typeahead through a real `FormGroup` (S19.6.3).** With
  `new FormControl(['alpha'])`: the chip list is empty and the `<input>` shows
  `alpha`; `writeValue` is never called. Typing `be` writes the string `be` to
  the parent control, and the options list still shows all three values (the
  filter reads the unbound `inputValue`, which stays `''`). Choosing an option
  adds a chip but leaves the parent control at `be`.
  `fg.setValue({tags: ['gamma']})` does not change the chips (the input shows
  `gamma`). `fg.reset()` leaves the chips. A disabled control leaves the chip
  close buttons enabled.
- **Table fixture destruction (S19.5.2).** After `fixture.destroy()`, `rendered`
  stays `true` and the four `.ng-accel` listeners remain on the element: the
  component has no `ngOnDestroy` that calls `destroy()`. `highlightRow("a'b")`
  throws jQuery's "Syntax error, unrecognized expression:
  tr[data-uniqueid=a'b]"; the selector at `table.component.ts:292` is
  unquoted.

## Tests first

All tests below are new and pass at `48e181a`; they are written against the
current code before any other edit, so there is no failing step in this brief.
Run each spec file once after writing it to confirm it passes. Use
`vi.useFakeTimers()` in the timer tests and `vi.useRealTimers()` in `afterEach`.

**`table.component.spec.ts`**, new `describe('rendered host')`, with a host
component `<rnf-table #t [options]="opts" />` (a `viewChild` to the table),
columns `{ field: 'state', checkbox: true }`, `id`, `name`, `pagination: false`,
`search: false`, `toolbarButtons` of `ToolbarHelper.updateButton` and
`deleteButton` with spy callbacks, and `await loadBootstrapTable()` (from
`./bootstrap-table-loader`) in `beforeAll`. After `createComponent` +
`detectChanges`, flush the post-render work with
`await vi.advanceTimersByTimeAsync(0)` and `detectChanges` again.

1. `renders a row per loaded item`: `rendered` is `true`; after
   `load([...2 rows])` the host has two `tbody tr`; `getData()` returns them.
1. `selecting a row updates the selection and the linked toolbar buttons`: both
   toolbar `<button>`s are disabled; clicking the first row's checkbox gives
   `getSelectedRows()` of length 1 and enables both buttons; unchecking
   disables them again.
1. `rerender keeps a single selection listener`: `render()` called twice, rows
   reloaded; with `vi.spyOn(table, 'getSelectedRowsCount')` one checkbox click
   calls it exactly once.
1. `rerender resets the selection state`: select a row, `render()`, reload; the
   toolbar buttons are disabled.
1. `updateRow highlights the row and clears it after 5 s`: with fake timers,
   `updateRow({ id: 1, ... })` adds `highlight-update` to the row, and
   `advanceTimersByTimeAsync(5000)` removes it.
1. `destroy() clears the plugin state`: `rendered` is `false`, selection count 0
   (toolbar buttons disabled after a re-render is not required).
1. `destroying the fixture after destroy() is safe`: `table.destroy()`,
   `fixture.destroy()`, then `advanceTimersByTimeAsync(5000)` with a pending
   `highlightRow(1)` does not throw. (This asserts safety only; it does not
   assert that Angular destruction releases the plugin, which is S19.5.2.)

**`multi-typeahead-field.component.spec.ts`**, new
`describe('inside a reactive form')`, with a host
`<rnf-multi-typeahead-field name="tags" [formGroup]="fg" [values]="values" />`
and `fg = new FormGroup({ tags: new FormControl<unknown>(null) })`,
`values = ['alpha', 'beta', 'gamma']`. Type by setting the `<input>` value and
dispatching `input`; choose and remove by clicking the rendered `li button` and
`.btn-close`.

1. `typing opens the options list`: after typing, the list shows buttons and
   each button's text comes from `formatter`. (Assert presence and formatted
   text, not filtering.)
1. `choosing an option shows it as a chip`: click the `beta` button; one
   `.badge` reads `beta`.
1. `removing a chip drops it`: choose two options, click the first chip's close
   button; one chip remains.
1. `blur marks the parent control touched`: `touched` is `false`, dispatch
   `blur` on the `<input>`, it is `true`.
1. `disabling the control disables the input`: `fg.controls.tags.disable()` +
   `detectChanges`; the `<input>` is disabled; `enable()` re-enables it.
1. `resetting the form clears the typed text`: type `be`, `fg.reset()` +
   `detectChanges`; the `<input>` value is empty. (Chip reset behaviour is
   S19.6.3's.)

**`crud.manager.spec.ts`**: no new tests; the existing 41 tests pass unchanged
in assertion after the access replacement. Check that the 18 former `call(...)`
tests still assert what they did.
