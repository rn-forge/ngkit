# S19.6.1 — Serialize values without truthiness loss

Brief for
[S19.6.1](../F19.6-forms-and-crud.md#s1961-serialize-values-without-truthiness-loss),
at `bfd1392`.

## Goal

A submitted CRUD form must send `0` and `false` to the data source as they are.
Today the form-to-request conversion tests each value for truthiness, so both
become `null` and a user cannot save a zero quantity or an unchecked box. Fix
that one conversion and pin the rest of its behaviour with tests; no other
behaviour changes.

## Settled

- The story's acceptance (F19.6, S19.6.1): `0` and `false` survive; tests pin
  empty strings, nullish values and relation objects (including an ID of zero)
  before conversion changes; conversion overrides, ETags, idempotency retry,
  problem-to-control errors and permission vocabulary keep working.
- The owner, 2026-11-18, from S19.3.2's analysis of the CRUD manager: the
  manager stays intact and nothing is extracted in this story. The third
  acceptance bullet is satisfied by recording that S19.3.2 found no useful
  boundary (see "Change", last item). `design.md` agrees: do not split the
  manager merely to lower a metric.
- Intended handling, chosen from what the code and its test already say (neither
  the docs, the READMEs nor a doc comment describe it, so the existing test's
  title is the only written statement:
  `toRequestParams() nulls empties and takes ids from objects`,
  `crud.manager.spec.ts:547`):
    - `''`, `null` and `undefined` become `null` (kept; the key is always present,
      so `JSON.stringify` keeps it and a PUT clears the field).
    - `0`, `false`, `true`, any non-empty string (including `'0'`) and any other
      number pass through unchanged.
    - A relation (an object) becomes its `id`, including `{ id: 0 }` which becomes
      `0`. `{ id: null }` becomes `null`. The only change is that the emptiness
      test stops treating `0` and `false` as empty. `NaN` is no longer converted
      to `null` by the manager; it reaches the data source as `NaN`, which
      `JSON.stringify` writes as `null`, so the request body is the same.
- ADR-0002: presentation-free policy belongs in `ng`, dialogs and widget wiring
  in `ng-bootstrap`. Nothing moves in this story, so the fix stays in
  `libs/ng-bootstrap/crud`.
- No dependency is added (epic Scope constraints; ADR-0001).

## Current behaviour

All line numbers are at `bfd1392`, in
`libs/ng-bootstrap/crud/src/lib/crud/crud.manager.ts` unless noted.

Public path: the toolbar "Add" or "Update" button calls
`startAdd`/`startUpdate`; `submitAddUpdate()` (`:418-453`) calls
`fromAddUpdateFormValue()` (`:483-485`), which is
`toRequestParams(this.addUpdateForm.rawValue)` (`:468-481`), and hands the
result to `dataSource.create(payload, { idempotencyKey })` (`:440`) or
`dataSource.update(id, payload, { etag })` (`:446`). The conversion:

```ts
if (!value) {                       // :471  the defect
  resolvedValue = null;
} else if (typeof value === 'object') {
  resolvedValue = (value as GenericType)['id'];   // :473
} else {
  resolvedValue = value;            // :475
}
```

Observed through that path (a scratch spec, since deleted, submitted a form
whose `rawValue` held each value; the data source received):

| Form value | Payload value today | Why |
| -- | -- | -- |
| `0` | `null` | `!0` (`:471`) — **defect** |
| `false` | `null` | `!false` (`:471`) — **defect** |
| `NaN` | `null` | `!NaN` (`:471`) |
| `true`, `-1`, `'0'` | unchanged | `:475` |
| `''` | `null` | `:471` (intended) |
| `null` | `null` | `:471` (intended) |
| `undefined` | `null` (key present) | `:471` (intended) |
| `{ id: 5 }` | `5` | `:473` |
| `{ id: 0 }` | `0` | object is truthy, so `:473` (already correct) |
| `{ id: null }` | `null` | `:473` |
| `{ name: 'x' }`, `{}` | `undefined` (key present) | `:473`, no `id` |
| `[1, 2]`, `new Date(0)`, `{ a: { id: 2 } }` | `undefined` (key present) | `:473`: an array, a date or a nested object has no `id` |

The last row is outside this story (see "Out of scope"); it is recorded so the
reviewer does not mistake it for a regression.

Other places that read the payload and must keep working with `0`/`false`:

- `keyFor(payload)` (`:455-462`) compares `JSON.stringify(payload)` with the
  last create body: it reuses the idempotency key on retry and renews it when
  the body changes. After the fix a `0` and a `null` are different bodies
  (they were the same body before).
- `handleSaveError` (`:503-523`) maps a 412 to `conflict`, a problem body to the
  form's controls (`problemToFormErrors`), anything else to an alert.
- Two near-identical `pointer: detail` formatters exist at `:640-642`
  (`handleImportReport`) and `:667-669` (`handleImportError`). They format
  import errors and take no part in form conversion.

Existing spec (`crud.manager.spec.ts`): `TestManager` (`:52-84`) overrides
`fromAddUpdateFormValue` to return a constant (`:68-70`), so tests that submit
never exercise the real conversion; it also widens `toRequestParams` to public
(`:72-74`). `makeContext()` (`:102-135`) builds a context whose
`addUpdateForm.rawValue` is `{}` and is a plain property, so a test can set it.
The existing conversion test is `:547-554`.

## Change

- **Change:** `libs/ng-bootstrap/crud/src/lib/crud/crud.manager.ts`, in
  `toRequestParams` only: replace the truthiness test with an explicit one,

    ```ts
    if (value === undefined || value === null || value === '') {
      resolvedValue = null;
    }
    ```

    leaving the `typeof value === 'object'` and pass-through branches as they are.
    Add a short doc comment above `toRequestParams` stating the rule in the
    table of "Settled" (empties become `null`; `0` and `false` are values; an
    object becomes its `id`). Keep the signature
    `protected toRequestParams<T>(rawValue: GenericType): T`, because
    applications override it.

- **Change:** `libs/ng-bootstrap/crud/src/lib/crud/crud.manager.spec.ts`: the
  tests below.

- **Change:** record, in the story's outcome line when it closes (the reviewer's
  commit, not yours), that S19.3.2 found no useful boundary so the manager is
  unchanged. You write nothing in the spec pages.

- **Leave alone:** every other part of `crud.manager.ts`: application conversion
  overrides (`toAddUpdateFormValue`, `fromAddUpdateFormValue`,
  `toRequestParams` as an extension point), ETag handling (`editing.etag`,
  `reloadConflict`), the idempotency key and `keyFor`, `handleSaveError` and
  `problemToFormErrors`, the permission checks and keys, `tableOptions`, the
  delete and import/export flows, and the file's structure. Do not touch
  `crud.component.*`, `libs/ng/crud` or any docs page. Do not edit the
  existing tests or `TestManager`'s existing overrides.

## Tests first

All in `crud.manager.spec.ts`, in a new `describe('form value conversion', ...)`
inside the top-level `describe('AbstractCrudManager')`, going through the public
path: `manager.init(ctx)`, `press(manager, 'Add')`, `manager.submitAddUpdate()`,
then read the `create` mock's first argument.

Setup helper (add near `TestManager`): a second class
`FormValueManager extends AbstractCrudManager<TestWrite, TestRead>` that is a
copy of `TestManager`'s overrides (`name`, `permissionKey`, `source`,
`dataSource`, `tableColumns`, `addUpdateFormControls`, `toAddUpdateFormValue`)
but does **not** override `fromAddUpdateFormValue` or `toRequestParams`, so the
real conversion runs. Provide it like `setup()` does (`APP_CONFIG_PROVIDER` and
the class). Set the form value with `ctx.addUpdateForm.rawValue = {...}` (cast
as needed; the mock's `rawValue` is a plain property). Use
`create: vi.fn(() => of({ value: { id: 9, name: 'new' } }))` from `makeSource`.

Write the tests, run them, and confirm which fail before the change:

1. `submits 0 and false unchanged` — `rawValue = { count: 0, active: false }`;
   expect the `create` payload `toEqual({ count: 0, active: false })`. **Fails
   before the change** (both are `null`); passes after.
1. `an update submits 0 and false unchanged` — `startUpdate` path:
   `manager.list.select([1])`, `press(manager, 'Update')`, set `rawValue` as
   above, `submitAddUpdate()`; expect `update` called with
   `(1, { count: 0, active: false }, { etag: '"e1"' })`. **Fails before**;
   also shows the ETag is still passed.
1. `submits empty strings and nullish values as null` —
   `rawValue = { a: '', b: null, c: undefined }`; expect payload
   `toEqual({ a: null, b: null, c: null })` and `Object.keys(payload)` to
   equal `['a', 'b', 'c']` (the keys stay present). Passes before and after
   (pins the intended handling).
1. `submits a relation as its id, including zero` —
   `rawValue = { owner: { id: 5 }, parent: { id: 0 }, unset: { id: null } }`;
   expect `{ owner: 5, parent: 0, unset: null }`. Passes before and after.
1. `submits other scalars unchanged` — `{ s: 'x', zero: '0', n: -1, t: true }`
   unchanged. Passes before and after.
1. `renews the idempotency key when 0 replaces an empty value` — first submit
   `{ count: null }` with `create` throwing (`throwError(() => http(500))`),
   second submit `{ count: 0 }`; expect the two `idempotencyKey` values to
   differ, and a third identical submit to reuse the second's key. **Fails
   before** (both bodies were `{"count":null}`, so the key was reused).

Leave the existing `toRequestParams() nulls empties and takes ids from objects`
test as it is; it must still pass.

Confirm tests 1, 2 and 6 fail on the unchanged `crud.manager.ts` (paste the
failure lines into `## Result`), then make the change and confirm all pass.
