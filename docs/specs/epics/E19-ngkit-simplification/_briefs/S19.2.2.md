# S19.2.2 — Keep docstrings contractual

Brief for
[S19.2.2](../F19.2-current-documentation.md#s1922-keep-docstrings-contractual),
at `7373431`.

## Goal

Make the doc comments changed during E19 state what the code does, so a reader
who trusts them is not misled. Three comments are wrong today; the test-title
and package-README parts of the acceptance are verified and found already
satisfied, with a guard so they stay so.

## Settled

- `updateOptions(undefined)` stays a no-op: `TableComponent.render()` passes its
  optional argument straight through, so clearing there would reset overrides
  on every plain `render()` (S19.5.1, closed). The docstring changes, the code
  does not. `clearOverrides()` is the way to clear
  ([design.md](../design.md#documentation-that-stays-small)).
- The settings example uses Angular `inject()` and the real method names (F19.2
  acceptance; design.md, same section).
- The Bootstrap JS bundle's guarantee is "imported, data-attribute API listeners
  registered"; `window.bootstrap` is not guaranteed in an installed consumer
  because esbuild takes the bundle's UMD CommonJS branch (S19.8.2 finding,
  F19.8 page; the consumer fixture's own comment at
  `tools/consumer/ng-bootstrap-app.mjs:217` already says the bundle is proved
  by the dropdown's data-API listener, not `window.bootstrap`).
- Only the identified occurrences change. There is no repository-wide rename
  (F19.2 acceptance).

## Current behaviour

1. `libs/ng-bootstrap/src/lib/bootstrap.component.ts:259-272`
   `ConfigurableComponent.updateOptions(updates?)`. The doc says "Replaces the
   current runtime overrides with `updates`. Pass `undefined` to clear
   overrides without changing anything else." The body sets `_updatedOptions`
   only `if (updates)`, so `undefined` does nothing. Callers:
   `table.component.ts:188` (`render(updatedOptions?)` calls
   `this.updateOptions(updatedOptions)`), `crud.manager.ts:390,408,581`.
   Related: `table.component.ts:178-181` documents `render()` as "Optionally
   merges `updatedOptions` before rendering"; `updateOptions` replaces, it
   does not merge (`mergeOptions` merges).
1. `libs/ng-bootstrap/auth/src/lib/user/settings/settings.service.ts:25-29` the
   `@example` is `const userSettingsService = new UserSettingsService();` and
   `userSettingsService.updateSettings('theme', 'dark');`. The service is
   `@Injectable({ providedIn: 'root' })` and builds on
   `inject(LocalStorageService)` (line 35), so `new` outside an injection
   context throws; the method is `updateSetting(key, value)` (line 89), not
   `updateSettings`. The real API:
   `registerChangeListener(key, callback): () => void` (line 62, returns a
   disposer), `hasStoredSetting(key)` (82), `updateSetting` (89),
   `clearStoredSettings()` (113). This is the only place the wrong name or
   `new` appears: `grep -rn "updateSettings\|new UserSettingsService"` over
   `*.md`, `*.ts`, `*.mjs` (excluding `node_modules`, `dist`) hits only this
   file and the spec pages that describe the defect.
1. `libs/ng-bootstrap/src/lib/bootstrap-loader.ts:1-5` the header comment says
   loading the bundle "registers the data-attribute API listeners (dropdown,
   offcanvas, etc.) plus window.bootstrap before first render". S19.8.2 found
   `window.bootstrap` undefined in an installed consumer. The code (lines
   8-14) only awaits `import('bootstrap/dist/js/bootstrap.bundle.js')` once
   and memoizes the promise. `loadBootstrap()` resolution is the guarantee;
   the data-API listeners are registered by the bundle on `document`. The code
   itself imports Bootstrap types only via `import type ... from 'bootstrap'`
   (`shell/src/lib/offcanvas/offcanvas.ts:4`), never `window.bootstrap`.
1. Test titles: `git diff 282f4f2..7373431 -- '*.spec.ts'` adds or changes 14
   spec files. Their `describe`/`it`/`test` titles contain no work IDs

   of the two `option-resolution.*.measure.spec.ts` files and of

   Titles carrying IDs exist only in `libs/ng-tailwind/src/css-contract.spec.ts`

## Change

- **Change:**
    - `libs/ng-bootstrap/src/lib/bootstrap.component.ts`, `updateOptions` doc:
      state that it replaces the runtime overrides with `updates`, that calling
      it with `undefined` (or no argument) does nothing and leaves the current
      overrides in place so a caller may forward an optional argument, and that
      `clearOverrides()` removes overrides. No code change.
    - `libs/ng-bootstrap/src/lib/table/table.component.ts`, `render` doc: replace
      "Optionally merges `updatedOptions`" with wording that agrees with
      `updateOptions` (replaces the runtime overrides when given; unchanged when
      omitted). Doc only.
    - `libs/ng-bootstrap/auth/src/lib/user/settings/settings.service.ts`, class
      `@example`: use `inject(UserSettingsService)` in an injection context (a
      field initializer or constructor body of an Angular class), then
      `updateSetting('theme', 'dark')`, `hasStoredSetting('theme')`, a
      `registerChangeListener('theme', (value) => ...)` whose returned disposer
      is called in `ngOnDestroy`/`DestroyRef.onDestroy`, and
      `clearStoredSettings()`. Keep it short; every method named must exist in
      the class.
    - `libs/ng-bootstrap/src/lib/bootstrap-loader.ts`, header comment: say the
      bundle is imported once, before first render, and registers the Bootstrap
      data-attribute API listeners (dropdown, offcanvas, etc.) on `document`;
      `window.bootstrap` is not guaranteed (an installed consumer's bundler
      takes the UMD CommonJS branch), so code needing the JS API imports from
      `'bootstrap'` instead of reading the global. Verify the data-API claim
      against `tools/consumer/ng-bootstrap-app.mjs` near line 217 and the
      S19.8.2 spec `apps/ng-bootstrap-e2e/src/consumer.spec.ts` before writing
      it; if the spec does not exercise it, state only what the fixture comment
      states.
    - Test titles: none to reword (item 4). If the pre-change grep finds a changed
      title with an ID that this brief missed, reword that title to describe
      behaviour, change nothing else in the test, and record it under Result.
    - Package READMEs: none to change (item 5). If the check finds a relative link
      that escapes the package, replace it with
      `https://github.com/rn-forge/ngkit/blob/main/<path>` and record it under
      Result.
- **Leave alone:**
    - All behaviour: no code change in `updateOptions`, `render`, the settings
      service or `loadBootstrap`; no `clearOverrides` call added; no change to
      `TableComponent.render()`.
    - S19.2.1's scope: landing pages, inventories, command guidance (`README.md`,
      `docs/index.md`, `docs/guides/development.md`, consumer matrix prose) and
      its brief.
    - Spec pages, release records, ADRs, `design.md`, and the S19.3.2 header
      comments in the measure files and `measure.fixtures.ts` (comments, not
      test descriptions; the IDs there are the sanctioned pointer back to the
      spec).
    - `libs/ng-tailwind` test titles (not changed in this epic).
    - `docs/guides/building-an-app.md` and `docs/architecture/configuration.md`
      mentions of `updateOptions()`/`mergeOptions()` (accurate as written).
    - Files whose header says kiln generated them.
