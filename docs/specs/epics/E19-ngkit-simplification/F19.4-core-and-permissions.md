Keep small Angular wrappers small while making their ownership and repeated
events explicit. The outgoing auth transport remains E5's responsibility.

## S19.4.1 — Permission rebinding renders one view

**State:** New

**Acceptance:**

- Both permission directives render exactly one embedded view across repeated
  allowed inputs, allowed-to-allowed changes and deny/allow transitions.
- A rendered host verifies content and destruction, rather than asserting
  private container calls. Existing `RNF_PERMISSION` vocabulary survives E5.

## S19.4.2 — A failed source schedules one replacement

**State:** New

**Acceptance:**

- Reproduce repeated `CLOSED` error delivery from a controlled source. At most
  one reconnect timer and one current source exist; stale source events cannot
  change the replacement's connected state or schedule another replacement.
- Calling `close()` or destroying the injector cancels pending work, closes the
  owned source and prevents later opens, including after repeated errors.
- Preserve browser-managed `CONNECTING` retries, jitter/backoff, named handler
  dispatch, `ErrorHandler` routing and the inert server path. No new transport
  abstraction or dependency is introduced.

## Acceptance

- S19.4.1: Permission input changes cannot append duplicate content.
- S19.4.2: Repeated failure notifications cannot multiply reconnect ownership.
