## S19.1.1 — Establish the retention and brief boundary

**State:** New

**Acceptance:**

- The repository's agent guidance points at one brief rule: one unpublished file
  per next story, settled contracts retained permanently, deletion at
  close/removal, and implementer/reviewer validation responsibilities.
- Generated routing and checks are adopted through their existing kiln owner,
  without hand-editing managed files or creating a competing local validator.
  Local guidance suffices until the shared check is available; enforcement is
  not claimed before it is adopted and exercised.
- A temporary open-story brief is excluded from published navigation and site
  output and changes no derived work counts; removing it restores the tree.

## S19.1.2 — Cut settled build prose without losing work

**State:** New · **Depends on:** S19.1.1

**Acceptance:**

- Review the E17 cutover and consumer migration pages, F11.1 and E12 first.
  Closed build recipes and repeated code are removed only after preserving
  acceptance, decisions, permanent IDs and links to current guidance.
- Open E17, E5 and F11.1 acceptance remains sufficient to finish the work;
  deferred triggers remain intact. No deferred design is elaborated.
- Existing inbound links still resolve; derived generation is idempotent and the
  strict docs build passes. No new historical review ledger is introduced.

## Acceptance

- S19.1.1: Briefs have one lifecycle and remain outside the published record.
- S19.1.2: Settled prose is cut while work IDs, open acceptance and links
