## S19.3.1 — Exercise public lifecycles and rendered interactions

**State:** Closed (2026-11-18)

**Acceptance:**

- Each correctness case in F19.4–F19.7 has a failing pre-fix regression through
  its public API or rendered host, followed by a passing post-fix run.
- Table tests exercise render, selection, rerender and fixture destruction;
  multi-typeahead tests type, select, remove, reset, blur and disable through
  a real reactive form. Creation-only tests do not stand in for these cases.
- Replace string-based access to manager internals where public actions or a
  typed test subclass suffice. Keep adapter integration assertions for real
  requests, form errors, ETags, retry keys and selection.
- Keep CSS artifact assertions that enforce token/layer API and browser tests
  for cascade and accessibility. Fake timers and controllable observables
  coordinate lifecycle cases without arbitrary sleeps or weaker assertions.

Outcome: the per-case regressions of the first line are written by the
F19.4–F19.7 stories that fix each case (reviewer ruling, 2026-11-18).

## S19.3.2 — Measure before removing machinery

**State:** New

**Acceptance:**

- Before F19.5 changes configuration, record repeated reads, input/override
  updates and mount/destroy churn at representative table/form option sizes:
  merge/diff calls, retained instances, elapsed time and peak memory.
- Before splitting the CRUD manager, identify independent responsibilities and
  the state crossing their boundaries. Split only where coupling or duplicated
  policy falls; keep it intact if extraction merely moves code.
- Set workload-specific no-regression or improvement criteria before choosing
  the implementation. Record results in the brief, retain required outcomes on
  the story, and make no speedup claim from static inspection.
