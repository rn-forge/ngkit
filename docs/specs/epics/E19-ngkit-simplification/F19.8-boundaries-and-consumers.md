## S19.8.1 — Enforce the declared dependency direction

**State:** Closed (2026-11-18)

**Acceptance:**

- Repository-owned lint configuration rejects a core-to-presentation import and
  an import between Bootstrap and Tailwind presentation libraries, while
  allowing presentation-to-core and demo consumers.
- Temporary negative fixtures demonstrate the failures; normal library and
  secondary-entry-point imports pass. Use existing lint capabilities, adding
  no dependency or parallel boundary-check framework.
- ADR-0002's statement that review alone enforces direction is updated only once
  these checks actually enforce it.

Outcome: `type:core`, `type:ui`, `ui:bootstrap` and `ui:tailwind` depConstraints
in `eslint.config.mjs`; ADR-0002 records the enforcement.

## S19.8.2 — Exercise Bootstrap as an installed consumer

**State:** Closed (2026-11-18) · **Depends on:** F17.5

**Acceptance:**

- A temporary standalone application installs packed `ng-bootstrap` and `ng`
  with resolved internal peers, imports the published Bootstrap entry points
  and theme, and builds/renders representative root, form and CRUD components.
- The declared Angular floor/current supported cells and zone/zoneless modes are
  explicit. Browser coverage proves startup import ordering and plugin
  availability; a namespace import alone is not a render check.
- Keep existing `ng` imports/storage and Tailwind plain/bridge builds, CSS
  cascade and accessibility coverage. Use F17.5's matrix/hook contract without
  restoring the deleted orchestration script or changing release mode.

Outcome: `ng-bootstrap:verify-consumer` runs four cells (22.0/22.1 ×
zone/zoneless) and `ng-bootstrap-e2e` serves 22.0-zone and 22.1-zoneless
fixtures. The cells name the packed `ng` tarball by version (owner decision,
2026-11-18); the releasing runbook updates it on each bump. Finding:
`window.bootstrap` is not set in an installed consumer (esbuild takes the UMD
CommonJS branch), contrary to `bootstrap-loader.ts`.
