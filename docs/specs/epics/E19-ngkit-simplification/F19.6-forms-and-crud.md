Give the form one value owner, apply relevant configuration changes, and keep
the CRUD renderer focused on translating UI events to its existing controller.

## S19.6.1 — Serialize values without truthiness loss

**State:** Closed (2026-11-18)

**Acceptance:**

- A submitted CRUD form preserves `0` and `false` in the data-source payload.
  Tests pin the intended handling of empty strings, nullish values and
  relation objects (including an ID of zero) before changing conversion.
- Keep application conversion overrides, ETags, idempotency retry behavior,
  problem-to-control errors and permission vocabulary working.
- After correctness coverage, extract manager responsibilities only if S19.3.2
  establishes a useful boundary. Presentation-free policy belongs in `ng`;
  dialogs and widget wiring stay in `ng-bootstrap`.
- `''`, `null` and `undefined` become `null`; a non-array object with an own
  `id` becomes its `id`; arrays, dates and other objects pass through
  unchanged (owner decision, 2026-11-18).

Outcome: S19.3.2 found no seam where extraction reduces coupling, so the manager
stays intact (owner decision, 2026-11-18).

## S19.6.2 — Apply configuration changes with the same control names

**State:** New

**Acceptance:**

- Replacing validators or context with unchanged control names takes effect;
  tests also cover control-definition changes and delimiter-containing names.
- Cosmetic options do not silently discard edits, touched/dirty state or
  disabled fields. Settle which structural changes rebuild the group and
  document their reset semantics before implementation.

## S19.6.3 — Wire multi-typeahead to one reactive-form value

**State:** Closed (2026-11-18)

**Acceptance:**

- Typing filters by the typed text; selecting/removing items updates the parent
  control's array value. Parent reset/value writes update the rendered chips.
- Blur marks the control touched; disabled state prevents typing, selection and
  removal. Updating the component does not mutate an array supplied by its
  caller. Tests run through the rendered host and parent `FormGroup`.
- Choose one Angular forms integration consistent with the neighboring fields;
  remove disconnected callback/value state instead of keeping two authorities.
  Preserve custom filtering/formatting and accessible action labels.
- The removed public members (`onChange`, `onTouched`, `writeValue`,
  `registerOnChange`, `registerOnTouched`, `setDisabledState`) are listed as a
  breaking change in the changelog of the release that ships them.

Outcome: the field reads and writes the parent `FormGroup` control only; the
typed text goes to the filter as typed.

## Acceptance

- S19.6.1: Submitted scalar values survive UI translation.
- S19.6.2: Relevant form configuration changes apply without accidental resets.
- S19.6.3: Multi-typeahead and its parent form share one value and disabled
  state.
