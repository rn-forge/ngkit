# F14.2 — `ng/crud` and the HTTP guide

**Status:** done · **Implemented:** 2026-10-24 · **Owner:** ngkit · **Epic:** [E14](index.md) · **Release:** [Release 2](../../../releases/release-2/index.md)

**Depends on:** [F14.1](F14.1-problem-types.md).

`@rn-forge/ng/crud` already reads problems through its own `ProblemDetails` and `problemOf`, which detect a problem by body shape. This feature moves it onto the core helpers, so there is one definition and it follows the media type, and shows the helpers in the HTTP guide.

## Stories

### S14.2.1 — `ng/crud` reads problems through core

**Status:** done (2026-10-24)

**Acceptance:**

- `ProblemDetails` and `crud`'s `problemOf` are removed; `crud` imports `Problem` and `problemOf` from `core`. No deprecated alias is kept.
- `ProblemFieldError` stays in `crud` as the shape of the `errors` extension, and `crud` reads it as `Problem<{ errors?: readonly ProblemFieldError[] }>`.
- `problemToFormErrors(error, form)` and `crudErrorKind(error)` take the `HttpErrorResponse`; a bare body is no longer accepted. `crudErrorKind` gives `problem` only for a 4xx whose body is a problem by media type, `conflict` for 412 as before, and `other` otherwise.
- `ng-bootstrap/crud`'s `crud.manager.ts` imports `problemOf` from `core`; its behaviour is unchanged for `application/problem+json` responses.
- The `crud` specs build their `HttpErrorResponse`s with a `Content-Type` header, and add: a 422 `application/json` body with `errors` gives `other` and leaves the form untouched; a 422 `application/problem+json; charset=utf-8` body gives `problem`.
- `libs/ng/crud/README.md` and [the resource screen architecture page](../../../architecture/resource-screen.md) name the media-type rule.

### S14.2.2 — `httpResource` and the HTTP guide

**Status:** done (2026-10-24)

**Acceptance:**

- A spec with `provideHttpClientTesting` and `HttpTestingController` shows `problemMessage(resource.error())` and `hasProblemType(resource.error(), …)` on an `httpResource` whose request fails with a 404 problem, and the same helpers on an `HttpClient` call's error.
- [The HTTP guide](../../../guides/http.md) gains a "Problem responses" section: a screen reads `problemMessage` and `hasProblemType` at the call site or from `httpResource().error()`; the application interceptor keeps rethrowing the original `HttpErrorResponse`; trace correlation comes from the `traceresponse` header, not the body.
