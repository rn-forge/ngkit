## Design

**Library candidates** (npm, 2026-09-23): `angular-auth-oidc-client` 22.0.1 (modified 2026-09-21, Angular `>=20`) and `angular-oauth2-oidc` 22.0.2 (modified 2026-06-26, Angular `>=22`). Recommended: `angular-auth-oidc-client`. Confirm its OpenID Foundation certification, refresh-token rotation and allowlisted interceptor in the implementing PR, and record the comparison.

**The wrapper:**

- `provideRnForgeAuth(config)`: a readonly typed config (`authority`, `clientId`, `scopes`, `secureRoutes`, `forbiddenPath`) mapped onto the library's own. Missing required config fails with `[rn-forge.ng.auth]`. The library's service stays reachable (escape hatch).
- Tokens attach **only** to `secureRoutes` (allowlist). `ignoreBackendURLs` is removed.
- A functional `authGuard` (`CanMatchFn`) that starts login with a return URL.
- `hasScope()` / `hasRole()` signals and a structural directive, reading the standard `scope` claim and RFC 9068 `roles`/`groups`. **UI hints only**; the server's 403 is authoritative.
- Profile from OIDC `userinfo` standard claims (`sub`, `name`, `email`, `picture`). `UserProfile`, `JwtCredentials`, the `profile` claim and `jwt-decode` are removed.
- One error policy in the RxJS error channel: 401 → re-authenticate once (no loop), 403 → `forbiddenPath`, never login.
- An explicit no-auth mode for demos and tests (`provideRnForgeAuth(false)` or similar), documented as never for production. It replaces the implicit `disableAuth: true` default.
