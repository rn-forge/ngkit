# F5.1 — Client model

**Status:** elaborating · **Owner:** ngkit · **Epic:** [E5](index.md)

Whether the SPA is a browser OIDC client or sits behind a backend-for-frontend, decided once so the rest of E5 builds against it.

## Stories

### S5.1.1 — Browser client or BFF

**Status:** planned

**Acceptance:** the choice is written into [ADR-0006](../../../adr/ADR-0006.md), which then moves to `accepted`.

## Design

- **Browser client (recommended start):** PKCE public client, tokens in memory, rotating refresh tokens. Needs no new backend component: the API only verifies the tokens.
- **BFF (upgrade path):** a same-origin backend holds the tokens and the browser holds only an HttpOnly session cookie. The IETF "OAuth 2.0 for Browser-Based Applications" draft ranks it most secure, and [the HTTP guide](../../../guides/http.md) already prefers a same-origin gateway. Needs a BFF component, which doesn't exist yet.
- Design E5 so a BFF is a drop-in: guards, `hasScope`/`hasRole` and the 401/403 policy stay; the token source changes, and Angular's XSRF support (`withXsrfConfiguration`) covers the cookie.

Open. Default: browser client + PKCE, BFF-ready. The choice stays open until S5.1.1 is done.
