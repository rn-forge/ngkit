# F15.1 — `createEventStream`

**Status:** elaborating · **Owner:** ngkit · **Epic:** [E15](index.md)

**Depends on:** none.

## Stories

### S15.1.1 — The factory and named handlers

**Status:** planned

```ts
export interface EventStreamOptions {
  /** URL, or a function read each time a new source is opened. */
  readonly url: string | (() => string);
  /** Handlers keyed by SSE event name; each receives the raw MessageEvent. */
  readonly events: Readonly<Record<string, (event: MessageEvent<string>) => void>>;
  /** Delay before opening a new source after the browser fails the connection. */
  readonly backoff?: { readonly baseMs?: number; readonly maxMs?: number }; // 1000, 30000
  readonly withCredentials?: boolean;
  readonly injector?: Injector;
}
export interface EventStream {
  readonly connected: Signal<boolean>;
  /** The underlying source, as an escape hatch; `null` when inert or between sources. */
  readonly source: Signal<EventSource | null>;
  close(): void; // idempotent
}
export function createEventStream(options: EventStreamOptions): EventStream;
export const RNF_EVENT_SOURCE_FACTORY: InjectionToken<((url: string, init: EventSourceInit) => EventSource) | null>;
```

`createEventStream` runs in an injection context, or takes `injector`. It opens one `EventSource`, attaches one listener per key of `events`, and never parses data: the handler owns `JSON.parse`.

**Acceptance:**

- A message with a registered name reaches that handler once; a name with no handler is ignored.
- A throwing handler does not close the stream; its error is passed to the injector's `ErrorHandler`.
- `RNF_EVENT_SOURCE_FACTORY` defaults to `EventSource` when it exists and `null` otherwise; a spec replaces it with a fake `EventSource`.

### S15.1.2 — Standard reconnection, backoff after failure

**Status:** planned

**Acceptance:**

- An `error` event while `readyState` is `CONNECTING` leaves the source open and schedules nothing: the browser's own reconnection (with `retry:` and `Last-Event-ID`) is not interrupted. A spec proves the fake source is not closed.
- An `error` event with `readyState` `CLOSED` opens a new source after `min(baseMs * 2^attempt, maxMs)` with equal jitter, so the delay lies in `[cap / 2, cap]`, and the attempt count then increases. A `url` function is called again for the new source.
- With the defaults, successive delays lie within 0.5 to 1 s, 1 to 2 s, and so on up to a cap of 30 s, shown with fake timers and a stubbed `Math.random`; `baseMs` and `maxMs` are configurable.
- The attempt count resets to zero on `open`.
- No new source is opened after `close()` or destroy, and a pending timer is cleared.

### S15.1.3 — `connected`

**Status:** planned

**Acceptance:**

- `connected` is `false` at first, `true` on `open`, `false` on `error` (in either `readyState`), and `false` after `close()`.

### S15.1.4 — Teardown and SSR

**Status:** planned

**Acceptance:**

- Destroying the owning injector (`DestroyRef`) closes the source and clears the timer; `close()` called before, after or twice is safe.
- With no `EventSource` (the factory is `null`, as on the server), `createEventStream` returns a stream whose `connected` stays `false` and `source` stays `null`, opens nothing and schedules nothing; calling `close()` is safe.
- All specs use a fake `EventSource` and fake timers, with no real sleeps; coverage of the new file is at least 90%.
