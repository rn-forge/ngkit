# S11.1.4 — `@rn-forge/ng-plugin:scaffold-component`

Brief for
[S11.1.4](../F11.1-ng-plugin.md#s1114-rn-forgeng-pluginscaffold-component), at
`ce8278f`.

## Goal

Add the `scaffold-component` generator to `@rn-forge/ng-plugin`
(`tools/ng-plugin`). It writes a standalone Angular component in an Angular
application or library, in one of four shapes (`component`, `page`, `table`,
`form`), following the conventions the repository's own libraries and demo app
already use. In a library it can also export the component from the public API.

## Settled

- **Contract:** F11.1's Design: the "`scaffold-component`" schema and steps, and
  "Design defaults": component templates `component`, `page`, `table`, `form`;
  `page` does not update routes; an application rejects `--export`; a story is
  skipped with a warning when Storybook is absent; the component prefix is the
  project's `prefix`, falling back to `rnf`. S11.1.4's acceptance.
- **"rn-forge conventions", as this repository's code shows them** (reviewer
  ruling, from `libs/ng-bootstrap/src/lib/alert/` and
  `apps/ng-demo/src/app/`):
    - One folder per component: `<base>/<file>/`, where `<file>` is
      `names(name).fileName` from `@nx/devkit` (so `CustomerGrid` and
      `customer-grid` both give `customer-grid`).
    - `<base>`: `<sourceRoot>/<directory>` when `directory` is given; otherwise
      `<sourceRoot>/app` for an application and `<sourceRoot>/lib` for a
      library. `sourceRoot` falls back to `<root>/src`.
    - Suffix: `page` for `type: page`, `component` for the other three. Files
      `<file>.<suffix>.ts`, `<file>.<suffix>.html`, `<file>.<suffix>.scss`
      (empty), plus `<file>.<suffix>.spec.ts` when `withTest` and
      `<file>.stories.ts` when a story is written.
    - Class: `<ClassName>PageComponent` for `page`, `<ClassName>Component`
      otherwise (`names(name).className`). Selector `<prefix>-<file>`.
    - Decorator: `selector`, `standalone: true`, `imports: [...]`, `templateUrl`,
      `styleUrl`.
- **The four templates** (TypeScript strings in the generator module, as
  `add-bootstrap-table` does; no template directory):
    - `component`: `imports: []`; HTML `<p><file> works</p>`.
    - `page`: `imports: []`; HTML a `<div class="container py-4">` holding
      `<h4 class="mb-1"><Title></h4>`, `<Title>` being `names(name).className`
      split into words (`Customer Grid`), as the demo pages' headings do.
    - `table`: `imports: [TableComponent]` from `@rn-forge/ng-bootstrap`,
      `options: Partial<TableOptions>` with two columns (`id`, `name`) and
      `data: []`; HTML `<rnf-table [options]="options" />`.
    - `form`: `imports: [FormComponent, InputFieldComponent]` from
      `@rn-forge/ng-bootstrap/form`, `formOptions: Partial<FormOptions>` with
      `controls: { name: [''] }` and `submitBtn: 'Submit'`; HTML
      `<rnf-form [options]="formOptions" [template]="fields" />` and an
      `<ng-template #fields let-ctx>` holding
      `<rnf-input-field name="name" label="Name" [formGroup]="ctx.formGroup" />`,
      as `apps/ng-demo/src/app/forms/forms.page.html` does.
- **Spec** (`withTest`, default `true`): the shape of
  `libs/ng-bootstrap/src/lib/table/table.component.spec.ts`: `describe` on the
  class, `TestBed.configureTestingModule({ imports: [<Class>] })`,
  `createComponent`, `detectChanges`, `afterEach` reset, and one
  `it('creates the component', ...)`. No Vitest imports (globals, as the
  libraries' specs use).
- **Story** (`withStory`): written only when the project has a `storybook` or
  `build-storybook` target or a `<root>/.storybook` directory; otherwise
  `logger.warn` and no story. Content: a `Meta<<Class>>` default export with
  `title: '<ClassName>'` and `component: <Class>`, and one
  `export const Default: StoryObj<<Class>> = {};`, typed imports from
  `@storybook/angular` as `alert.stories.ts` has them.
- **Project check:** add `readAngularProject(tree, project)` to
  `src/utils/angular-project.ts`, beside `readAngularApplication`: it accepts
  what `readAngularApplication` accepts, plus a `library` whose `build`
  executor is one of `@nx/angular:package`, `@nx/angular:ng-packagr-lite`,
  `@angular/build:ng-packagr`, `@angular-devkit/build-angular:ng-packagr`.
  Otherwise it throws an `Error` containing `Angular application or library`
  and the project name. Do not change `readAngularApplication`.
- **Refusals, before any change:**
    - `export` on an application → `Error` containing `--export` and `library`.
    - The component folder already exists → `Error` naming it; nothing is
      overwritten.
- **Export** (`export: true`, library only): append
  `export * from './<relative path to the .ts file without extension>';` to
  `<sourceRoot>/index.ts`, unless that exact line is already there. A missing
  `index.ts` → `Error` naming it, before any change.
- **Schema** (`src/generators/scaffold-component/schema.json` and `schema.d.ts`,
  `ScaffoldComponentGeneratorSchema`): `project` (string, required), `name`
  (string, required, `$default` argv 0), `directory` (string), `type` (enum
  `component`, `page`, `table`, `form`; default `component`), `export`
  (boolean, `false`), `withStory` (boolean, `false`), `withTest` (boolean,
  `true`).
- **No dependencies, no install.** The generator returns `Promise<void>` and
  calls `formatFiles(tree)`. It adds no route.
- **Registration and docs:** `generators.json` gains `scaffold-component`;
  `src/index.ts` exports `scaffoldComponentGenerator` and its schema type;
  `tools/ng-plugin/README.md` gains a section after `configure-theme` (usage
  line, options table, one sentence each on file layout and `--export`).

## Tests first

Write these in `generator.spec.ts` (tree from `createTreeWithEmptyWorkspace`; an
app `my-app` with `prefix: 'acme'` and an `@angular/build:application` build,
and a library `my-lib` at `libs/my-lib` with an `@nx/angular:package` build and
`libs/my-lib/src/index.ts`) and confirm each fails before the generator exists:

1. **Standalone component in an app:** `--name=customer-grid` writes
   `apps/my-app/src/app/customer-grid/customer-grid.component.{ts,html,scss,spec.ts}`;
   the `.ts` has `selector: 'acme-customer-grid'`, `standalone: true`,
   `export class CustomerGridComponent`, `templateUrl` and `styleUrl`; the
   spec imports `CustomerGridComponent` and has `creates the component`.
1. **Export from library:** `--project=my-lib --export` appends
   `export * from './lib/customer-grid/customer-grid.component';` to
   `libs/my-lib/src/index.ts`; a second run with a different `name` adds a
   second line, and the first stays once. Without `prefix` on `my-lib`, the
   selector is `rnf-customer-grid`.
1. **Types:** `page` writes `customer-grid.page.*` with
   `CustomerGridPageComponent` and `Customer Grid` in the heading; `table`
   imports `TableComponent` and renders `rnf-table`; `form` imports
   `FormComponent` and `InputFieldComponent` from `@rn-forge/ng-bootstrap/form`
   and renders `rnf-form`.
1. **`directory`:** `--directory=features` writes under
   `apps/my-app/src/features/customer-grid/`.
1. **`withTest: false`:** no `.spec.ts`.
1. **Story:** with a `storybook` target on `my-lib`, `withStory` writes
   `customer-grid.stories.ts` with `component: CustomerGridComponent`; without
   Storybook, no story and a warning (spy on `logger.warn`).
1. **Refusals:** `export` on `my-app`; an existing folder; a non-Angular project
   (`projectType: 'library'` with a `@nx/js:tsc` build) → each throws as
   settled above, and no file changed.
