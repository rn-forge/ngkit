# S11.1.3 — `@rn-forge/ng-plugin:configure-theme`

Brief for
[S11.1.3](../F11.1-ng-plugin.md#s1113-rn-forgeng-pluginconfigure-theme), at
`b6a8e63`.

## Goal

Add the `configure-theme` generator to `@rn-forge/ng-plugin`
(`tools/ng-plugin`). It imports the rn-forge Bootstrap theme into an Angular
application's SCSS stylesheet inside the managed `rn-forge` markers, through the
same helper `setup` uses.

## Settled

- **Contract:** F11.1's Design: "Decisions" (theme entry
  `@rn-forge/ng-bootstrap/assets/theme`, imported with a plain `@use` so a
  consumer can add `with (...)`), the "`configure-theme`" schema and steps,
  and "Design defaults" (stylesheet from the build target's `styles[]`,
  falling back to `src/styles.scss`; `default` preset only; marker-region
  patching; SCSS only). S11.1.3's acceptance.
- **Reuse:** `readAngularApplication` and `findStylesheet`
  (`src/utils/angular-project.ts`), and `ensureThemeImport`
  (`src/utils/theme.ts`). `setup` keeps calling `ensureThemeImport` as it does
  now; its behaviour and specs do not change.
- **Schema** (`src/generators/configure-theme/schema.json` and `schema.d.ts`,
  `ConfigureThemeGeneratorSchema`): `project` (string, required, `$default`
  argv 0), `theme` (string, `enum: ["default"]`, default `default`),
  `stylesheet` (string, optional; a workspace-relative path), `force`
  (boolean, `false`).
- **Stylesheet resolution:**
    - With `stylesheet`: use it. If it does not exist or does not end in `.scss`,
      throw an `Error` naming the path, before any change.
    - Without it: `findStylesheet(tree, config)`. If that returns nothing, throw
      an `Error` containing `no SCSS stylesheet` and suggesting `--stylesheet`.
      (`setup` warns and skips instead, because the theme is one of its several
      steps; for this generator it is the only step.)
- **`force`** (an optional third parameter on the helper,
  `ensureThemeImport(tree, path, { force })`, default `false`):
    - When both markers exist, `force` replaces everything between them with the
      one line `@use '@rn-forge/ng-bootstrap/assets/theme';`, discarding a
      `with (...)` clause or other lines a user put there.
    - Without both markers, `force` changes nothing beyond the normal behaviour:
      an unmarked import outside the markers is left as it is, and a file with
      no import gets the marked block at the top.
    - Without `force`, behaviour is exactly today's: any existing import of the
      module, inside or outside the markers, means no change.
- **No dependencies, no install:** the generator adds no packages and returns
  nothing (`Promise<void>`). It calls `formatFiles(tree)`.
- **Registration:** `generators.json` gains `configure-theme` (factory
  `./src/generators/configure-theme/generator`, schema
  `./src/generators/configure-theme/schema.json`, a one-line description).
  `src/index.ts` exports it as `configureThemeGenerator` with its schema type.
- **README:** `tools/ng-plugin/README.md` gains a `configure-theme` section
  after `add-bootstrap-table`: usage line, options table, and one sentence on
  `force`.

## Current behaviour

At `b6a8e63`:

- `generators.json` lists `setup` and `add-bootstrap-table`; there is no
  `src/generators/configure-theme/`, so the new spec fails on its import.
- `ensureThemeImport(tree, path)` takes no options. It warns and returns for a
  missing or non-SCSS path; returns unchanged when the file matches
  `/@use\s+['"]@rn-forge\/ng-bootstrap\/assets\/theme['"]/` anywhere; puts the
  `@use` line before `// rn-forge:end` when both markers exist; otherwise
  prepends the three-line marked block. A `with (...)` import inside the
  markers therefore counts as present, which is why `force` is needed to reset
  it.
- Every gate step passes except `kiln:doctor` (in `task lint`), which fails on
  the base too: `kiln.ref: 'feature/v1' names a branch`. That failure is
  expected; see Validation.

## Tests first

Write these in `generator.spec.ts` (tree from `createTreeWithEmptyWorkspace`, an
app `my-app` with `styles: ['apps/my-app/src/styles.scss']`, as in
`src/generators/setup/generator.spec.ts`) and confirm each fails before the
generator and the `force` option exist:

1. **Default theme:** a stylesheet `body {\n  margin: 0;\n}\n` gains the marked
   block at the top, and `body` is kept.
1. **Idempotent:** a second run leaves the file byte-identical; the `@use` line
   appears once.
1. **Existing unmarked import:** unchanged, without and with `force`.
1. **`force` resets the block:** markers holding
   `@use '@rn-forge/ng-bootstrap/assets/theme' with ($primary: #000);` → with
   `force`, the region holds only the plain `@use` line; without `force`, the
   file is unchanged.
1. **Explicit `stylesheet`:** `--stylesheet=apps/my-app/src/theme.scss` (an
   existing file not in `styles[]`) is patched, and `styles.scss` is not.
1. **Bad `stylesheet`:** a missing path and a `.css` path each throw with the
   path in the message; no file changed.
1. **No stylesheet found:** an app with `styles: []` and no `src/styles.scss`
   throws with `no SCSS stylesheet`.
1. **Non-Angular project rejected:** a library `my-lib` → throws with
   `Angular application`; no file changed.
