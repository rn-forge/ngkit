# S11.1.7 — `@rn-forge/ng-plugin:create-library`

Brief for
[S11.1.7](../F11.1-ng-plugin.md#s1117-rn-forgeng-plugincreate-library), at
`d7c5a64`.

## Goal

Add the `create-library` generator to `@rn-forge/ng-plugin` (`tools/ng-plugin`).
It scaffolds a publishable Angular library through `@nx/angular`'s library
generator, then applies the settings the
[publishable-library guide](../../../../guides/development.md#adding-a-publishable-library)
lists, so the new project packs, verifies and releases like `ng`, `ng-bootstrap`
and `ng-tailwind`.

## Settled

- **Contract:** F11.1's Design: "Decisions" (`create-library` lives here because
  it needs `@nx/angular`; it writes the project's publishable settings itself
  and does not edit `nx.json#release.projects`; Storybook and Compodoc are
  flags), the "`create-library`" schema and steps. S11.1.7's acceptance.
- **Peer:** `tools/ng-plugin/package.json` gains the peer `@nx/angular`
  `^24.0.0`. Like the other peers it adds no lockfile importer (S11.1.1);
  confirm `pnpm-lock.yaml` is unchanged after `task setup`.
- **Order of work, each step on the same tree:**
    1. **Refuse an existing project first:** if `getProjects(tree)` has `name`,
       throw an `Error` naming it, before any change.
    1. `libraryGenerator` (`@nx/angular/generators`) with `name`, `directory`
       (default `libs/<name>`), `importPath`, `publishable: true`,
       `standalone: true`, `strict: true`, `style: 'scss'`,
       `unitTestRunner: 'vitest-angular'`, `linter: 'eslint'`,
       `skipFormat: true`. Keep its returned callback.
    1. For each comma-separated, trimmed, non-empty `secondaryEntryPoints` name:
       `librarySecondaryEntryPointGenerator` with `name`, `library: <name>`,
       `skipFormat: true`.
    1. **Peers:** in `<projectRoot>/package.json`, move every `@angular/*` entry
       from `dependencies` and `devDependencies` into `peerDependencies`
       (keeping the version; an entry already in `peerDependencies` wins). Drop
       an emptied `dependencies` or `devDependencies` object.
    1. **Package metadata** in `<projectRoot>/package.json`: `description`
       (`"<importPath> Angular library."` unless one is set), `license` (the
       root `package.json`'s, else `MIT`), `repository` (the root
       `package.json`'s `repository` with `directory` set to the project root,
       when the root has one; otherwise `logger.warn` that `repository` must be
       added by hand), `publishConfig.access: "public"`.
    1. **Project settings** in `project.json` (`updateProjectConfiguration`):
        - add the `publishable` tag (keep existing tags, no duplicate);
        - `release.version.manifestRootsToUpdate` set to
          `["{projectRoot}", { "path": "dist/{projectRoot}", "preserveLocalDependencyProtocols": false }]`;
        - targets `pack: {}`, `verify-dist: {}`, and `nx-release-publish` with
          `options: { packageRoot: "dist/{projectRoot}", dryRun: true }`;
        - the `test` target's `options.coverage: true` and `coverageThresholds` of
          `coverageThreshold` (default `35`) for `statements`, `branches`,
          `functions` and `lines`.
    1. **`tsconfig.spec.json`:** `exclude` gains `**/*.stories.ts` and
       `**/*.stories.js` (once each).
    1. **Storybook** (`storybook: true`):
        - write `<projectRoot>/.storybook/main.ts`, `preview.ts` and
          `tsconfig.json`, as `libs/ng-tailwind/.storybook/` has them but without
          the `webpackFinal` alias and with an empty `preview.ts` default export
          (`const preview = {}; export default preview;`);
        - add the `build-storybook` target:
          `executor: "@storybook/angular:build-storybook"`,
          `options: { configDir, tsConfig: "<projectRoot>/.storybook/tsconfig.json", outputDir: "dist/storybook/<name>" }`,
          `configurations: { production: {} }`;
        - add the root devDependencies `storybook` and `@storybook/angular`
          (`10.6.6` each, constants in `src/utils/versions.ts`), keeping existing
          versions.
    1. **Compodoc** (`compodoc: true`):
        - write `<projectRoot>/tsconfig.compodoc.json` as
          `libs/ng-tailwind/tsconfig.compodoc.json` has it;
        - add the `compodoc` target as `libs/ng-tailwind/project.json` has it
          (executor `@twittwer/compodoc:compodoc`, `outputs`
          `["{workspaceRoot}/dist/compodoc/<name>"]`, `tsConfig`,
          `outputPath: "dist/compodoc/<name>"`, and the `json` and `serve`
          configurations);
        - add the root devDependencies `@twittwer/compodoc` (`^1.13.0`) and
          `@compodoc/compodoc` (`^2.0.0`), keeping existing versions.
    1. `formatFiles(tree)`; return a callback that runs the library generator's
       callback and then `installPackagesTask(tree)`, unless `skipInstall`, in
       which case return `undefined`.
- **Not done:** `nx.json` is never written; no `verify-consumer`, no
  `patch-package-exports`, no `exports` field, no README or Projects-table
  rows (those are the consumer repository's), no change to
  `tsconfig.base.json` beyond what `@nx/angular` itself writes.
- **Schema** (`src/generators/create-library/schema.json` and `schema.d.ts`,
  `CreateLibraryGeneratorSchema`): `name` (string, required, `$default` argv
  0), `importPath` (string, required), `directory` (string),
  `secondaryEntryPoints` (string), `storybook` (boolean, `false`), `compodoc`
  (boolean, `false`), `coverageThreshold` (number, `35`), `skipInstall`
  (boolean, `false`).
- **Registration and docs:** `generators.json` gains `create-library`;
  `src/index.ts` exports `createLibraryGenerator` and its schema type;
  `tools/ng-plugin/README.md` gains a section after `scaffold-component`
  (usage line, options table, and the list of settings it writes).
- **Build check (reviewer):** a tree spec cannot run `nx build`. The reviewer
  runs the built generator once against the worktree's real file tree, builds
  the generated library with `pnpm nx build my-ui`, and reverts; that is the
  acceptance's `build` line. The implementer does not need to.

## Current behaviour

At `d7c5a64`:

- `generators.json` lists `setup`, `add-bootstrap-table`, `configure-theme` and
  `scaffold-component`; there is no `src/generators/create-library/`, so the
  new spec fails on its import.
- `@nx/angular` 24.0.4 is a root devDependency. `@nx/angular/generators` exports
  `libraryGenerator(tree, schema): Promise<GeneratorCallback>` and
  `librarySecondaryEntryPointGenerator(tree, options): Promise<void>` (schema
  requires `name` and `library`). With `unitTestRunner: 'vitest-angular'` the
  library's `test` target uses `@nx/angular:unit-test`, which needs Angular
  21+ in the root `package.json`, so the spec's tree must declare
  `@angular/core` (use `~22.2.5`, the root's range).
- Every gate step passes except `kiln:doctor` (in `task lint`), which fails on
  the base too: `kiln.ref: 'feature/v1' names a branch`. That failure is
  expected; see Validation.
