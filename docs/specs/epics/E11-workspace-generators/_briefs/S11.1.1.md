# S11.1.1 — `@rn-forge/ng-plugin:setup`

Brief for [S11.1.1](../F11.1-ng-plugin.md#s1111-rn-forgeng-pluginsetup), at
`744eae3`.

## Goal

Create the `@rn-forge/ng-plugin` package (`tools/ng-plugin`, Nx project
`ng-plugin`, tagged `publishable`) with its first generator, `setup`, which
configures an existing Angular application to consume `@rn-forge/ng` and
`@rn-forge/ng-bootstrap`. Build the two helpers that S11.1.2 and S11.1.3 will
reuse (theme import, Bootstrap Table dependencies) as internal modules.

- **Lockfile.** `pnpm-workspace.yaml` already includes `tools/**`, so the new
  `package.json` is a workspace package and `pnpm-lock.yaml` needs its
  importer, or `task setup` (frozen lockfile) fails. No `task` verb updates
  the lockfile, so run `pnpm install --lockfile-only` once, after writing
  `tools/ng-plugin/package.json`. This is the one exception to the
  task-entrypoint rule in this story; record it under Deviations. The lockfile
  diff must be only the new `tools/ng-plugin` importer; any other change stops
  the story.
- **Version source.** The generator reads its own `package.json` `version` at
  run time (resolved relative to the compiled generator, so it works from
  `dist/tools/ng-plugin`) and adds `@rn-forge/ng` and `@rn-forge/ng-bootstrap`
  as `^<version>`.
- **Peers.** One constant in `src/utils/versions.ts` holds
  `libs/ng-bootstrap/package.json`'s `peerDependencies` without `@rn-forge/ng`
  (a superset of `libs/ng`'s peers). `setup` adds every entry except the three
  Bootstrap Table packages; the Bootstrap Table helper adds those three
  (`bootstrap-table`, `jquery`, `jquery-treegrid`) with the constant's ranges,
  so `includeBootstrapTable: false` leaves them out. All go in `dependencies`.
  Existing entries keep their versions
  (`addDependenciesToPackageJson(..., keepExistingVersions: true)`).
- **Angular application check.** `project` must exist, have `projectType`
  `application`, and a `build` target whose executor is one of
  `@angular/build:application`, `@angular-devkit/build-angular:application`,
  `@angular-devkit/build-angular:browser`, `@nx/angular:application`,
  `@nx/angular:browser-esbuild`. Otherwise throw an `Error` whose message
  contains `Angular application` and the project name, before changing any
  file.
- **Stylesheet (`src/utils/theme.ts`, `ensureThemeImport(tree, path)`).**
    - Path: the first entry of the build target's `options.styles` (a string or an
      object's `input`) ending in `.scss`; otherwise `<sourceRoot>/styles.scss`
      if it exists. A non-SCSS or missing stylesheet logs a warning
      (`logger.warn`) and is skipped, not an error.

    - Already imported anywhere in the file
      (`/@use\s+['"]@rn-forge\/ng-bootstrap\/assets\/theme['"]/`): no change.

    - Otherwise insert at the top of the file (Sass requires `@use` before other
      rules):

        ```scss
        // rn-forge:start
        @use '@rn-forge/ng-bootstrap/assets/theme';
        // rn-forge:end
        ```

        If both markers already exist without the import, put the `@use` line
        between them instead.

    - Patched only when `skipStyles` is false and `includeTheme` is true.
- **Build target options** (skipped by `skipConfig`):
    - `allowedCommonJsDependencies`: the union of existing entries and
      `bootstrap/dist/js/bootstrap.bundle.js`, `build-url-ts`, `jquery`,
      `jquery-treegrid`, `quill-delta`, sorted, no duplicates.
    - `polyfills`: absent → `["@angular/localize/init"]`; an array → appended
      once; a string → `[<string>, "@angular/localize/init"]` unless it is that
      entry.
    - `scripts`, `assets` and `styles` are never written.
    - Write the project configuration only when a value changed.
- **`app.config.ts`** (skipped by `skipConfig`):
  `<sourceRoot>/app/app.config.ts`. Missing → `logger.warn` and skip. Parse
  with the TypeScript compiler API (`typescript`, the peer) to find the
  `providers` array literal in the exported `ApplicationConfig` object. If any
  element calls `provideRnForgeBootstrapConfig`, change nothing. Otherwise
  append `provideRnForgeBootstrapConfig({})` as the last element and add
  `import { provideRnForgeBootstrapConfig } from '@rn-forge/ng-bootstrap';`
  unless the name is already imported. Edit by text offsets from the AST; no
  new dependency.
- **Install.** The generator returns
  `() => installPackagesTask(tree, false, tree.root, options.packageManager)`
  unless `skipInstall`, and `undefined` with `skipInstall`. It calls
  `formatFiles(tree)` before returning.
- **Idempotent.** A second run on the same tree changes no file.
- **README note.** `libs/ng-bootstrap/README.md:41-42` ("This list will be added
  automatically by a scaffolding generator in a future version.") becomes a
  pointer: `@rn-forge/ng-plugin:setup` writes this list, with the usage line.
- **Project tables.** Add an `ng-plugin` row to the Projects table in
  `README.md` and `docs/architecture/workspace.md` ("Nx plugin
  (`tools/ng-plugin`), published as `@rn-forge/ng-plugin`: generators that set
  up Angular apps for the rn-forge libraries"), and add `ng-plugin` to the
  `pack` line under "Nx targets worth knowing" in `workspace.md`.

  `pnpm nx test ng-plugin` fails with "Cannot find project 'ng-plugin'".

  including `@rn-forge/ng` (`workspace:^`), `@angular/localize` and the three
  Bootstrap Table packages.

## Tests first

Write these in `generator.spec.ts` (tree from `createTreeWithEmptyWorkspace`, an
app added with `addProjectConfiguration`) before the generator, and confirm they
fail (generator module missing, or a stub that throws):

1. **Full setup:** an app `my-app` (`@angular/build:application`, `styles`
   `["apps/my-app/src/styles.scss"]`, an `app.config.ts` with
   `providers: [provideRouter(routes)]`). After `setup` with `skipInstall`:
   root `package.json` `dependencies` has `@rn-forge/ng` and
   `@rn-forge/ng-bootstrap` at `^<plugin version>`, every peer constant entry,
   and the three Bootstrap Table packages; the stylesheet has the marked
   `@use` block; `allowedCommonJsDependencies` is the five entries;
   `polyfills` is `["@angular/localize/init"]`; `app.config.ts` imports and
   provides `provideRnForgeBootstrapConfig({})`; `scripts` and `assets` are
   unchanged from the fixture.
1. **Idempotent:** run twice; every file's content after the second run equals
   that after the first.
1. **Non-Angular project rejected:** a library `my-lib` → throws with
   `Angular application`; no file changed (`tree.listChanges()` empty after
   the fixture is committed or compared).
1. **skipInstall:** returns `undefined`; without it, returns a function that
   calls `installPackagesTask` (mock `@nx/devkit`'s export with `vi.mock`,
   keeping the rest).
1. **skipStyles** and **`includeTheme: false`:** stylesheet unchanged.
1. **Existing unmarked theme import:** stylesheet unchanged; the module appears
   once.
1. **Existing config preserved:** existing `allowedCommonJsDependencies`
   (`lodash`) and `polyfills` (`zone.js`) remain, the new entries appear once.
1. **`includeBootstrapTable: false`:** the three packages are absent.
1. **skipConfig:** build target options and `app.config.ts` unchanged.
1. **Peer constant in sync:** read `libs/ng-bootstrap/package.json` from
   `workspaceRoot` (`@nx/devkit`); its `peerDependencies` minus `@rn-forge/ng`
   equals the constant.
1. **Demo app configuration:** load `apps/ng-demo/project.json`,
   `apps/ng-demo/src/styles.scss` and `apps/ng-demo/src/app/app.config.ts`
   from `workspaceRoot` into the tree; after `setup` with `skipInstall`, the
   build target's `options` deep-equal the originals and the two files are
   byte-identical. This is the acceptance's "demo app's configuration"
   fixture: with the gate's `ng-demo` build, it shows that what `setup` writes
   builds without CommonJS warnings.
