# F11.1 — `@rn-forge/ng-plugin`

**Status:** planned · **Owner:** ngkit · **Epic:** [E11](index.md) · **Release:** [Release 3](../../../releases/release-3/index.md)

Published Nx plugin for Angular-specific rn-forge setup and component/configuration generators. It ships in the fixed release group ([design](design.md#release-model)).

## Stories

### S11.1.1 — `@rn-forge/ng-plugin:setup`

**Status:** planned

**Acceptance:**

```gherkin
Feature: ng-plugin:setup generator

  Background:
    Given an Nx Angular workspace
    And an Angular app "my-app" exists

  Scenario: full setup
    When I run "pnpm nx g @rn-forge/ng-plugin:setup --project=my-app"
    Then package.json contains @rn-forge/ng and @rn-forge/ng-bootstrap and their peer dependencies
    And the app stylesheet contains "@use '@rn-forge/ng-bootstrap/assets/theme';" between the rn-forge markers
    And the build target options list "allowedCommonJsDependencies" with bootstrap/dist/js/bootstrap.bundle.js, jquery, jquery-treegrid, quill-delta and build-url-ts
    And app.config.ts provides provideRnForgeBootstrapConfig({})
    And the build target gains no scripts, polyfills or assets entries
    And "pnpm nx build my-app" succeeds without CommonJS warnings

  Scenario: idempotent
    Given ng-plugin:setup has already been run on "my-app"
    When I run the generator again
    Then no files are changed

  Scenario: non-Angular project rejected
    When I run "pnpm nx g @rn-forge/ng-plugin:setup --project=my-lib"
    Then the generator exits with an error containing "Angular application"

  Scenario: skipInstall
    When I run "pnpm nx g @rn-forge/ng-plugin:setup --project=my-app --skipInstall"
    Then package.json is updated but install is not executed

  Scenario: skipStyles
    When I run "pnpm nx g @rn-forge/ng-plugin:setup --project=my-app --skipStyles"
    Then the app stylesheet is not modified

  Scenario: existing unmarked theme import
    Given the app stylesheet already contains "@use '@rn-forge/ng-bootstrap/assets/theme';" outside the markers
    When I run the generator
    Then the stylesheet is not changed and the module is imported once

  Scenario: existing config preserved
    Given the build target already lists other allowedCommonJsDependencies
    When I run the generator
    Then those entries remain and the five rn-forge entries are added once
```

The tests run each scenario in a temporary Nx workspace tree (`createTreeWithEmptyWorkspace`) inside this repository. The Angular app fixture for `build` is the demo app's configuration.

Part of this story's done state: once `setup` exists, `libs/ng-bootstrap/README.md` replaces its "will be added automatically by a scaffolding generator" note with a pointer to `@rn-forge/ng-plugin:setup`.

## Design

### Decisions

Recorded by S11.1.6 (owner decision, 2026-10-17).

- **What `setup` wires.** `provideRnForgeBootstrapConfig()` loads every vendor script at runtime and `ng-bootstrap` needs no `scripts`, `polyfills` or `assets` entries (`libs/ng-bootstrap/README.md`), so no generator patches the build target's `scripts`, `polyfills` or `assets`. `setup` does only what the package cannot do for itself: add the packages, import the theme, list the CommonJS dependencies and register the provider.
- **No path aliases.** Published packages resolve through `node_modules` and the `exports` map patched into the dist manifest (`./assets/*`), so no generator touches `tsconfig.base.json` for them.
- **Theme path.** The stylesheet entry is `@rn-forge/ng-bootstrap/assets/theme` (`libs/ng-bootstrap/assets/theme.scss`), imported with a plain `@use` so a consumer can add `with (...)` overrides. There is no `/styles` entry.
- **`allowedCommonJsDependencies`.** `setup` writes all five entries (`bootstrap/dist/js/bootstrap.bundle.js`, `jquery`, `jquery-treegrid`, `quill-delta`, `build-url-ts`). Two are always needed; the other three depend on features the generator cannot detect, and an unused entry is harmless.
- **`add-bootstrap-table` shrinks** to the three dependencies (`bootstrap-table`, `jquery`, `jquery-treegrid`) and an optional example component. The extension list is dropped because the library loads its extensions itself.
- **Angular library scaffolding lives here** as `create-library`: it needs `@nx/angular` and Angular peer-dependency knowledge (the rule in [design.md](design.md#design-decision)). Storybook and Compodoc stay flags on it.
- **`create-library` writes the project's publishable settings itself** (owner decision, 2026-10-17). It was to compose `nx-plugin:create-publishable-lib`, retired with F11.2 because kiln owns repository-level setup ([epic](index.md)). The settings it writes (the `publishable` tag, package metadata, `manifestRootsToUpdate`, `pack`, `verify-dist`, `nx-release-publish`) belong to the project, not the repository: they are the declarations [the CI template](../../../architecture/ci-template.md) leaves to the repository, and kiln at most seeds them once and then leaves them to the repository (kiln F9.1). The steps are the [publishable-library guide](../../../guides/development.md#adding-a-publishable-library)'s.

### Considered and rejected

- **Keeping script, polyfill and asset patching in `setup`.** The library already loads them; patching would double-load them.
- **An `--linkLocal` alias option.** Nothing needs aliases for tarball-installed packages; add it when a local-linking workflow exists.
- **Dropping `add-bootstrap-table`.** Kept for the dependency and example wiring, which `setup` includes by default.
- **Deferring `create-library` until kiln generates library projects.** kiln's planned package generator covers Python workspaces only (kiln E10, F11.3); the guide's steps are already manual work this generator removes.

### `setup`

Configures an existing Angular app to consume `@rn-forge/ng` and `@rn-forge/ng-bootstrap`.

It belongs in `ng-plugin` because it understands Angular app structure and rn-forge Angular runtime packages.

#### Usage

```bash
pnpm nx g @rn-forge/ng-plugin:setup --project=my-app
```

#### Schema

| Option                  | Type    | Required | Default | Description                                                     |
| ----------------------- | ------- | -------- | ------- | --------------------------------------------------------------- |
| `project`               | string  | yes      | —       | Angular app project to configure                                |
| `packageManager`        | enum    | no       | `pnpm`  | `pnpm \| npm \| yarn`                                           |
| `skipInstall`           | boolean | no       | `false` | Skip dependency installation                                    |
| `skipStyles`            | boolean | no       | `false` | Skip app stylesheet injection                                   |
| `skipConfig`            | boolean | no       | `false` | Skip `allowedCommonJsDependencies` and `app.config.ts` provider |
| `includeBootstrapTable` | boolean | no       | `true`  | Add the Bootstrap Table dependencies during setup               |
| `includeTheme`          | boolean | no       | `true`  | Include rn-forge theme/style wiring during setup                |

#### Steps

1. Validate that `project` exists and is an Angular application.
2. Add `@rn-forge/ng` and `@rn-forge/ng-bootstrap` at the plugin's own version (the three share one release version), plus the peer dependencies `ng-bootstrap` declares.
3. Inject `@use '@rn-forge/ng-bootstrap/assets/theme';` between the `rn-forge:start` and `rn-forge:end` markers in the app stylesheet (the `configure-theme` helper). When the stylesheet already imports that module outside the markers, change nothing.
4. Merge the five CommonJS entries into the build target's `options.allowedCommonJsDependencies`, keeping existing entries, sorted and without duplicates.
5. Add `provideRnForgeBootstrapConfig({})` and its import to the providers in `app.config.ts`.
6. Add the Bootstrap Table dependencies through the same helper as `:add-bootstrap-table`.
7. Format files.
8. Run package installation unless `skipInstall` is true.

Adds Bootstrap Table support to an Angular app already using, or about to use, `@rn-forge/ng-bootstrap`.

#### Usage

```bash
pnpm nx g @rn-forge/ng-plugin:add-bootstrap-table --project=my-app
```

#### Schema

| Option            | Type    | Required | Default | Description                                            |
| ----------------- | ------- | -------- | ------- | ------------------------------------------------------ |
| `project`         | string  | yes      | —       | Angular app project to configure                       |
| `skipInstall`     | boolean | no       | `false` | Skip dependency installation                           |
| `scaffoldExample` | boolean | no       | `false` | Create an example component/page using Bootstrap Table |

#### Steps

1. Validate Angular application project.
2. Add `bootstrap-table`, `jquery` and `jquery-treegrid` to `package.json` when absent.
3. Optionally scaffold an example standalone component.
4. Format files.
5. Install packages unless skipped.

### `scaffold-component`

Creates an opinionated Angular standalone component using rn-forge conventions.

#### Usage

```bash
pnpm nx g @rn-forge/ng-plugin:scaffold-component --project=my-app --name=customer-grid
```

#### Schema

| Option      | Type    | Required | Default     | Description                                              |
| ----------- | ------- | -------- | ----------- | -------------------------------------------------------- |
| `project`   | string  | yes      | —           | Target Angular app or library                            |
| `name`      | string  | yes      | —           | Component name                                           |
| `directory` | string  | no       | auto        | Directory relative to project source root                |
| `type`      | enum    | no       | `component` | `component \| page \| table \| form`                     |
| `export`    | boolean | no       | `false`     | Export from library public API when project is a library |
| `withStory` | boolean | no       | `false`     | Generate a Storybook story if Storybook exists           |
| `withTest`  | boolean | no       | `true`      | Generate Vitest spec                                     |

#### Steps

1. Validate target project is Angular app or library.
2. Generate a standalone Angular component.
3. Apply rn-forge naming, prefix, SCSS, and testing conventions.
4. Add optional story/test files.
5. Update library public API when requested.
6. Format files.

### `create-library`

Scaffolds a publishable Angular library.

#### Usage

```bash
pnpm nx g @rn-forge/ng-plugin:create-library --name=my-ui --importPath=@acme/my-ui
```

#### Schema

| Option                 | Type    | Required | Default | Description                                                      |
| ---------------------- | ------- | -------- | ------- | ---------------------------------------------------------------- |
| `name`                 | string  | yes      | —       | Library project name                                             |
| `importPath`           | string  | yes      | —       | npm package name                                                 |
| `directory`            | string  | no       | `libs/` | Library directory                                                |
| `secondaryEntryPoints` | string  | no       | —       | Comma-separated entry point names                                |
| `storybook`            | boolean | no       | `false` | Declare `build-storybook` writing `dist/storybook/{projectName}` |
| `compodoc`             | boolean | no       | `false` | Declare `compodoc` writing `dist/compodoc/{projectName}`         |
| `coverageThreshold`    | number  | no       | `35`    | Vitest coverage threshold for all metrics                        |
| `skipInstall`          | boolean | no       | `false` | Skip dependency installation                                     |

#### Steps

1. Validate that the project name is free.
2. Run `@nx/angular:library` with publishable, standalone, strict, SCSS and Vitest Angular options.
3. Scaffold secondary entry points if requested.
4. Move `@angular/*` packages to `peerDependencies`.
5. Apply the [publishable-library guide](../../../guides/development.md#adding-a-publishable-library)'s settings: the `publishable` tag, package metadata, `release.version.manifestRootsToUpdate`, and the `pack`, `verify-dist` and `nx-release-publish` (`dryRun: true`) targets. `nx.json#release.projects` is not edited.
6. Apply library defaults: eslint baseline, Vitest target, `tsconfig.spec.json` include/exclude.
7. Add the Storybook and Compodoc targets when requested, with the target names and output paths above, so the docs site finds them.
8. Format files; install unless skipped.

## Design defaults

These defaults stand until a story's work shows a reason to change them.

| Topic                  | Default                                                                                             |
| ---------------------- | --------------------------------------------------------------------------------------------------- |
| Build target detection | Standard Nx Angular executors only                                                                  |
| Stylesheet location    | Read build target `styles[]`; fallback to `src/styles.scss`                                         |
| SSR                    | Not supported initially; detect and warn only                                                       |
| Example scaffold       | Standalone component only                                                                           |
| Theme presets          | `default` only; marker region patching; SCSS only                                                   |
| Component templates    | `component`, `page`, `table`, `form`; `page` does not update routes                                 |
| Public API export      | App projects reject `--export`; story generation is skipped with a warning when Storybook is absent |
| Component prefix       | Workspace/project prefix, fallback `rnf`                                                            |
| Testing                | Same thresholds for apps and libraries; keep `35`; Vitest Angular only                              |

## Open questions

1. **`@angular/localize/init` polyfill.** `apps/ng-demo/project.json` lists `"polyfills": ["@angular/localize/init"]` and `@angular/localize` is a peer of `ng-bootstrap`, but the `ng-bootstrap` README does not say whether an app needs the polyfill. Verify against the library's use of `$localize`; if it is needed, `setup` adds the polyfill (and the story's acceptance gains a line for it), otherwise this question is removed.
