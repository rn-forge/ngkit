Published Nx plugin for Angular-specific rn-forge setup and
component/configuration generators. It ships in the fixed release group
([design](design.md#release-model)).

## Design

### Decisions

Recorded by S11.1.6 (owner decision, 2026-10-17; re-confirmed 2026-11-17).

- **What `setup` wires.** `provideRnForgeBootstrapConfig()` loads every vendor
  script at runtime and `ng-bootstrap` needs no `scripts` or `assets` entries
  (`libs/ng-bootstrap/README.md`), so no generator patches the build target's
  `scripts` or `assets`. `setup` does only what the package cannot do for
  itself: add the packages, import the theme, list the CommonJS dependencies,
  add the `@angular/localize/init` polyfill and register the provider.
- **`@angular/localize/init` polyfill** (owner decision, 2026-11-17).
  `@ng-bootstrap/ng-bootstrap`, a peer of `ng-bootstrap`, calls `$localize`,
  so an app without the polyfill fails at runtime; `ng-bootstrap`'s own test
  setup and the demo app load it. `setup` adds it to the build target's
  `polyfills`, and it is the one `polyfills` entry a generator writes.
- **Peers are also dev dependencies** (owner decision, 2026-11-17). pnpm 12
  writes no lockfile importer for a workspace package whose only dependencies
  are peers, even with `autoInstallPeers`, and then warns on every run that
  the package "has dependencies but does not have a modules directory".
  Listing each peer in `devDependencies` as well, as `libs/ng-bootstrap` does,
  gives the package an importer. It is a `devDependencies` and not a
  `dependencies` entry so that the production audit does not take in the Nx
  toolchain. This applies to the plugin itself and to every library
  `create-library` generates, in this repository and in the workspaces that
  use it.
- **No path aliases.** Published packages resolve through `node_modules` and the
  `exports` map patched into the dist manifest (`./assets/*`), so no generator
  touches `tsconfig.base.json` for them.
- **Theme path.** The stylesheet entry is `@rn-forge/ng-bootstrap/assets/theme`
  (`libs/ng-bootstrap/assets/theme.scss`), imported with a plain `@use` so a
  consumer can add `with (...)` overrides. There is no `/styles` entry.
- **`allowedCommonJsDependencies`.** `setup` writes all five entries
  (`bootstrap/dist/js/bootstrap.bundle.js`, `jquery`, `jquery-treegrid`,
  `quill-delta`, `build-url-ts`). Two are always needed; the other three
  depend on features the generator cannot detect, and an unused entry is
  harmless.
- **`add-bootstrap-table` shrinks** to the three dependencies
  (`bootstrap-table`, `jquery`, `jquery-treegrid`) and an optional example
  component. The extension list is dropped because the library loads its
  extensions itself.
- **Angular library scaffolding lives here** as `create-library`: it needs
  `@nx/angular` and Angular peer-dependency knowledge (the rule in
  [design.md](design.md#design-decision)). Storybook and Compodoc stay flags
  on it.
- **`create-library` writes the project's publishable settings itself** (owner
  decision, 2026-10-17). It was to compose `nx-plugin:create-publishable-lib`,
  retired with F11.2 because kiln owns repository-level setup
  ([epic](index.md)). The settings it writes (the `publishable` tag, package
  metadata, `manifestRootsToUpdate`, `pack`, `verify-dist`,
  `nx-release-publish`) belong to the project, not the repository: they are
  the
  [declarations](../../../architecture/release-pipeline.md#what-a-repository-declares)
  the CI template (retired by E17) left to the repository, and kiln at most
  seeds them once and then leaves them to the repository (kiln F9.1). The
  steps are the
  [publishable-library guide](../../../guides/development.md#adding-a-publishable-library)'s.

### Considered and rejected

- **Keeping script and asset patching in `setup`.** The library already loads
  them; patching would double-load them.
- **An `--linkLocal` alias option.** Nothing needs aliases for tarball-installed
  packages; add it when a local-linking workflow exists.
- **Dropping `add-bootstrap-table`.** Kept for the dependency and example
  wiring, which `setup` includes by default.
- **Deferring `create-library` until kiln generates library projects.** kiln's
  planned package generator covers Python workspaces only (kiln E10, F11.3);
  the guide's steps are already manual work this generator removes.

The package declares `exports` for `.`, `./package.json` and
`./generators.json`: kiln's `dist-verify` requires an `exports` map (or `module`
and `typings`) in the dist manifest (S11.1.1). Its peers (`@nx/angular`,
`@nx/devkit`, `typescript`) are also its `devDependencies`, with the same ranges
(S11.1.8).

Built with `@nx/js:tsc`. Prefer `module: node16` / `moduleResolution: node16`
unless the repo standard changes. Generator template files are non-TS assets:
whether the package then needs `patch-package-exports` is checked when the
package is created
([publishable-library guide](../../../guides/development.md#adding-a-publishable-library),
item 5).

### `setup`

Configures an existing Angular app to consume `@rn-forge/ng` and
`@rn-forge/ng-bootstrap`.

It belongs in `ng-plugin` because it understands Angular app structure and
rn-forge Angular runtime packages.

#### Usage

```bash
pnpm nx g @rn-forge/ng-plugin:setup --project=my-app
```

#### Schema

| Option | Type | Required | Default | Description |
| -- | -- | -- | -- | -- |
| `project` | string | yes | — | Angular app project to configure |
| `packageManager` | enum | no | `pnpm` | `pnpm \| npm \| yarn` |
| `skipInstall` | boolean | no | `false` | Skip dependency installation |
| `skipStyles` | boolean | no | `false` | Skip app stylesheet injection |
| `skipConfig` | boolean | no | `false` | Skip `allowedCommonJsDependencies`, the `@angular/localize/init` polyfill and the `app.config.ts` provider |
| `includeBootstrapTable` | boolean | no | `true` | Add the Bootstrap Table dependencies during setup |
| `includeTheme` | boolean | no | `true` | Include rn-forge theme/style wiring during setup |

#### Steps

1. Validate that `project` exists and is an Angular application.
1. Add `@rn-forge/ng` and `@rn-forge/ng-bootstrap` at the plugin's own version
   (the three share one release version), plus the peer dependencies
   `ng-bootstrap` declares.
1. Inject `@use '@rn-forge/ng-bootstrap/assets/theme';` between the
   `rn-forge:start` and `rn-forge:end` markers in the app stylesheet (the
   `configure-theme` helper). When the stylesheet already imports that module
   outside the markers, change nothing.
1. Merge the five CommonJS entries into the build target's
   `options.allowedCommonJsDependencies`, keeping existing entries, sorted and
   without duplicates.
1. Add `@angular/localize/init` to the build target's `options.polyfills`,
   keeping existing entries, once.
1. Add `provideRnForgeBootstrapConfig({})` and its import to the providers in
   `app.config.ts`.
1. Add the Bootstrap Table dependencies through the same helper as
   `:add-bootstrap-table`.
1. Format files.
1. Run package installation unless `skipInstall` is true.

### `create-library`

Scaffolds a publishable Angular library.

#### Usage

```bash
pnpm nx g @rn-forge/ng-plugin:create-library --name=my-ui --importPath=@acme/my-ui
```

#### Schema

| Option | Type | Required | Default | Description |
| -- | -- | -- | -- | -- |
| `name` | string | yes | — | Library project name |
| `importPath` | string | yes | — | npm package name |
| `directory` | string | no | `libs/` | Library directory |
| `secondaryEntryPoints` | string | no | — | Comma-separated entry point names |
| `storybook` | boolean | no | `false` | Declare `build-storybook` writing `dist/storybook/{projectName}` |
| `compodoc` | boolean | no | `false` | Declare `compodoc` writing `dist/compodoc/{projectName}` |
| `coverageThreshold` | number | no | `35` | Vitest coverage threshold for all metrics |
| `skipInstall` | boolean | no | `false` | Skip dependency installation |

#### Steps

1. Validate that the project name is free.
1. Run `@nx/angular:library` with publishable, standalone, strict, SCSS and
   Vitest Angular options.
1. Scaffold secondary entry points if requested.
1. Move `@angular/*` packages to `peerDependencies`, and list each peer in
   `devDependencies` with the same range (S11.1.8).
1. Apply the
   [publishable-library guide](../../../guides/development.md#adding-a-publishable-library)'s
   settings: the `publishable` tag, package metadata,
   `release.version.manifestRootsToUpdate`, and the `pack`, `verify-dist` and
   `nx-release-publish` (`dryRun: true`) targets. `nx.json#release.projects`
   is not edited.
1. Apply library defaults: eslint baseline, Vitest target, `tsconfig.spec.json`
   include/exclude.
1. Add the Storybook and Compodoc targets when requested, with the target names
   and output paths above, so the docs site finds them.
1. Format files; install unless skipped.

| `reporters` | string | no | `text,html,json` | Coverage reporters |

#### Steps

1. Patch project test target.

1. Add coverage thresholds.
1. Format files.

## Design defaults

These defaults stand until a story's work shows a reason to change them.

| Topic | Default |
| -- | -- |
| Build target detection | Standard Nx Angular executors only |
| Stylesheet location | Read build target `styles[]`; fallback to `src/styles.scss` |
| SSR | Not supported initially; detect and warn only |
| Example scaffold | Standalone component only |
| Theme presets | `default` only; marker region patching; SCSS only |
| Component templates | `component`, `page`, `table`, `form`; `page` does not update routes |
| Public API export | App projects reject `--export`; story generation is skipped with a warning when Storybook is absent |
| Component prefix | Workspace/project prefix, fallback `rnf` |
| Testing | Same thresholds for apps and libraries; keep `35`; Vitest Angular only |

## S11.1.1 — `@rn-forge/ng-plugin:setup`

**State:** Closed (2026-11-17)

**Acceptance:**

```gherkin
Feature: ng-plugin:setup generator

  Background:
    Given an Nx Angular workspace
    And an Angular app "my-app" exists

  Scenario: full setup
    When I run "pnpm nx g @rn-forge/ng-plugin:setup --project=my-app"
    Then package.json contains @rn-forge/ng and @rn-forge/ng-bootstrap and their peer dependencies
    And the app stylesheet contains "@use '@rn-forge/ng-bootstrap/assets/theme';" between the rn-forge markers
    And the build target options list "allowedCommonJsDependencies" with bootstrap/dist/js/bootstrap.bundle.js, jquery, jquery-treegrid, quill-delta and build-url-ts
    And app.config.ts provides provideRnForgeBootstrapConfig({})
    And the build target options list "polyfills" with @angular/localize/init
    And the build target gains no scripts or assets entries and no other polyfills
    And "pnpm nx build my-app" succeeds without CommonJS warnings

  Scenario: idempotent
    Given ng-plugin:setup has already been run on "my-app"
    When I run the generator again
    Then no files are changed

  Scenario: non-Angular project rejected
    When I run "pnpm nx g @rn-forge/ng-plugin:setup --project=my-lib"
    Then the generator exits with an error containing "Angular application"

  Scenario: skipInstall
    When I run "pnpm nx g @rn-forge/ng-plugin:setup --project=my-app --skipInstall"
    Then package.json is updated but install is not executed

  Scenario: skipStyles
    When I run "pnpm nx g @rn-forge/ng-plugin:setup --project=my-app --skipStyles"
    Then the app stylesheet is not modified

  Scenario: existing unmarked theme import
    Given the app stylesheet already contains "@use '@rn-forge/ng-bootstrap/assets/theme';" outside the markers
    When I run the generator
    Then the stylesheet is not changed and the module is imported once

  Scenario: existing config preserved
    Given the build target already lists other allowedCommonJsDependencies
    When I run the generator
    Then those entries remain and the five rn-forge entries are added once
```

The tests run each scenario in a temporary Nx workspace tree
(`createTreeWithEmptyWorkspace`) inside this repository. The Angular app fixture
for `build` is the demo app's configuration.

Part of this story's done state: once `setup` exists,
`libs/ng-bootstrap/README.md` replaces its "will be added automatically by a
scaffolding generator" note with a pointer to `@rn-forge/ng-plugin:setup`.

Outcome: 15 generator specs pass; the demo app's configuration is unchanged by
`setup`, and its build reports no CommonJS warnings.

## Acceptance

The tests run in temporary Nx workspace trees inside this repository.

```bash
set -euo pipefail
pnpm exec nx test ng-plugin                 # S11.1.1–S11.1.5, S11.1.7: generator specs
pnpm exec nx build ng-plugin
test "$(pnpm exec nx show project ng-plugin --json | jq -r '.tags | index("publishable") != null')" = true   # fixed group
```
