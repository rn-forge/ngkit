# F5.2 — `@rn-forge/ng/auth` session client

**Status:** elaborating · **Owner:** ngkit · **Epic:** [E5](index.md) · **Release:** [Release 2](../../../releases/release-2/index.md)

**Depends on:** [S5.1.2](F5.1-client-model.md#s512--settle-the-wire-contract).

The session client in `@rn-forge/ng/auth`, built on Angular's `HttpClient`, router and XSRF support, with no new dependency ([ADR-0001](../../../adr/ADR-0001.md), [ADR-0002](../../../adr/ADR-0002.md)). It implements [Design](design.md) and is tested against it with `HttpTestingController`; the demo's mock interceptor serves the auth routes until [F5.4](F5.4-auth-acceptance.md).

## Stories

### S5.2.1 — Configuration and session bootstrap

**Status:** planned

**Acceptance:**

- `provideRnForgeAuth(config)` takes a readonly typed config (`sessionUrl`, `providersUrl`, `loginUrl`, `logoutUrl`, `passwordLoginUrl`, `loginPath`, `errorPath`, `forbiddenPath`, `loggedOutPath`, XSRF cookie and header names, loop-guard window, expiry lead time) with Design's defaults, and sets `withXsrfConfiguration`. An invalid config fails with `[rn-forge.ng.auth]`.
- On startup, `200` from `/auth/session` sets `RNF_CREDENTIALS` from the session body, and `401` sets anonymous credentials, with no navigation.
- `RNF_PERMISSION` answers `hasPermission`/`hasAnyPermission` from the session's `permissions`; credentials expose `roles` for display and offer no scope check.
- `provideRnForgeAuthConfig`, `RnForgeAuthConfig`, `RN_FORGE_AUTH_CONFIG_TOKEN`, `LoginResponse`, `UserProfile`, `JwtCredentials`, `JwtToken`, the `refreshToken` hook, `disableAuth` and the `jwt-decode` dependency are gone, and no auth code calls `localStorage`.

### S5.2.2 — Login and logout

**Status:** planned

**Acceptance:**

- `login(provider, returnTo)` navigates with `window.location.assign` to the login URL with a relative `return_to`; an absolute `returnTo` is rejected with `[rn-forge.ng.auth]`.
- `loginWithPassword(username, password)` posts with the XSRF header and, on `200`, sets credentials from the returned body without a reload; `401` surfaces as a typed failure.
- `providers()` returns the `/auth/providers` list, skipping and logging unknown kinds.
- `logout()` posts, clears credentials, then follows `redirect` by full-page navigation or routes to `loggedOutPath` when it is `null`.

### S5.2.3 — Error policy

**Status:** planned

**Acceptance:** unit tests show, using the RxJS error channel:

- a `401` from `/auth/session` never navigates;
- a `401` from another request clears credentials and starts a login (or the login page, with several providers) with the current URL as `return_to`;
- a `401` inside the loop-guard window after a login returns goes to `errorPath?error=session_not_established`, and no second login starts;
- a `403` refetches the session once, even for parallel `403`s, then goes to `forbiddenPath`, and never clears credentials or starts a login;
- no request carries an `Authorization` header.

### S5.2.4 — Guards, refresh and expiry

**Status:** planned

**Acceptance:**

- A functional `authGuard` sends an anonymous user to a login as Design's table says; `permissionGuard(...keys)` sends a signed-in user without the keys to `forbiddenPath`. `authRouteGuard` and `ignoreAppRoutes` are gone.
- The session is refetched when the window regains focus.
- An `expiryWarning` signal turns true the configured lead time before `expiresAt` and false after a fresh session; nothing polls the backend.

### S5.2.5 — Testing provider

**Status:** planned

**Acceptance:**

- A `@rn-forge/ng/auth/testing` entry point exports `provideRnForgeAuthTesting(session)`, which seeds credentials and permissions with no HTTP call.
- The `ng-demo` production bundle contains no code from the testing entry point.

## Acceptance

- Each story's acceptance holds (S5.2.1–S5.2.5).
- `pnpm nx run-many -t lint test build --projects=ng,ng-bootstrap,ng-demo` and `pnpm nx run ng:verify-consumer` pass.
- The `@rn-forge/ng/auth` README documents the configuration, the error policy and the testing provider, and names the breaking changes.
