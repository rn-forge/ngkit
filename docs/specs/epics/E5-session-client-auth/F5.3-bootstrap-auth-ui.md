# F5.3 — Bootstrap auth UI

**Status:** elaborating · **Owner:** ngkit · **Epic:** [E5](index.md) · **Release:** [Release 3](../../../releases/release-3/index.md)

**Depends on:** [F5.2](F5.2-auth-wrapper.md).

`@rn-forge/ng-bootstrap/auth` renders the session client's states. The identity provider owns its own login screen; ngkit's login page only chooses a provider, or takes a local password when the backend offers one. User, group and permission administration are [E4](../E4-standard-resource-screen/index.md) resource screens, or the identity provider's admin.

## Stories

### S5.3.1 — Login page

**Status:** planned

**Acceptance:**

- The login page lists the providers from `/auth/providers` and starts the chosen login with the `returnTo` it was given.
- A `password` provider shows a username and password form that signs in through `loginWithPassword` and then routes to `returnTo`; a failure shows a message that does not say whether the account exists.
- With exactly one provider of a navigating kind, the page starts its login without showing the list.
- The current `AuthComponent` login and logout modes are gone.

### S5.3.2 — Auth error and forbidden pages

**Status:** planned

**Acceptance:**

- The error page shows a message for each code in Design's [error route codes](design.md#error-route-codes), a generic one for any other value, and a link back to the login page.
- The forbidden page says the user is signed in but not allowed, and never offers to sign in again.

### S5.3.3 — User menu and expiry warning

**Status:** planned

**Acceptance:**

- A user menu shows the session's `name` (falling back to `subject`), `email`, `picture` and provider, and signs out through `logout()`.
- While `expiryWarning` is true, a dismissible notice offers a fresh login that returns to the current URL.
- `UserComponent`'s profile and settings views read from the session body or are removed; nothing reads `UserProfile`.

## Acceptance

- Each story's acceptance holds (S5.3.1–S5.3.3), with component tests seeded through `provideRnForgeAuthTesting`.
- `ng-demo` routes its login, error and forbidden pages to these components.
- `pnpm nx run-many -t lint test build --projects=ng-bootstrap,ng-demo` passes.
