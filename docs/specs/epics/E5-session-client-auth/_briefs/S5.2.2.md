# S5.2.2 — Login and logout

Brief for [S5.2.2](../F5.2-auth-wrapper.md#s522-login-and-logout), at `f8aaf74`.

## Goal

Add login by full-page navigation, local password login, the provider list, and
logout to `AuthService`, following [Design](../design.md). Then put the
`ng-demo` Logout menu item back.

## Settled

- **The wire contract** is [Design](../design.md) (S5.1.2, 2026-11-14): the
  routes table, the provider kinds, and the Logout row of the Client behaviour
  table.

- **Consumers are migrated minimally (owner, 2026-11-15).** The real login page
  is F5.3. This story touches `ng-demo` only to put Logout back and to mock
  the new routes.

- **Public surface** (reviewer). This is the contract, added to
  `libs/ng/auth/src/lib/auth.types.ts` and `auth.services.ts`:

    ```ts
    export type AuthProviderKind = 'oidc' | 'oauth2' | 'development' | 'password';
    export interface AuthProvider {
      readonly id: string;
      readonly name: string;
      readonly kind: AuthProviderKind;
    }
    export type PasswordLoginFailure = 'invalid-credentials' | 'rate-limited';
    export class PasswordLoginError extends Error {
      constructor(readonly reason: PasswordLoginFailure); // message starts '[rn-forge.ng.auth]'
    }

    // AuthService gains:
    login(provider: string, returnTo: string): void;
    loginWithPassword(username: string, password: string): Observable<Credentials>;
    providers(): Observable<readonly AuthProvider[]>;
    logout(): Observable<void>;
    ```

- **`login(provider, returnTo)`:**

    - `returnTo` is relative when it starts with `/` and its second character is
      neither `/` nor `\`. Anything else throws
      `Error('[rn-forge.ng.auth] returnTo must be a relative path …')`
      synchronously, and nothing navigates.
    - It writes `Date.now()` to `sessionStorage` under the key
      `rnf.auth.loginStartedAt` (the loop-guard record Design describes; S5.2.3
      reads it). Then it calls the full-page navigation with
      `` `${loginUrl}/${encodeURIComponent(provider)}?return_to=${encodeURIComponent(returnTo)}` ``.
    - It never uses `HttpClient`.

- **Full-page navigation is injectable**, so tests can see it. Add an internal
  `FullPageNavigation` service (`@Injectable({ providedIn: 'root' })`) with
  `assign(url: string): void`, which calls
  `inject(DOCUMENT).defaultView?.location.assign(url)`. Put it in
  `auth.navigation.ts`. It is **not** exported from `src/index.ts`; tests
  import it from its file and override it with
  `{ provide: FullPageNavigation, useValue: { assign: vi.fn() } }`.

- **`loginWithPassword`** posts `{ username, password }` to `passwordLoginUrl`.
  Angular's XSRF interceptor adds the header to a relative `POST`; nothing
  adds it by hand.

    - `200`: the body is a `Session`. Set `SessionCredentials`, emit them, and do
      not navigate or reload.
    - `401` errors with `PasswordLoginError('invalid-credentials')`.
    - `429` errors with `PasswordLoginError('rate-limited')`.
    - Any other error passes through as the `HttpErrorResponse`, and credentials
      stay unchanged.

- **`providers()`** issues `GET providersUrl`. It keeps each entry whose `kind`
  is one of the four, and drops every other entry with one
  `console.warn('[rn-forge.ng.auth] unknown provider kind …')` per skipped
  entry.

- **`logout()`** posts `{}` to `logoutUrl`.

    - `200 { redirect }` or a `401`: set `AnonymousCredentials`. Then, when
      `redirect` is a string, call `FullPageNavigation.assign(redirect)`;
      otherwise (`null`, or a `401`) call `Router.navigateByUrl(loggedOutPath)`.
      Complete without emitting a value.
    - Any other error passes through, and credentials stay unchanged.

- **The demo mock** keeps its session in memory: a module-level `signedIn` flag,
  `true` at load. `resetMockApi()` resets it to `true`.

    - `GET …/auth/session` returns the S5.2.1 session while `signedIn` is true,
      and a `401` problem otherwise.
    - `POST …/auth/logout` sets `signedIn = false` and returns
      `200 { redirect: null }`.
    - `GET …/auth/providers` returns
      `[{ id: 'development', name: 'Development', kind: 'development' }]`.

    Signing back in in the demo is a page reload until F5.3 and F5.4.

## Current behaviour

At `f8aaf74`:

- `libs/ng/auth/src/lib/auth.services.ts:16-39`: `AuthService` has only
  `credentials` and `refresh()`. It has no `login`, `loginWithPassword`,
  `providers` or `logout`, so tests calling them fail to compile.
- `auth.types.ts` has no `AuthProvider`, `AuthProviderKind` or
  `PasswordLoginError`.
- `auth.config.ts` already defines `loginUrl`, `passwordLoginUrl`,
  `providersUrl`, `logoutUrl` and `loggedOutPath`, with Design's defaults.
- `apps/ng-demo/src/app/app.ts:~80`: the User submenu has Profile and Settings,
  and no Logout.
- `apps/ng-demo/src/app/shared/mock-api.interceptor.ts:210`: the mock always
  answers `GET …/auth/session` with `200`, and does not mock `/auth/logout` or
  `/auth/providers`.
- `libs/ng/auth/src/lib/auth.source.spec.ts` forbids the strings `localStorage`,
  `jwt-decode` and `Authorization` anywhere under `libs/ng/auth/src`, comments
  included. `sessionStorage` is allowed.

      `PasswordLoginFailure`, `PasswordLoginError`, each with a one-line doc
      comment.
    - `auth.navigation.ts` (new, internal): `FullPageNavigation`.

## Tests first

Write these first, in `libs/ng/auth/src/lib/auth.services.spec.ts`, using
`provideRnForgeAuth()`, `HttpTestingController`, a `FullPageNavigation` stub and
a `Router.navigateByUrl` spy. Flush the startup `GET /auth/session` with a `401`
first. Each fails to compile before the change, because the methods and types
are missing.

1. `login('workspace', '/orders?page=2')`:
    - calls `assign` with `/auth/login/workspace?return_to=%2Forders%3Fpage%3D2`;
    - stores a numeric `rnf.auth.loginStartedAt` in `sessionStorage`;
    - issues no HTTP request (`httpMock.verify()`).
1. `login` with `https://evil.example/x`, `//evil.example` or `/\evil` throws
   `/^\[rn-forge\.ng\.auth\]/`, and calls neither `assign` nor
   `sessionStorage`.
1. `loginWithPassword('ada', 'pw')`:
    - `POST /auth/login/password` with body `{ username: 'ada', password: 'pw' }`
      and, after `document.cookie = 'XSRF-TOKEN=t1'`, header
      `X-XSRF-TOKEN: t1`;
    - `200` with a session sets `credentials().isAuthenticated` true, and calls
      neither `assign` nor `navigateByUrl`.
1. `loginWithPassword`:
    - `401` errors with `PasswordLoginError` and reason `invalid-credentials`;
    - `429` errors with reason `rate-limited`;
    - `500` errors with an `HttpErrorResponse` of status 500;
    - credentials stay anonymous in all three cases.
1. `providers()` with entries of kinds `oidc`, `password` and `saml` emits the
   first two, and calls `console.warn` once, with the prefix.
1. `logout()` from a signed-in state:
    - `200 { redirect: 'https://idp.example/logout' }` leaves credentials
      anonymous and calls `assign` with that URL;
    - `200 { redirect: null }` calls `navigateByUrl('/login')`;
    - a `401` also calls `navigateByUrl('/login')` and leaves credentials
      anonymous;
    - a `500` errors and leaves credentials signed in.
