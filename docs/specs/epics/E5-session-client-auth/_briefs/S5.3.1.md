# S5.3.1 — Login page

Brief for [S5.3.1](../F5.3-bootstrap-auth-ui.md#s531-login-page), at `c3c2769`.

## Goal

Replace the interim `AuthComponent` in `@rn-forge/ng-bootstrap/auth` with a
`LoginComponent`. It chooses a provider from `/auth/providers`, or takes a local
password, and returns to `returnTo`. Route `ng-demo`'s `/login` to it.

## Settled

- **Contract:**
    - [Design](../design.md) (S5.1.2, 2026-11-14): the provider kinds table and
      the client routes. `loginPath` is `/login`, with `?returnTo=<path>`.
    - F5.2 (closed 2026-11-15). `AuthService` provides `providers()`,
      `login(id, returnTo)` (it throws on a non-relative `returnTo`),
      `loginWithPassword(u, p)` (errors with `PasswordLoginError`, whose
      `reason` is `invalid-credentials` or `rate-limited`) and `credentials`.
    - `@rn-forge/ng/auth/testing` provides `provideRnForgeAuthTesting(session)`
      and a `FakeAuthService` with `setProviders`, `setSession` and `logins`.
- **Component** (reviewer). `LoginComponent`, selector `rnf-login`, in
  `libs/ng-bootstrap/auth/src/lib/login/`. It extends `AbstractAuthPage`, with
  `configKey = 'login'` and options `ConfigOptions`. It replaces
  `AuthComponent`: delete `auth/auth.component.*` and its `AuthOptions`
  export.
- **`returnTo`** is the `returnTo` query param when it is a relative path: it
  starts with `/`, and its second character is neither `/` nor `\`. Otherwise
  it is `/`.
- **Behaviour on init:**
    1. If signed in, `navigateByUrl(returnTo)` and stop.
    1. Otherwise call `providers()`. **Navigating kinds** are `oidc`, `oauth2` and
       `development`.
        - If there is exactly one navigating provider and no `password` provider,
          call `login(id, returnTo)` at once, and render no provider list.
        - Otherwise render one button per navigating provider, labelled with its
          `name`, each calling `login(id, returnTo)`. When a `password` provider
          is present, also render the password form.
        - If `providers()` errors, show the unavailable message.
- **Password form:**
    - Angular reactive forms (`ReactiveFormsModule`, already a peer). It has
      `username` (`type="text"`, `autocomplete="username"`) and `password`
      (`type="password"`, `autocomplete="current-password"`), both required,
      with Bootstrap `form-control` classes. `ng-bootstrap/form` has no password
      field, and this story does not add one.
    - Submit calls `loginWithPassword` and disables the button while the call is
      pending. On success it calls `navigateByUrl(returnTo)`.
- **Messages,** shown in a Bootstrap `alert alert-danger` with `role="alert"`:
    - `invalid-credentials`: "Sign-in failed. Check your username and password."
      This must not say whether the account exists;
    - `rate-limited`: "Too many sign-in attempts. Try again later.";
    - any other error, or `providers()` failing: "Sign-in is unavailable right
      now. Try again later."
- **Demo mock.** `GET …/auth/providers` returns only
  `[{ id: 'password', name: 'Password', kind: 'password' }]`. A navigating
  provider would leave the mock-backed demo for a backend route it does not
  have. `POST …/auth/login/password` with password `demo` sets
  `signedIn = true` and returns the demo session. Any other password returns a
  `401` problem. The demo's `/login` route uses `LoginComponent`.

## Tests first

Write these first, in `login.component.spec.ts`. Use
`provideRnForgeAuthTesting(null)` (or a session), `provideRouter([])` with a spy
on `Router.navigateByUrl`, and `inject(FakeAuthService)` to set providers and
spy on methods. Set `queryParams` through the router: navigate the test harness
to `/login?returnTo=/orders`, or stub `RouteService` as the existing specs do.
Each test fails before the change, because the module does not exist.

1. Signed in, with `returnTo=/orders`: `navigateByUrl('/orders')`, and
   `providers()` is not called.
1. Providers `oidc` "Workspace" and `development` "Dev": two buttons with those
   labels. Clicking "Workspace" records
   `{ provider: 'oidc-id', returnTo: '/orders' }` in `logins`.
1. A single `oidc` provider: `logins` has one entry at init, and no button is
   rendered.
1. A single `oidc` plus a `password` provider: one button and the form, and no
   automatic login.
1. A `password` provider only: the form renders, and submitting `ada`/`pw` calls
   `loginWithPassword('ada', 'pw')`. On success, `navigateByUrl('/orders')`.
1. `loginWithPassword` erroring with
   `new PasswordLoginError('invalid-credentials')` shows exactly the
   invalid-credentials message. The rendered text contains neither "exist" nor
   "not found".
1. `rate-limited` shows the rate-limited message, and an `HttpErrorResponse`
   with status 500 shows the unavailable message.
1. `providers()` erroring shows the unavailable message.
1. `returnTo=https://evil.example` falls back to `/`: clicking a provider
   records `returnTo: '/'`.
