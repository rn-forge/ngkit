# S5.2.4 — Guards, refresh and expiry

Brief for [S5.2.4](../F5.2-auth-wrapper.md#s524-guards-refresh-and-expiry), at
`7002d1b`.

## Goal

Replace the interim `authRouteGuard` with `authGuard` and
`permissionGuard(...keys)`. Refetch the session when the window regains focus,
and add an `expiryWarning` signal. All three follow [Design](../design.md).

## Settled

- **The wire contract** is [Design](../design.md) (S5.1.2, 2026-11-14): the rows
  of its Client behaviour table for an anonymous user on a guarded route,
  window focus, and `expiresAt` approaching.

- **Consumers are migrated minimally (owner, 2026-11-15).**

- **Public surface** (reviewer). This is the contract:

    ```ts
    // auth.guards.ts
    export const authGuard: CanActivateFn & CanActivateChildFn;
    export function permissionGuard(...keys: string[]): CanActivateFn & CanActivateChildFn;
    // AuthService gains:
    readonly expiryWarning: Signal<boolean>;
    ```

    `authRouteGuard` is deleted.

- **`authGuard`.** When signed in, it returns `true`. When anonymous, it calls
  `AuthService.startLogin(state.url)` and returns `false`. `startLogin`
  already applies Design's rule: one navigating provider starts its login,
  otherwise the login page opens with `returnTo`.

- **`permissionGuard(...keys)`.**

    - When anonymous, it behaves exactly like `authGuard`.
    - When signed in and holding **every** key (`hasPermission` for each), it
      returns `true`.
    - Otherwise it returns `router.createUrlTree([forbiddenPath])`.
    - Calling it with no keys throws `[rn-forge.ng.auth]` when the route table is
      built, i.e. at the `permissionGuard()` call itself.

- **Focus refetch.**

    - `provideRnForgeAuth`'s app initializer adds a `focus` listener on
      `inject(DOCUMENT).defaultView`. It removes the listener through
      `inject(DestroyRef).onDestroy`.
    - Each focus event calls `refresh()`, unless a focus refresh is already in
      flight, in which case the event is ignored.
    - A non-401 error from a focus refresh is logged once with
      `console.error('[rn-forge.ng.auth] …')` and leaves credentials unchanged.
    - Nothing refetches on an interval.

- **`expiryWarning`.**

    - It is a readonly signal on `AuthService`, recomputed whenever the service
      sets credentials (startup, `refresh`, `loginWithPassword`, `logout`,
      `clear`). Each recompute first clears any pending timer.
    - **Anonymous credentials:** `false`.
    - **A session:** with
      `due = Date.parse(expiresAt) - expiryLeadMs - Date.now()`, the signal
      becomes `true` at once when `due <= 0`. Otherwise it is `false`, and a
      `setTimeout` sets it `true` after `due`.
    - `setTimeout` overflows above `2_147_483_647` ms (about 24.8 days) and would
      fire at once. A larger `due` therefore schedules a recompute after
      `2_147_483_647` ms instead.
    - A fresh session with a later `expiresAt` sets the signal back to `false`.
    - Nothing polls the backend to keep the session alive.

- **Demo routes.** The parent route takes `canActivateChild: [authGuard]`. Each
  child that has `data.permission` today takes
  `canActivate: [permissionGuard('<that key>')]` instead, and
  `data.permission` is removed. The `user/*`, redirect and `**` routes keep
  only the parent guard.

## Current behaviour

At `7002d1b`:

- `libs/ng/auth/src/lib/auth.guards.ts:13-27`: `authRouteGuard` returns a
  `UrlTree` to `loginPath?returnTo=` for an anonymous user, without calling
  `startLogin`. For a signed-in user without `route.data.permission` it
  returns `false`, not the forbidden page. `authGuard` and `permissionGuard`
  do not exist, so tests importing them fail to compile.
- `auth.services.ts`:
    - `startLogin`, `clear`, `refresh`, `loginWithPassword` and `logout` set
      credentials through the private `currentCredentials` signal;
    - there is no `expiryWarning`.
- `auth.providers.ts:~88-100`: the app initializer injects `AuthErrorPolicy` and
  awaits `refresh()`. There is no focus listener.
- `apps/ng-demo/src/app/app.routes.ts:33-55`: the parent route uses
  `canActivateChild: [authRouteGuard]`, and the children use
  `data.permission`.
- Docs naming `authRouteGuard` or `route.data.permission`:
    - `libs/ng/auth/README.md:65`;
    - `docs/guides/building-an-app.md:228`, `:240`, `:313` and `:535`.
- `auth.source.spec.ts` fails if any file under `libs/ng/auth/src` contains
  `localStorage`, `jwt-decode` or `Authorization`, comments included.

## Change

- **Change:**
    - `libs/ng/auth/src/lib/auth.guards.ts`: `authGuard` and `permissionGuard`.
      Delete `authRouteGuard`.
    - `auth.services.ts`: `expiryWarning`. Route every credentials update through
      one private setter that recomputes it.
    - `auth.providers.ts`: the focus listener.
    - Specs: `auth.guards.spec.ts` (rewritten), `auth.services.spec.ts`, and
      `auth.providers.spec.ts` or `auth.integration.spec.ts` for focus.
    - `apps/ng-demo/src/app/app.routes.ts`: the routes above.
    - Docs: README and building-an-app guide. Replace `authRouteGuard` and
      `data.permission` with `authGuard` and `permissionGuard`. Document focus
      refetch and `expiryWarning` in the README.
- **Leave alone:** `auth.interceptors.ts`, `auth.config.ts`,
  `auth.directives.ts`, `auth.mixins.ts`, all of `libs/ng-bootstrap` (the
  expiry notice is F5.3), the navbar's `item.permission`, spec pages other
  than this brief, and kiln-generated files.

## Tests first

Write these first. Each fails before the change: either it does not compile (the
missing symbols), or its assertion fails.

1. In `auth.guards.spec.ts`, using `TestBed.runInInjectionContext` and a stubbed
   `AuthService.startLogin`:
    - an anonymous user on `authGuard` gets `false`, and `startLogin` is called
      with `state.url`;
    - a signed-in user gets `true`;
    - `permissionGuard('a.read', 'a.update')`:
        - a user with both keys gets `true`;
        - a user with one key gets a `UrlTree` serializing to `/forbidden`;
        - an anonymous user gets `false`, and `startLogin` is called;
    - `permissionGuard()` with no keys throws `/^\[rn-forge\.ng\.auth\]/`.
1. In `auth.services.spec.ts`, with `vi.useFakeTimers()` and a fixed
   `Date.now()`:
    - a session expiring in 10 min with the default 5 min lead: `expiryWarning()`
      is `false`, then `true` after advancing 5 min;
    - a session expiring in 2 min is `true` at once;
    - after it turns `true`, a `refresh()` returning a session expiring in 1 h
      sets it back to `false`;
    - `logout()` sets it `false`;
    - a session expiring in 2099 stays `false` after advancing 25 days, with no
      overflow firing.
    - Use `vi.getTimerCount()`, or flush the HTTP mock, to show no request is
      made by the timer.
1. Focus refetch, with `provideRnForgeAuth()`:
    - after startup, `window.dispatchEvent(new Event('focus'))` issues one
      `GET /auth/session`;
    - two focus events before it is flushed issue one request;
    - a `500` on that request logs once with the prefix and keeps the signed-in
      credentials;
    - advancing timers by 1 h issues no request.
