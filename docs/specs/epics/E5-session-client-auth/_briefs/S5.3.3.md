# S5.3.3 — User menu and expiry warning

Brief for
[S5.3.3](../F5.3-bootstrap-auth-ui.md#s533-user-menu-and-expiry-warning), at
`63431ab`.

## Goal

Add a user menu and a session-expiry notice to `@rn-forge/ng-bootstrap/auth`,
and use both in `ng-demo`. The user profile view reads only the session body.

## Settled

- **Contract:**
    - [Design](../design.md) (S5.1.2, 2026-11-14): the session body, where `name`,
      `email` and `picture` may be absent and `subject` is always present, and
      the "`expiresAt` approaching" row of the Client behaviour table;
    - F5.2 (closed 2026-11-15): `AuthService.expiryWarning`, `logout()`,
      `startLogin(returnTo)` and `credentials`;
    - `@rn-forge/ng/auth/testing`: `provideRnForgeAuthTesting(session)` and a
      `FakeAuthService` with `setSession` and `setExpiryWarning`.
- **`UserMenuComponent`** (reviewer): selector `rnf-user-menu`, in
  `libs/ng-bootstrap/auth/src/lib/user-menu/`, standalone, not a page.
    - It renders nothing while anonymous.
    - Signed in, it renders a Bootstrap dropdown, marked up like the navbar's
      submenu at `libs/ng-bootstrap/shell/src/lib/navbar/navbar.html:47-64`: a
      `button.btn.dropdown-toggle` with `data-bs-toggle="dropdown"` and
      `aria-expanded="false"`, then a `ul.dropdown-menu.dropdown-menu-end`.
    - The toggle shows the `picture` as a 24px rounded `img`, with `alt=""` and
      only when `picture` is present, followed by the display name. The display
      name is `name`, or `subject` when `name` is absent.
    - The menu has:
        - a non-interactive header with the display name, the `email` when present,
          and "Signed in with <provider>";
        - a divider;
        - optional `routerLink` items for its inputs `profileUrl` and `settingsUrl`,
          each `string | undefined` and each rendered only when set, labelled
          "Profile" and "Settings";
        - a "Sign out" `button.dropdown-item` that calls
          `AuthService.logout().subscribe()`.
- **`SessionExpiryNoticeComponent`** (reviewer): selector
  `rnf-session-expiry-notice`, in
  `libs/ng-bootstrap/auth/src/lib/expiry-notice/`.
    - While `expiryWarning()` is true and the notice is not dismissed, it renders
      `div.alert.alert-warning.alert-dismissible` with `role="alert"`. Inside
      are the text "Your session ends soon.", a `button` "Sign in again" that
      calls `AuthService.startLogin(router.url)`, and a `btn-close` button with
      `aria-label="Dismiss"`.
    - Dismissing hides it. The dismissed flag resets when `expiryWarning()`
      becomes false, so the next session warns again.
    - It uses no Bootstrap JS.
- **Both components** inject `AuthService` and `RNF_CREDENTIALS`, and nothing
  else from `@rn-forge/ng/auth`. Export both from the entry point.
- **Profile and settings.** `UserComponent` and `UserProfileComponent` already
  read `Session` (since S5.2.1). Add a "Picture" row to the profile's default
  rows (`picture`) and keep the rest. `UserSettingsComponent` reads no
  identity and stays unchanged. Nothing under `libs/` names a `UserProfile`
  *type*; the component and options names `UserProfileComponent` and
  `UserProfileOptions` stay.
- **Demo (`apps/ng-demo/src/app/app.ts` and `app.html`):**
    - remove the navbar "User" submenu, which holds Profile, Settings and Logout,
      together with the `DIVIDER` before it and the `AuthService` field if
      unused;
    - in `app.html`, between `<rnf-header>` and `<main>`, add a
      `div.d-flex.justify-content-end.px-3.py-2` containing
      `<rnf-user-menu profileUrl="/user/profile" settingsUrl="/user/settings" />`;
    - add `<rnf-session-expiry-notice />` as the first child of `<main>`.

## Tests first

Write these first. They fail to compile before the change, because the modules
do not exist. Use `provideRnForgeAuthTesting(...)` and
`inject(FakeAuthService)`.

1. `user-menu.component.spec.ts`:
    - signed in with `name`, `email`, `picture` and provider `workspace`: the
      toggle has the `img` and the name, and the menu has the email and "Signed
      in with workspace";
    - with no `name`, `email` or `picture`: the toggle shows `subject`, with no
      `img` and no email line;
    - anonymous: no element rendered;
    - with `profileUrl` set and `settingsUrl` unset: one "Profile" link to that
      URL and no "Settings";
    - clicking "Sign out" calls `logout` (spy) once.

    - with `setExpiryWarning(false)`, nothing is rendered; after
      `setExpiryWarning(true)`, the alert is shown;
    - "Sign in again" calls `startLogin` (spy) with `router.url`;
    - dismissing hides it;
    - `setExpiryWarning(false)` then `true` shows it again.
1. `profile.component.spec.ts`: the default rows include `picture`.
