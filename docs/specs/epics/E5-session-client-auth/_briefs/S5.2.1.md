# S5.2.1 — Configuration and session bootstrap

Brief for
[S5.2.1](../F5.2-auth-wrapper.md#s521-configuration-and-session-bootstrap), at
`9edd409`.

## Goal

Replace the JWT client in `@rn-forge/ng/auth` with the configuration, session
types and startup fetch of a same-origin session client
([Design](../design.md)). Delete the JWT and `localStorage` code, and migrate
the code that uses it just far enough to keep `task validate` green. Later
stories add login/logout (S5.2.2), the error-policy interceptor (S5.2.3) and the
new guards (S5.2.4).

## Settled

- **The wire contract** is [Design](../design.md), settled by S5.1.2 on
  2026-11-14: the session body, the default routes and the client routes.

- **Consumers are migrated minimally (owner, 2026-11-15).** F5.2 stories change
  `@rn-forge/ng-bootstrap/auth`, `ng-demo` and the docs only as far as needed
  to keep the gate green. F5.3 replaces the Bootstrap auth UI properly.

- **Config shape** (reviewer, from the S5.2.1 acceptance and Design). This is
  the contract:

    ```ts
    export interface AuthConfig {
      readonly sessionUrl: string;        // '/auth/session'
      readonly providersUrl: string;      // '/auth/providers'
      readonly loginUrl: string;          // '/auth/login'  (provider is appended: `${loginUrl}/${id}`)
      readonly passwordLoginUrl: string;  // '/auth/login/password'
      readonly logoutUrl: string;         // '/auth/logout'
      readonly apiUrls: readonly string[];// ['/api']
      readonly loginPath: string;         // '/login'
      readonly errorPath: string;         // '/login/error'
      readonly forbiddenPath: string;     // '/forbidden'
      readonly loggedOutPath: string;     // '/login'
      readonly xsrfCookieName: string;    // 'XSRF-TOKEN'
      readonly xsrfHeaderName: string;    // 'X-XSRF-TOKEN'
      readonly loopGuardMs: number;       // 10_000
      readonly expiryLeadMs: number;      // 300_000
    }
    export const DEFAULT_AUTH_CONFIG: AuthConfig;          // frozen, the values above
    export const RNF_AUTH_CONFIG_TOKEN: InjectionToken<AuthConfig>; // factory: DEFAULT_AUTH_CONFIG
    export function provideRnForgeAuth(config?: Partial<AuthConfig>): EnvironmentProviders;
    ```

    `provideRnForgeAuth` shallow-merges `config` over the defaults and freezes the
    result (`apiUrls` too). It throws synchronously, with a message starting
    `[rn-forge.ng.auth]` and naming the field, when:

    - any URL or path field, or any `apiUrls` entry, does not start with `/`;
    - `apiUrls` is empty;
    - `loopGuardMs` or `expiryLeadMs` is not a finite number `> 0`;
    - `xsrfCookieName` or `xsrfHeaderName` is empty.

- **XSRF wiring** (reviewer). `withXsrfConfiguration` returns an `HttpFeature`,
  which only `provideHttpClient` accepts. `provideRnForgeAuth` therefore
  spreads `withXsrfConfiguration({ cookieName, headerName }).ɵproviders` into
  its own providers. In Angular 22.2.5,
  `node_modules/@angular/common/fesm2022/_module-chunk.mjs:2019` builds every
  feature as `{ ɵkind, ɵproviders }`, and the XSRF name tokens are root-level
  with factory defaults (`:1072`), so the order of `provideHttpClient` and
  `provideRnForgeAuth` does not matter. Give the reason for reading
  `ɵproviders` in the doc comment. This deviates from ADR-0001's public-API
  preference, and AGENTS.md requires the doc comment to record it.

- **Session types** (reviewer, from Design's session body). Readonly throughout:

    ```ts
    export interface Session {
      readonly subject: string;
      readonly name?: string;
      readonly email?: string;
      readonly picture?: string;
      readonly provider: string;
      readonly roles: readonly string[];
      readonly permissions: readonly string[];
      readonly attributes?: Readonly<Record<string, unknown>>;
      readonly authTime?: string;
      readonly amr?: readonly string[];
      readonly expiresAt: string;
    }
    export interface Credentials {
      readonly isAuthenticated: boolean;
      readonly session: Session | null;
      readonly roles: readonly string[];
      hasPermission(key: string): boolean;
      hasAnyPermission(...keys: string[]): boolean;
    }
    export class AnonymousCredentials implements Credentials { /* session null, roles [], every check false */ }
    export class SessionCredentials implements Credentials { constructor(session: Session) /* checks against session.permissions only */ }
    ```

    `Permission`, `AllowAnyPermission`, `RNF_PERMISSION` and `RNF_CREDENTIALS`
    keep their names and their zero-config defaults. Credentials offer no role
    check and no scope check.

- **Startup** (Design, Client behaviour table). `provideRnForgeAuth` registers
  an app initializer (`provideAppInitializer`) that awaits
  `AuthService.refresh()`:

    - a `200` sets `SessionCredentials(body)`;
    - a `401` sets `AnonymousCredentials`;
    - any other error sets `AnonymousCredentials` and logs once with
      `console.error('[rn-forge.ng.auth] …')`, so the app still starts.

    Startup never navigates. `RNF_CREDENTIALS` is provided as
    `AuthService.credentials`, and `RNF_PERMISSION` is the existing internal
    `CredentialPermission`.

- **`AuthService` after this story** has `credentials: Signal<Credentials>` and
  `refresh(): Observable<Credentials>`, which issues `GET sessionUrl`, maps
  the result as above, sets the signal and emits the new credentials. Outside
  startup, `refresh()` passes non-401 errors to its caller. Nothing else.

- **Interim states, replaced by later stories:**

    - `authHttpInterceptor` is deleted in this story; S5.2.3 adds the new one.
    - `authRouteGuard` stays until S5.2.4, rewritten without `ignoreAppRoutes`. An
      anonymous user is sent to `` `${loginPath}?returnTo=${state.url}` `` (a
      `UrlTree`). A missing `route.data.permission` returns `false`, as it does
      today.
    - `ng-demo` has no Logout menu item until S5.2.2 adds `logout()`.

## Change

- **Change:**
    - `libs/ng/auth/src/lib/auth.config.ts`: the `AuthConfig` contract, defaults
      and token above. Keep `RNF_PERMISSION` and `RNF_CREDENTIALS`.
    - `auth.providers.ts`: `provideRnForgeAuth` (validate, merge, freeze, XSRF
      providers, app initializer, `RNF_CREDENTIALS`, `RNF_PERMISSION`).
      `provideRnForgeAuthConfig` is gone.
    - `auth.types.ts`: `Session`, `Credentials`, `AnonymousCredentials`,
      `SessionCredentials`, `Permission`, `AllowAnyPermission`. Delete
      `LoginResponse`, `UserProfile`, `JwtCredentials` and `JwtToken`.
    - `auth.services.ts`: `AuthService` as settled. Delete `AuthBackendService`
      and every `localStorage`, `LocalStorageService`, `buildUrl` and lodash
      use.
    - `auth.interceptors.ts` and its spec: delete. Remove it from `src/index.ts`.
    - `auth.guards.ts`: the interim `authRouteGuard`.
    - `auth.mixins.ts`: read `RNF_CREDENTIALS` and `RNF_PERMISSION`, expose
      `session: Session | null` instead of `userProfile`, and drop
      `authService`.
    - Rewrite the specs (`auth.*.spec.ts`, `auth.integration.spec.ts`) for the new
      surface. Drop tests of deleted code.
    - `libs/ng/package.json` and the root `package.json`: remove `jwt-decode`.
      Removing a dependency is allowed; adding one is not. Run `task setup` so
      the lock follows.
    - `libs/ng-bootstrap/auth`:
        - `abstract-auth-page.ts`: `get session(): Session | null` replaces
          `userProfile`.
        - `profile.component.ts`: input `profile: InputSignal<Session>`. Default
          rows: subject, name, email, provider, roles (joined), permissions
          (joined), expiresAt.
        - `user.component.html`: render the profile only when `session` is non-null.
        - `auth.component.ts/.html`: drop the JWT form, `AuthBackendService`,
          `users`/`userType` options and the logout mode. When authenticated it
          navigates to the `returnTo` query param (default `/`); when anonymous it
          shows its heading and alert only.
        - `auth-ui.config.ts:22` doc text: name `provideRnForgeAuth`.
        - The specs for these files.
    - `apps/ng-demo`:
        - `app.config.ts`: `provideRnForgeAuth()` with the defaults; no auth
          interceptor in the chain.
        - `app.routes.ts`: the `auth` path becomes `login` (Design's `loginPath`),
          without the `users` option.
        - `app.ts`: drop the `AuthService` injection and the Logout item.
        - `dashboard.page.ts`: welcome with
          `session?.name ?? session?.subject ?? 'user'`, read from
          `RNF_CREDENTIALS`.
        - `mock-api.interceptor.ts`: before the `/api/` check, answer `GET` on a
          path ending `/auth/session` with `200` and a demo session, in both
          `environment.mockProducts` modes. The session has subject `demo-admin`,
          name `Demo Admin`, provider `development`, roles `['admin']`, an
          `expiresAt` far in the future, and permissions `demo.dashboard`,
          `demo.products`, `demo.products.list`, `.read`, `.create`, `.update`,
          `.delete`, `.import`, `.export`, `demo.forms` and `demo.org-chart`.
          Delete the `/api/auth/` JWT mock.
        - `shared/demo-jwt.ts`: delete.
        - `mock-api.interceptor.spec.ts`: update for the above.
    - Docs:
        - `libs/ng/auth/README.md`: document `provideRnForgeAuth`, its fields and
          defaults, and the startup fetch, and list this story's removals as
          breaking changes.
        - `docs/guides/building-an-app.md` and `docs/architecture/configuration.md`:
          replace each mention of the removed API with the new one, or delete it.
          Where the guide shows the interceptor, say an error-policy interceptor

- **Leave alone:** `auth.directives.ts` (its behaviour is unchanged);
