# S5.3.2 — Auth error and forbidden pages

Brief for
[S5.3.2](../F5.3-bootstrap-auth-ui.md#s532-auth-error-and-forbidden-pages), at
`0271c14`.

## Goal

Add the auth error page and the forbidden page to `@rn-forge/ng-bootstrap/auth`.
Route `ng-demo`'s `errorPath` (`/login/error`) and `forbiddenPath`
(`/forbidden`) to them.

## Settled

- **Contract:**

    - [Design](../design.md#error-route-codes) (S5.1.2, 2026-11-14): the closed
      list of error codes, where any other code is shown as `unknown`;
    - the client routes `errorPath` `/login/error?error=<code>` and
      `forbiddenPath` `/forbidden`;
    - the session client reaches these routes from the loop guard and from `403`s
      (F5.2, closed 2026-11-15).

- **Components** (reviewer). Both live in `libs/ng-bootstrap/auth/src/lib/`,
  extend `AbstractAuthPage<ConfigOptions>` and are exported from the entry
  point.

    - `AuthErrorComponent`: selector `rnf-auth-error`, `configKey = 'authError'`,
      in `auth-error/`.
    - `ForbiddenComponent`: selector `rnf-forbidden`, `configKey = 'forbidden'`,
      in `forbidden/`.

    Do not reuse the root `ErrorComponent`. Its messages are fixed per HTTP
    status, and it builds links with `href`.

- **Error page.** It reads the `error` query param through `RouteService` and
  shows a heading "Sign-in problem" and the message for that code, exactly:

    | Code | Message |
    | -- | -- |
    | `access_denied` | Sign-in was cancelled or refused by the identity provider. |
    | `account_not_provisioned` | You signed in, but this application has no account for you. Contact your administrator. |
    | `login_failed` | Sign-in could not be completed. Please try again. |
    | `session_not_established` | Sign-in completed, but no session was established. Check that this site may set cookies, then try again. |
    | any other value, or missing | Sign-in failed for an unknown reason. Please try again. |

    Below the message is a link "Back to sign in", a `routerLink` to `loginPath`
    from `RNF_AUTH_CONFIG_TOKEN`. The raw query value is never rendered.

- **Forbidden page.** It shows a heading "Access denied" and the text "You are
  signed in, but you do not have permission to view this page.", then a
  `routerLink` "Go to the home page" to `/`. It never offers to sign in again:
  no link to `loginPath`, no call to `login` or `startLogin`, and no "sign in"
  wording.

- **Demo routes.** Add top-level routes, before the guarded `''` parent:
  `login/error` → `AuthErrorComponent` and `forbidden` → `ForbiddenComponent`.
  Neither route is guarded, so a forbidden page cannot loop through a guard.

## Current behaviour

At `0271c14`:

- `libs/ng-bootstrap/auth` has no error or forbidden page. Its entry point
  exports `LoginComponent`, `AbstractAuthPage`, the user components and the
  auth UI config. Importing either new component fails to compile.
- `apps/ng-demo/src/app/app.routes.ts`: the routes are `login`, `error` (a 500
  page) and the guarded `''` parent, whose `**` child is a 404 page.
  `/login/error` and `/forbidden` therefore fall through to the 404 page.
- `libs/ng/auth` already navigates to
  `/login/error?error=session_not_established` and to `/forbidden`.

## Tests first

Write these first. They fail to compile before the change, because the modules
do not exist. Use `provideRnForgeAuthTesting(...)` from
`@rn-forge/ng/auth/testing` and `provideRouter([])`, and stub `RouteService`
query params as the login spec does.

1. `auth-error.component.spec.ts`:
    - each of the four codes renders exactly its message;
    - `error=<script>x</script>` and a missing param both render the unknown
      message, and the raw value does not appear in the DOM text;
    - the "Back to sign in" link's `href` is `/login`;
    - with `RNF_AUTH_CONFIG_TOKEN` overridden to `loginPath: '/signin'`, the
      link's `href` is `/signin`.
1. `forbidden.component.spec.ts`:
    - signed in through `provideRnForgeAuthTesting(session)`, it renders the
      heading and the text, with a home link `href` of `/`;
    - no anchor points at `/login`;
    - the text does not match `/sign in/i`;
    - `FakeAuthService.logins` stays empty, and a spy on `startLogin` is never
      called.
