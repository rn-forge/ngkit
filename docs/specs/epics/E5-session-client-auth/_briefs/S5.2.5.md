# S5.2.5 — Testing provider

Brief for [S5.2.5](../F5.2-auth-wrapper.md#s525-testing-provider), at `b829a7e`.

## Goal

Add a `@rn-forge/ng/auth/testing` entry point. Its
`provideRnForgeAuthTesting(session)` seeds credentials, permissions and an
`AuthService` stand-in, with no HTTP call. Unit tests and stories (including
F5.3's component tests) can then render signed-in or anonymous states. Keep it
out of production bundles.

## Settled

- **No switch turns auth off**
  ([Design](../design.md#what-the-client-never-does)). Unit tests and stories
  seed a session through the testing provider instead.

- **Public surface** (reviewer). This is the contract, exported from
  `@rn-forge/ng/auth/testing` only:

    ```ts
    export function provideRnForgeAuthTesting(session: Session | null): EnvironmentProviders;
    export class FakeAuthService {
      readonly credentials: Signal<Credentials>;
      readonly expiryWarning: Signal<boolean>;
      /** Calls recorded by login(); tests assert on them. */
      readonly logins: { provider: string; returnTo: string }[];
      setSession(session: Session | null): void;       // replaces credentials
      setExpiryWarning(value: boolean): void;
      setProviders(providers: readonly AuthProvider[]): void; // default []
      login(provider: string, returnTo: string): void;  // records; never navigates
      startLogin(returnTo: string): void;               // no-op
      loginWithPassword(username: string, password: string): Observable<Credentials>; // of(credentials())
      providers(): Observable<readonly AuthProvider[]>;  // of(the set providers)
      logout(): Observable<void>;                        // setSession(null), then completes
      refresh(): Observable<Credentials>;               // of(credentials())
      clear(): void;                                    // setSession(null)
    }
    ```

    Tests override any method with `vi.spyOn`, e.g. to make `loginWithPassword`
    fail.

- **`provideRnForgeAuthTesting(session)` provides:**

    - `FakeAuthService`, seeded with `session`, as one instance;
    - `{ provide: AuthService, useExisting: FakeAuthService }`;
    - `RNF_CREDENTIALS` as the fake's `credentials`;
    - `RNF_PERMISSION` answering from those credentials. Write a small class in
      the testing entry point; the internal `CredentialPermission` is not
      exported;
    - `RNF_AUTH_CONFIG_TOKEN` as `DEFAULT_AUTH_CONFIG`.

    It provides no app initializer, no XSRF providers and no focus listener, and
    it needs no `HttpClient`.

- **Entry-point layout** follows the existing secondary entry points:

    - `libs/ng/auth/testing/ng-package.json` with
      `{ "lib": { "entryFile": "src/index.ts" } }`;
    - `libs/ng/auth/testing/src/index.ts`;
    - code in `libs/ng/auth/testing/src/lib/`;
    - the path
      `"@rn-forge/ng/auth/testing": ["./libs/ng/auth/testing/src/index.ts"]` in
      `tsconfig.base.json`;
    - `auth/testing/src/**/*.ts` in the `include` of `libs/ng/tsconfig.lib.json`
      and `libs/ng/tsconfig.spec.json`, with its `*.spec.ts` and `*.test.ts`
      excluded in `tsconfig.lib.json`, matching the other entry points.

    The testing code imports only from `@rn-forge/ng/auth`, never from relative
    `../../src` paths, so ng-packagr builds it as its own entry point.

- **Bundle check.** The fake's file holds the string literal
  `rn-forge.ng.auth.testing` (e.g. as a `static readonly marker` on
  `FakeAuthService`). After `pnpm nx build ng-demo`,
  `grep -rl 'rn-forge.ng.auth.testing' dist/apps/ng-demo` must print nothing.
  The demo imports nothing from the testing entry point.

## Current behaviour

At `b829a7e`:

- No `@rn-forge/ng/auth/testing` exists. Importing it fails to resolve, so the
  new spec fails to compile.

- `libs/ng/auth/src/lib/auth.providers.ts`:

    - `:25` holds the internal `CredentialPermission`;
    - `provideRnForgeAuth` registers an app initializer that issues
      `GET /auth/session` and adds a focus listener.

    A component test can therefore seed a session today only by flushing that
    request through `HttpTestingController`.

- `AuthService` (`auth.services.ts`) holds its credentials in a private signal.
  Its public members are `credentials`, `expiryWarning`, `clear`,
  `startLogin`, `login`, `loginWithPassword`, `providers`, `logout` and
  `refresh`.

- `tsconfig.base.json:19-21` maps `@rn-forge/ng/core`, `/auth` and `/crud`.
  `libs/ng/tsconfig.lib.json:10-27` and `tsconfig.spec.json:7-14` list each
  entry point's `src`.

- The consumer check packs the library and imports every subpath in the packed
  `exports`, so a new entry point needs no matrix edit
  ([development.md](../../../../guides/development.md)).

## Tests first

Write these first, in `libs/ng/auth/testing/src/lib/auth.testing.spec.ts`. They
fail to compile before the change, because the module does not resolve.

1. With `provideRnForgeAuthTesting(session)` holding
   `permissions: ['orders.read']` and `provideHttpClientTesting()` present:
    - `inject(RNF_CREDENTIALS)().isAuthenticated` is `true`;
    - `inject(RNF_PERMISSION).hasPermission('orders.read')` is `true`, and
      `'orders.update'` is `false`;
    - `inject(AuthService)` is the `FakeAuthService` instance;
    - `HttpTestingController.verify()` passes: no request was made.
1. With `provideRnForgeAuthTesting(null)`: credentials are anonymous, and every
   permission check is `false`.
1. `setSession` changes what `RNF_PERMISSION` answers.
1. `setExpiryWarning(true)` shows in `inject(AuthService).expiryWarning()`.
1. `login('dev', '/x')` is recorded in `logins`. `logout()` completes and leaves
   credentials anonymous.
1. A component using `HasPermissionDirective` renders its content under a seeded
   permission and not without it.
