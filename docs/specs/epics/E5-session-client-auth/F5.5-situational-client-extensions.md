# F5.5 — Situational client extensions

**Status:** deferred · **Owner:** ngkit · **Epic:** [E5](index.md)

**Entry criteria:** an application needs one of the rows below; that row becomes its own story.

Client support the first version leaves out, each with the trigger that brings it in.

| Extension                | What it adds                                                                                                                                         | Trigger                                                                 |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| Cross-origin credentials | An interceptor that adds `withCredentials` and the XSRF header for an allowlist of API origins, for a SPA and API on sibling subdomains of one site. | An application cannot serve the SPA and API from one origin.            |
| Step-up authentication   | A guard or check on `authTime` and `amr` that starts a fresh login for a recent or multi-factor sign-in.                                             | An application has an action that needs recent or multi-factor sign-in. |
| Tenant switching         | A tenant picker reading the session's `attributes`, and a backend call to change the active tenant.                                                  | An application lets one user act in more than one tenant.               |
| Browser-client profile   | The SPA as an OIDC public client with PKCE, for a SPA with no backend of its own, under the same guards, permission signals and 401/403 policy.      | An application has no backend that can hold a session.                  |
