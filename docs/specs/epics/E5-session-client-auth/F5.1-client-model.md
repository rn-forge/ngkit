# F5.1 — Client model and wire contract

**Status:** elaborating · **Owner:** ngkit · **Epic:** [E5](index.md) · **Release:** [Release 3](../../../releases/release-3/index.md)

The SPA is a client of a same-origin backend session, not an OAuth client. This feature records that choice and settles the contract in [Design](design.md) that the rest of E5 builds against.

## Stories

### S5.1.1 — Accept the session model

**Status:** planned

**Acceptance:** [ADR-0006](../../../adr/ADR-0006.md) states the session model and moves to `accepted`.

### S5.1.2 — Settle the wire contract

**Status:** planned

**Acceptance:** every [open question](#open-questions) is answered or deferred to [F5.5](F5.5-situational-client-extensions.md) with a trigger, and [Design](design.md) agrees with the answers.

## Acceptance

- ADR-0006 is `accepted` and describes the session model (S5.1.1).
- No open question remains below, and Design matches the answers (S5.1.2).

## Design

- **Session client (chosen):** the backend is the confidential OAuth client and SAML service provider; the browser holds an `HttpOnly` session cookie plus a CSRF token. The IETF "OAuth 2.0 for Browser-Based Applications" draft ranks this backend-for-frontend model first for applications that have a backend of their own, and [the HTTP guide](../../../guides/http.md) already prefers a same-origin gateway.
- It removes the OIDC client library, token storage, refresh rotation and the bearer interceptor from the SPA. SAML and social login need no broker, because the backend federates directly.
- The cost is a same-origin deployment and CSRF handling, both in [Design](design.md).

## Open questions

- **Loop-guard window.** How long after a login returns does a `401` count as `session_not_established`? _Default:_ 10 seconds, configurable.
- **Expiry warning lead time.** _Default:_ 5 minutes before `expiresAt`, configurable.
- **Background session refresh.** Focus and after-`403` refetches are in; is an interval refetch also needed? _Default:_ no interval in the first version.
- **Logged-out landing.** Where does `logout()` go when `redirect` is `null`? _Default:_ the login page.

## Considered and rejected

- **Browser OIDC client** (public client with PKCE, tokens in memory, rotating refresh tokens, an OIDC library such as `angular-auth-oidc-client`). Script running in the page can still acquire new tokens; revocation waits for token expiry; SAML and social login would always need a broker that issues OIDC tokens to the SPA; and every application already has a backend. It stays a possible situational profile ([F5.5](F5.5-situational-client-extensions.md)).
- **Token-mediating backend** (the backend runs the login and hands the SPA an access token). It keeps a token within reach of script and adds the backend login flow as well.
