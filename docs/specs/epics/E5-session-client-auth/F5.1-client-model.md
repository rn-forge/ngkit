The SPA is a client of a same-origin backend session, not an OAuth client. This
feature records that choice and settles the contract in [Design](design.md) that
the rest of E5 builds against.

## Design

- **Session client (chosen):** the backend is the confidential OAuth client, and
  reaches SAML identity providers through a broker; the browser holds an
  `HttpOnly` session cookie plus a CSRF token. The IETF "OAuth 2.0 for
  Browser-Based Applications" draft ranks this backend-for-frontend model
  first for applications that have a backend of their own, and
  [the HTTP guide](../../../guides/http.md) already prefers a same-origin
  gateway.
- It removes the OIDC client library, token storage, refresh rotation and the
  bearer interceptor from the SPA. SAML and social login are the backend's
  configuration, never the SPA's.
- The cost is a same-origin deployment and CSRF handling, both in
  [Design](design.md).

## Acceptance

- ADR-0006 is `accepted` and describes the session model (S5.1.1).
- Every open question is answered in [Decisions](#decisions), and Design matches
  the answers (S5.1.2).

## Considered and rejected

- **Browser OIDC client** (public client with PKCE, tokens in memory, rotating
  refresh tokens, an OIDC library such as `angular-auth-oidc-client`). Script
  running in the page can still acquire new tokens; revocation waits for token
  expiry; SAML and social login would always need a broker that issues OIDC
  tokens to the SPA; and every application already has a backend. It stays a
  possible situational profile
  ([F5.5](F5.5-situational-client-extensions.md)).
- **Token-mediating backend** (the backend runs the login and hands the SPA an
  access token). It keeps a token within reach of script and adds the backend
  login flow as well.

## Decisions

Recorded by S5.1.2 (owner decision, 2026-11-14): the four questions left open
take their proposed defaults, and [Design](design.md) states them.

- **Loop-guard window:** a `401` within 10 seconds after a login returns is
  `session_not_established`; configurable.
- **Expiry warning lead time:** 5 minutes before `expiresAt`; configurable.
- **Background session refresh:** focus and after-`403` refetches only; no
  interval refetch in the first version.
- **Logged-out landing:** with `redirect` `null`, `logout()` goes to the login
  page (`loggedOutPath`, default `/login`).

**Checked against the server libraries (2026-11-14).** `rn-forge-fastapi` at
`rn-forge-fastapi-v0.4.1` and `rn-forge-django` at `rn-forge-django-v0.6.1`
serve the same routes, session body, CSRF and error codes in Design. Reading
them changed Design in six places: the `saml` kind is gone (SAML is reached
through a broker, listed as `oidc`); a `403` of type `csrf-failed` renews the
token and retries once; the interceptor handles only `apiUrls`; the CSRF names
are Angular's defaults; the password login can answer `429` and logout `401`;
and the SPA's routes moved out of `/auth`, the prefix the proxy sends to the
backend, with the backend's error route set to the client's.
