# F16.1 — `Invalidation`

**Status:** done · **Implemented:** 2026-10-24 · **Owner:** ngkit · **Epic:** [E16](index.md) · **Release:** [Release 2](../../../releases/release-2/index.md)

**Depends on:** none.

## Stories

### S16.1.1 — The service and its accessor

**Status:** done (2026-10-24)

```ts
@Injectable({ providedIn: 'root' })
export class Invalidation<$Key extends string = string> {
  /** One counter per key, created on first read. Read it inside a request function. */
  version(key: $Key): number;
  /** Increment each key's counter, so every resource that read `version(key)` refetches. */
  invalidate(...keys: $Key[]): void;
}
/** The root `Invalidation`, typed with the application's key union. Runs in an injection context. */
export function injectInvalidation<$Key extends string>(): Invalidation<$Key>;

// app: keys declared once
export type DataKey = 'tracks' | 'dashboard';
// a reader
const invalidation = injectInvalidation<DataKey>();
readonly tracks = httpResource(() => {
  invalidation.version('tracks');
  return `/v1/tracks?${this.query()}`;
});
// a writer
invalidation.invalidate('tracks', 'dashboard');
```

**Acceptance:**

- One `signal<number>` per key, created lazily; `version(key)` reads that signal, so it is reactive inside `httpResource` and `computed`. `invalidate()` with several keys increments each, and a key never read before is created, not an error.
- `invalidate` of one key does not change another key's version.
- `Invalidation` and `injectInvalidation` are exported from `@rn-forge/ng/core`; `injectInvalidation` returns the same root instance as `inject(Invalidation)`.

### S16.1.2 — `httpResource` behaviour

**Status:** done (2026-10-24)

**Acceptance:**

- With `provideHttpClientTesting` and `HttpTestingController`: reading `version('a')` inside a request function and calling `invalidate('a')` issues one new request; `invalidate('b')` issues none for an `a` reader; `invalidate('a', 'b')` refetches an `a` reader and a `b` reader once each in one tick; two readers of one key both refetch.
