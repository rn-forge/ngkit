# F13.4 — Safe release

**Status:** in progress · **Owner:** ngkit · **Epic:** [E13](index.md)

**Depends on:** F13.1 (`-p tag:publishable`, `verify-dist`), S13.2.1 (setup action), S13.2.2 (`ci-ok`, so a green `ci.yml` run means every check passed).

`release.yml` today runs `nx release … --skip-publish`, which commits, tags, **pushes** and creates the GitHub Release, and only then verifies the dist manifests, packs and uploads the tarballs. When any later step fails:

- the tag and an asset-less GitHub Release are already public;
- a rerun resolves the current version from that tag and bumps again, so the failed version is never finished;
- the release never required CI to pass: it re-runs lint, test and build for two projects, and skips e2e, Sonar and `verify-consumer`.

This feature applies [principles 4–6](design.md#principles).

## Design

Recorded by S13.4.1 (owner decision, 2026-09-28).

**The workflow, not `nx release`, publishes.** `nx.json#release.changelog.workspaceChangelog.createRelease` becomes `false`. With no remote release configured, `nx release` commits and tags locally and does not push (Nx's `git.push` defaults to `false`; see [Release pipeline](../../../architecture/release-pipeline.md#pushing-the-release)). The workflow pushes only after every check on the built `dist/` passes, then creates the GitHub Release **with its assets in one command**: `gh release create <tag> <files> --notes-file <file>` creates a draft, uploads the assets, and publishes only after the uploads succeed. The notes are the version's section of `CHANGELOG.md`, which `nx release` still writes.

**The published release is the record.** A version is shipped when its GitHub Release is published (not a draft). Each run first asks whether the commit it runs on already carries a release tag:

| `HEAD` carries a `v*` tag? | Published release for it? | Run does                                                    |
| -------------------------- | ------------------------- | ----------------------------------------------------------- |
| no                         | —                         | a new release (steps 3–8)                                   |
| yes                        | no                        | **resume**: rebuild and verify from the tag, then steps 6–8 |
| yes                        | yes                       | step 8 only (bring `latest` up to date), then succeed       |

A failure before step 5 (push) leaves nothing public; the runner's local commit and tag are discarded, and a rerun computes the same version again.

**The CI gate.** The release runs on the commit `ci.yml` checked. A release commit is pushed with `GITHUB_TOKEN`, which starts no workflow, so in resume mode the gate checks `HEAD^`, the commit the release was cut from.

**Rolling `latest`.** Today it is deleted and recreated, which leaves no `latest` if the create fails. Step 8 becomes idempotent: if `latest` already points at this tag's commit, skip; otherwise delete and recreate as now. A rerun therefore always repairs it. (If the repository enables GitHub's immutable releases, a rolling release with replaced assets is no longer possible; that is out of scope.)

**npm.** Publishing stays a dry run ([ADR-0003](../../../adr/ADR-0003.md)) and runs after the GitHub Release. When npm is re-enabled, resume must also cover a failed publish; the runbook's re-enabling section says so.

### Considered and rejected

- **Re-running `ci.yml` inside the release (`workflow_call`).** It proves the same thing as checking the finished run, at the cost of a second full CI run per release.
- **Keeping `createRelease: "github"` and adding a resume mode.** The tag and an asset-less release would still be public before verification.

## Stories

### S13.4.1 — Decide who publishes

**Status:** done (2026-09-28)

**Acceptance:** this feature's Design records the decision and the rejected options.

### S13.4.2 — Gate on a green CI run

**Status:** done (2026-10-13)

First step after checkout and setup in `release.yml`:

- Resolve the gate SHA: `HEAD^` when `HEAD` carries a `v*` tag, else `HEAD`.
- Pass when `gh run list --workflow ci.yml --commit <sha> --status success --json databaseId --jq length` is at least 1.
- Otherwise fail with a message naming the SHA; in a dry run, print the same message as a warning (`::warning::`) and continue.
- Delete the "Validate (lint, test, build)" step.
- Add `actions: read` to the workflow's permissions.

**Acceptance:**

- `release.yml` has no `lint`, `test` or `e2e` invocation.
- On GitHub, a `dry-run: true` release from a commit with no green `ci.yml` run warns and completes; a `dry-run: false` release from it fails at the gate before any version step.

### S13.4.3 — Verify before anything is public

**Status:** done (2026-10-13)

- `nx.json`: `workspaceChangelog.createRelease: false`.
- New-release path, in order:
  1. `pnpm exec nx release "<specifier or exact-version>" --skip-publish [--first-release]` (local commit and tag only);
  2. resolve the tag with `git tag --points-at HEAD --list 'v*'`; fail if there is not exactly one;
  3. `pnpm exec nx run-many -t pack -p tag:publishable --excludeTaskDependencies`, then `-t verify-dist`, then `-t verify-consumer`, each with `-p tag:publishable --excludeTaskDependencies`;
  4. `git push --atomic origin "HEAD:refs/heads/$GITHUB_REF_NAME" "refs/tags/$tag"`;
  5. `node tools/ci/release-notes.mjs "${tag#v}" > "$RUNNER_TEMP/notes.md"`, then `gh release create "$tag" dist/tarballs/*.tgz --verify-tag --title "$tag" --notes-file "$RUNNER_TEMP/notes.md"`;
  6. `pnpm exec nx release publish --tag="$DIST_TAG" --excludeTaskDependencies [--dry-run] [--first-release]`.
- `tools/ci/release-notes.mjs <version>` prints `CHANGELOG.md`'s section whose `##` heading contains `<version>`, up to the next `##` heading, and exits non-zero when there is none.
- The dry-run path keeps `nx release version … --git-commit=false --git-tag=false --stage-changes=false`, then runs the same step 3 checks and the publish dry run. It pushes and creates nothing.

**Acceptance:**

- In a temporary clone whose `origin` is a local bare repository, running the new-release path's step 1 creates a local tag and leaves the bare repository without it (`git ls-remote --tags` is empty for that tag).
- `node tools/ci/release-notes.mjs 0.1.2` prints the `0.1.2` section of `CHANGELOG.md`; `node tools/ci/release-notes.mjs 9.9.9` exits non-zero.
- In `release.yml`, the `git push` step comes after every `verify-dist` and `verify-consumer` step, and `gh release create` comes after the push (checked by line order in the block below).
- `release.yml` contains no `gh release upload`.

### S13.4.4 — Resume a half-finished release

**Status:** done (2026-10-13)

Implement the Design's table as the step after the gate:

- **Resume:** `pnpm exec nx run-many -t pack verify-dist verify-consumer -p tag:publishable` (with task dependencies: `dist/` is rebuilt from the tagged source, and `resolve-dist-workspace-deps.mjs` stamps the exact internal pins), then the new-release path's steps 5–6.
- **Already released:** skip to S13.4.5's step.
- A published release is one where `gh release view "$tag" --json isDraft --jq '.isDraft'` prints `false`. A leftover draft for the tag is deleted before `gh release create`.

**Acceptance:**

- On GitHub (owner-run, once): after a real release, delete its GitHub Release but keep the tag, rerun **Release** from `main` with `dry-run: false`; it recreates the release with both tarballs and does not bump the version.
- Rerunning once more reports the version as already released and succeeds.

### S13.4.5 — Idempotent rolling `latest`

**Status:** planned

Only on `main`: when `gh release view latest --json targetCommitish` already names this tag's commit, skip. Otherwise do what the step does today (delete `latest` and its tag, retag, recreate with the tarballs and the "Rolling pointer to `<tag>`" note).

**Acceptance:** after S13.4.4's rerun, `latest` points at the same commit as the newest `v*` tag and has both tarballs.

### S13.4.6 — Check the published assets

**Status:** planned

A second job in `release.yml`, `published-install`:

- `needs: release`, runs when not a dry run, reads the tag from a `release` job output;
- checks out the tag, runs the setup action, `gh release download "$tag" --dir dist/tarballs --pattern '*.tgz'`, then `pnpm exec nx run-many -t verify-consumer --excludeTaskDependencies`.

This installs what consumers download, not what the runner built.

**Acceptance:**

- `actionlint` passes; the job exists with `needs: release`.
- On GitHub, the first real release after this change shows `published-install` passing.
- [Release 1](../../../releases/release-1/index.md)'s exit criterion "`verify-consumer` passes on the released tarballs" names this job as its evidence.

### S13.4.7 — Docs

**Status:** planned

**Acceptance:**

- [Release pipeline](../../../architecture/release-pipeline.md)'s "Pushing the release" and "Release workflow" sections describe the gate, the order (version locally → verify → push → release with assets → publish → `latest`), resume, and `published-install`.
- [Releasing](../../../runbooks/releasing.md) says what to do when a release fails: rerun **Release** from the same ref with the same inputs. Its "Verify" list adds `published-install` passing. Its "Re-enabling npm" section notes that resume does not yet retry a failed npm publish.
- `CLAUDE.md`'s release invariant about `createRelease: "github"` is replaced by: the workflow pushes the release commit and tag only after `verify-dist` and `verify-consumer` pass, and creates the GitHub Release with its assets in one step.

## Acceptance

```bash
set -euo pipefail
absent() { local rc=0; rg -q --hidden --glob '!.git' "$@" </dev/null || rc=$?; [ "$rc" -eq 1 ]; }
fails_with() { local out rc=0; out=$("${@:2}" 2>&1) || rc=$?; [ "$rc" -ne 0 ] && grep -qF -- "$1" <<<"$out"; }
wf=.github/workflows/release.yml
# S13.4.2
absent -e '-t lint|-t test|e2e' "$wf"
rg -q 'gh run list --workflow ci.yml' "$wf"
# S13.4.3
[ "$(jq '.release.changelog.workspaceChangelog.createRelease' nx.json)" = false ]
line() { rg -n -m1 -e "$1" "$wf" | cut -d: -f1; }
[ "$(line 'verify-consumer')" -lt "$(line 'git push --atomic')" ]
[ "$(line 'git push --atomic')" -lt "$(line 'gh release create "\$tag"')" ]
absent 'gh release upload' "$wf"
node tools/ci/release-notes.mjs 0.1.2 | rg -q '0\.1\.2'
fails_with '9.9.9' node tools/ci/release-notes.mjs 9.9.9
# An inherited NX_WORKSPACE_ROOT_PATH would make Nx in the clone version this checkout.
unset NX_WORKSPACE_ROOT_PATH
tmp=$(mktemp -d); git init -q --bare "$tmp/origin.git"
git clone -q . "$tmp/work"; cd "$tmp/work"
git remote set-url origin "$tmp/origin.git"; git push -q origin HEAD:refs/heads/main --tags
pnpm install --frozen-lockfile >/dev/null
pnpm exec nx release patch --skip-publish >/dev/null
tag=$(git tag --points-at HEAD --list 'v*'); [ -n "$tag" ]
[ -z "$(git ls-remote --tags origin "refs/tags/$tag")" ]
cd - >/dev/null
# S13.4.6
[ "$(yq '.jobs["published-install"].needs' "$wf")" = release ]
actionlint .github/workflows/*.yml
# S13.4.7
absent 'createRelease: "github"' CLAUDE.md
```
