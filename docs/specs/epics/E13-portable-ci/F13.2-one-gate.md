# F13.2 — One gate

**Status:** done · **Implemented:** 2026-10-13 (`51c4b16`) · **Owner:** ngkit · **Epic:** [E13](index.md)

**Depends on:** nothing. F13.1 can land before or after.

One shared setup, one required check, a Sonar job that neither fails on forks nor passes on a failed quality gate, and Nx Cloud settings that name nothing specific to this repository ([principles 3 and 8](design.md#principles)).

## Stories

### S13.2.1 — Composite setup action

**Status:** done (2026-10-12)

The same four steps (checkout, pnpm, Node, install) are repeated in five jobs across three workflows. Move the last three into `.github/actions/setup/action.yml`, a composite action.

- A local action can only be loaded from a checked-out tree, so **every job keeps its own `actions/checkout` step first** (pinned, `filter: tree:0`, `fetch-depth: 0`), then `uses: ./.github/actions/setup`.
- The action runs `pnpm/action-setup` (pnpm version from `package.json#packageManager`, `run_install: false`), an optional Nx Cloud start step, `actions/setup-node` (`node-version-file: .nvmrc`, `cache: pnpm`, optional `registry-url`), then `pnpm install --frozen-lockfile`.
- Inputs:
  - `start-ci-run` (default empty): when set, the action runs `pnpm dlx nx start-ci-run <value>` after pnpm is installed and before Node and the install, where `ci-cloud` runs it today.
  - `registry-url` (default empty): passed to `setup-node`; `release.yml` sets it for npm OIDC publishing.
- Add `.nvmrc` containing `24`. Nothing in `.github/` states a Node version.

**Acceptance:**

- `pnpm/action-setup`, `actions/setup-node` and `pnpm install` appear in `.github/actions/setup/action.yml` and in no workflow.
- Every job in `ci.yml` and `release.yml` that installs dependencies has `actions/checkout` followed by `./.github/actions/setup`.
- `rg -n 'node-version:' .github` finds nothing.
- `actionlint .github/workflows/*.yml` passes.

### S13.2.2 — `ci-ok` is the one required check

**Status:** done (2026-10-12)

Add a final job to `ci.yml`:

- `if: ${{ always() }}`, `needs:` every other job in the workflow (`ci-cloud`, `ci-local`, `sonar`, `package`, `docs` once F13.3 adds it).
- It fails when any needed job's result is `failure` or `cancelled`, and when neither `ci-cloud` nor `ci-local` is `success`. A `skipped` result otherwise passes (Sonar on Dependabot and fork PRs; `docs` off `main`).
- `timeout-minutes: 5`, `permissions: {}`.

**Acceptance:**

- `actionlint` passes, and the job's `needs` lists every other job id in `ci.yml` (checked by the block below).
- On GitHub, a pull request shows `ci-ok` passing with one of `ci-cloud`/`ci-local` skipped.
- [Releasing](../../../runbooks/releasing.md)'s one-time setup says branch protection requires `ci-ok` and nothing else.

### S13.2.3 — Sonar: guard and gate

**Status:** done (2026-10-12)

- Rename the job `sonarcloud` → `sonar`.
- Keep the Dependabot exclusion, and add the fork guard: the job runs when `github.event_name != 'pull_request' || github.event.pull_request.head.repo.full_name == github.repository`. A fork's pull request has no `SONAR_TOKEN`, so the job would otherwise fail on every external contribution.
- Pass `-Dsonar.qualitygate.wait=true` in the scan action's `args`, with F13.1's discovered report paths. Without the wait the job succeeds on submitting the analysis, and a failed quality gate never fails CI.

**Acceptance:**

- `ci.yml`'s `sonar` job contains the fork guard expression and `sonar.qualitygate.wait=true`.
- On GitHub, a run on `main` shows the scan step waiting for and reporting the quality gate status.

### S13.2.4 — Nx Cloud without repository names

**Status:** done (2026-10-12)

- Rename the launch template in `.nx/workflows/agents.yaml` from `rn-forge-ng` to `linux-medium`.
- `ci-cloud` passes `start-ci-run` the value `--distribute-on="${{ vars.NX_CLOUD_AGENTS || '3' }} linux-medium" --stop-agents-after="lint,test,build,e2e-ci"`.
- In the launch template's pnpm step, drop `corepack prepare pnpm@latest --activate`: it overrides `package.json#packageManager`, so agents can install with a different pnpm than the lockfile was written with. `corepack enable` alone uses the declared version.

**Acceptance:**

- `rg -n 'rn-forge|pnpm@latest' .nx/workflows` finds nothing.
- On GitHub, a `ci-cloud` run distributes to agents from `linux-medium`.

### S13.2.5 — Pins, timeouts, permissions

**Status:** done (2026-10-12)

- Every third-party `uses:` in `.github/` is pinned to a 40-character SHA with a trailing `# v<major>.<minor>.<patch>` comment (today the Sonar action's comment is `# v8`, and `nrwl/nx-set-shas`'s is `# v5`; resolve and write the full versions).
- Every job has `timeout-minutes`.
- `ci.yml`'s top-level `permissions` stays `contents: read` and `actions: read`; any job that needs more declares it on the job.

**Acceptance:** the block below.

## Acceptance

```bash
set -euo pipefail
absent() { local rc=0; rg -q --hidden --glob '!.git' "$@" </dev/null || rc=$?; [ "$rc" -eq 1 ]; }
# S13.2.1
absent -e 'pnpm/action-setup|actions/setup-node|pnpm install' .github/workflows
rg -q 'pnpm install --frozen-lockfile' .github/actions/setup/action.yml
absent 'node-version:' .github
test "$(cat .nvmrc)" = 24
actionlint .github/workflows/*.yml
# S13.2.2 — ci-ok needs every other job
jobs=$(yq '.jobs | keys | .[]' .github/workflows/ci.yml | rg -v '^ci-ok$' | sort)
needs=$(yq '.jobs["ci-ok"].needs[]' .github/workflows/ci.yml | sort)
[ "$jobs" = "$needs" ]
# S13.2.3
rg -q 'head.repo.full_name == github.repository' .github/workflows/ci.yml
rg -q 'sonar.qualitygate.wait=true' .github/workflows/ci.yml
# S13.2.4
absent -e 'rn-forge|pnpm@latest' .nx/workflows
# S13.2.5 — every remote action pinned by SHA with a full version comment
absent -e 'uses: [^.][^@]*@(?![0-9a-f]{40} # v[0-9]+\.[0-9]+\.[0-9]+)' --pcre2 .github
for f in .github/workflows/*.yml; do
  [ "$(yq '[.jobs[] | select(has("timeout-minutes") | not)] | length' "$f")" = 0 ]
done
```

Checked on GitHub: `ci-ok` on a pull request (S13.2.2), the quality-gate wait (S13.2.3), agent distribution (S13.2.4). The owner sets `ci-ok` as the only required check.
