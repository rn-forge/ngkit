# F13.5 — Template contract

**Status:** in progress · **Owner:** ngkit · **Epic:** [E13](index.md)

**Depends on:** F13.1–F13.4 (the files it marks and checks must be in their final form).

Make the template files recognizable, keep them free of repository-specific values by a check that runs in CI, and document what a repository must declare for them to work ([principle 7](design.md#principles)). After this feature, the template files can be copied into another Nx library workspace unchanged, and a copy can be compared byte for byte against its source.

## Design

**Marker.** Each template-owned file listed in [design.md](design.md#template-owned-and-repository-owned) starts with one marker line (after the shebang, where a `.mjs` file has one):

- YAML: `# ci-template: repository-agnostic. Reads only the declarations in docs/architecture/ci-template.md.`
- JavaScript: the same text, after `//` and a space.

A file carries the marker if and only if it is template-owned.

**What counts as repository-specific.** Any of: a project name from `nx show projects`, a project root, the `name` in a project root's `package.json`, the repository name, the Nx Cloud id, a Node or pnpm version, a Sonar project key or organization.

**Recorded during implementation (2026-10-13).** Judgement calls, for the owner to review:

- The workspace root project's root `.` is not a token (it would match every line); its name is.
- `GITHUB_REPOSITORY` contributes both `owner/name` and `name`.
- Files under `docs/` are not template files even when they quote the marker.
- The whole-token rule does not catch a version embedded in a longer identifier: `.nx/workflows/agents.yaml`'s Nx Cloud image `ubuntu22.04-node24.14-v1` names the Node version but passes. Nx Cloud launch templates select a prebuilt image by name, so the template cannot derive it from `.nvmrc`; a repository on a different Node major edits that one line. Accepted as a known exception; revisit if Nx Cloud allows the image to follow `.nvmrc`.

### Considered and rejected

- **Proving portability by generating a fresh Nx workspace in CI and copying the template in.** It needs network access to scaffold, and a generic workspace generator is E11's scope. The token check below catches the drift that matters, a repository value written into a template file.

## Stories

### S13.5.1 — Marker lines

**Status:** done (2026-10-13)

**Acceptance:**

- Every template-owned file in the design table begins with the marker (second line for a file with a shebang).
- `rg -l 'ci-template: repository-agnostic'` lists exactly the files in the design table, nothing else.

### S13.5.2 — The template check runs in CI

**Status:** done (2026-10-13)

`tools/ci/check-template.mjs` (template-owned, carries the marker):

- Finds every tracked file containing the marker (`git ls-files` then read).
- Builds the forbidden-token set per the Design: project names, roots and package names from Nx; the repository name from `GITHUB_REPOSITORY`, else the root directory's name; `nx.json#nxCloudId`; the values in `.nvmrc` and `package.json#packageManager`; `sonar.projectKey` and `sonar.organization` from `sonar-project.properties` when present.
- Matches each token as a whole token (bounded by start or end of line or a character outside `[A-Za-z0-9_@./-]`), and prints `file:line: token` for each hit; exits non-zero on any.
- Prints the list of marked files, so a drift check elsewhere can compare the set.

`ci.yml` gets a `template` job (checkout, setup action, `node tools/ci/check-template.mjs`, `timeout-minutes: 5`), and `ci-ok` needs it.

**Acceptance:**

- `node tools/ci/check-template.mjs` passes on the tree.
- Adding the line `# ng-bootstrap` to `.github/workflows/ci.yml` makes it fail naming that file and `ng-bootstrap`; so does adding `node-version: 24` to the setup action.
- `ci-ok`'s `needs` includes `template`.

  .github/actions/setup/action.yml .github/workflows/ci.yml .github/workflows/release.yml \

  tools/ci/assemble-site.mjs tools/ci/check-template.mjs tools/ci/release-notes.mjs \
