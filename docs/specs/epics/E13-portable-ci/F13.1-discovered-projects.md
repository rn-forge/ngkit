# F13.1 — Discovered projects

**Status:** in progress · **Owner:** ngkit · **Epic:** [E13](index.md)

**Depends on:** nothing.

Replace every project list in CI, release config and CI scripts with Nx discovery ([principles 1–2](design.md#principles)).

## Stories

### S13.1.1 — The `publishable` tag drives release config

**Status:** done (2026-10-12)

- Add the tag `publishable` to `libs/ng/project.json` and `libs/ng-bootstrap/project.json` (keep their existing tags).
- `nx.json#release.projects` becomes `["tag:publishable"]`.
- `nx.json#release.version.preVersionCommand` becomes `pnpm exec nx run-many -t build patch-package-exports -p tag:publishable`.

**Acceptance:**

- The resolved release group from `pnpm exec nx release --printConfig=debug` is exactly `ng` and `ng-bootstrap`.
- `nx.json` contains neither `"ng"` nor `"ng-bootstrap"` nor `--projects=`.
- A release dry run (`pnpm exec nx release version patch --dry-run`) plans the same two projects at the same version as before the change.

### S13.1.2 — `pack` and `verify-dist` are defined once

**Status:** done (2026-10-12)

- Move `tools/scripts/resolve-dist-workspace-deps.mjs` to `tools/ci/`. Replace its hardcoded `libs/` scan: it builds the name→version map from every project root Nx reports (`nx show projects --json`, then `nx show project <p> --json` for `root`, reading `<root>/package.json` where it exists). Keep its CLI (`<dist-package-json-path>`).
- Replace `tools/scripts/verify-dist-manifests.mjs` with `tools/ci/verify-dist-manifest.mjs <dist-dir>`: the same checks, for the one manifest it is given. Delete the old script.
- In `nx.json#targetDefaults`, define:
  - `pack`: `nx:run-commands`, `dependsOn: ["build"]`, `cwd: {workspaceRoot}`, command `node tools/ci/resolve-dist-workspace-deps.mjs dist/{projectRoot}/package.json && mkdir -p dist/tarballs && npm pack ./dist/{projectRoot} --pack-destination dist/tarballs`.
  - `verify-dist`: `nx:run-commands`, `dependsOn: ["pack"]`, `cache: false`, command `node tools/ci/verify-dist-manifest.mjs dist/{projectRoot}`.
- In each publishable `project.json`, replace the full `pack` target with `"pack": {}` and add `"verify-dist": {}`. `ng-bootstrap` keeps its difference as an override only: `"pack": { "dependsOn": ["patch-package-exports"] }`.
- If Nx does not apply a `targetDefaults` executor to an empty target, declare the full target in each project instead, byte-identical, and record that in this feature's Design.

**Acceptance:**

- `pnpm exec nx show project ng --json` and the same for `ng-bootstrap` show `pack` and `verify-dist` with the commands above; `ng-bootstrap`'s `pack` depends on `patch-package-exports`.
- `pnpm exec nx run-many -t verify-dist` passes, and produces both tarballs under `dist/tarballs/`.
- `verify-dist` fails when a dist manifest contains a `workspace:` range: test by editing `dist/libs/ng-bootstrap/package.json` after pack and running `node tools/ci/verify-dist-manifest.mjs dist/libs/ng-bootstrap`.
- `tools/scripts/verify-dist-manifests.mjs` and `tools/scripts/resolve-dist-workspace-deps.mjs` no longer exist; nothing references them.

### S13.1.3 — CI jobs run targets, not project lists

**Status:** done (2026-10-12)

- `ci.yml` `package` job: one step, `pnpm exec nx run-many -t pack verify-dist verify-consumer`, then the existing tarball upload. Delete the separate `node tools/scripts/verify-dist-manifests.mjs` and `nx run ng:verify-consumer` steps.
- `ci.yml` `sonarcloud` job: `pnpm exec nx run-many -t test` with no `--projects`.
- `release.yml`: every `--projects=ng,ng-bootstrap` becomes `-p tag:publishable`; the dist-manifest check becomes `pnpm exec nx run-many -t verify-dist -p tag:publishable --excludeTaskDependencies`. (F13.4 rewrites the rest of this workflow.)
- `ci-local` installs Playwright browsers only when `pnpm exec nx show projects --with-target e2e --json` is non-empty.

**Acceptance:**

- `rg -n 'ng-bootstrap|ng-demo|--projects=' .github/workflows` finds nothing, apart from `pages.yml`, which F13.3 removes.
- `rg -n 'node tools/scripts' .github/workflows` finds nothing.
- `actionlint .github/workflows/*.yml` passes.

### S13.1.4 — Sonar reads discovered coverage

**Status:** in progress

- Remove `sonar.javascript.lcov.reportPaths` from `sonar-project.properties`.
- In the Sonar job, after the tests, compute the list and pass it to the scanner: `reports=$(find coverage -name lcov.info | sort | paste -sd, -)`, failing the step when it is empty, then `-Dsonar.javascript.lcov.reportPaths=$reports` in the action's `args`.

**Acceptance:**

- `sonar-project.properties` contains no `coverage/` path.
- After `pnpm exec nx run-many -t test`, the `find` above lists `coverage/ng/lcov.info`, `coverage/ng-bootstrap/lcov.info` and `coverage/ng-demo/lcov.info`.
- On GitHub, the Sonar analysis of the first run after the change reports coverage for all three projects.

### S13.1.5 — Docs

**Status:** done (2026-10-12)

**Acceptance:**

- [Release pipeline](../../../architecture/release-pipeline.md) describes the `publishable` tag, the `pack`/`verify-dist` target defaults and discovered coverage, and names no deleted script.
- [Development](../../../guides/development.md)'s "Adding a publishable library" says: tag it `publishable`, declare `"pack": {}` and `"verify-dist": {}`, and declare `compodoc`/`verify-consumer` if it has them. It no longer says to edit `nx.json#release.projects`, `preVersionCommand` or any workflow.
- `CLAUDE.md`'s release invariant about `nx.json#release.projects` says "tag it `publishable`" instead.
