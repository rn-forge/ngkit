# F13.3 — Docs job

**Status:** in progress · **Owner:** ngkit · **Epic:** [E13](index.md)

**Depends on:** S13.2.1 (setup action), S13.2.2 (`ci-ok` lists the new job).

`pages.yml` names `ng` and `ng-bootstrap` in five places, deploys on any push touching `libs/**` even when CI fails for that commit, and cancels a deployment in progress. The site becomes a `docs` job in `ci.yml` that runs only after the checks pass, and builds from whichever projects declare the doc targets ([principles 1, 2 and 4](design.md#principles)).

## Design

**Output convention.** A project's `compodoc` writes `dist/compodoc/{projectName}`; its `build-storybook` writes `dist/storybook/{projectName}`. Both are declared in the project, as today.

**Site layout.** `dist/site/api/<project>/` per `compodoc` project, `dist/site/storybook/<project>/` per `build-storybook` project, a generated `index.html`, and `.nojekyll`. Storybook moves from `/storybook/` to `/storybook/ng-bootstrap/`: the layout cannot give one project the root and stay generic. The four links that name `/storybook/` are updated in the same change (S13.3.3).

**Index page.** `assemble-site.mjs` generates `index.html` with the styling of today's `tools/pages/index.html`: the repository name (from `GITHUB_REPOSITORY`, else the root directory name) as the heading, and one card per section entry, labelled with the project name and, where the project root has a `package.json`, its `description`. `tools/pages/` is deleted.

## Stories

### S13.3.1 — `assemble-site.mjs`

**Status:** done (2026-10-13)

`tools/ci/assemble-site.mjs`:

- Reads the projects from `pnpm exec nx show projects --with-target compodoc --json` and `--with-target build-storybook --json`.
- Copies each project's output into the layout above, fails with the project name when an expected output directory is missing, writes `index.html` and `.nojekyll`.
- Takes no arguments; writes `dist/site/`, replacing it if present.

**Acceptance:**

- After `pnpm exec nx run-many -t compodoc build-storybook`, `node tools/ci/assemble-site.mjs` produces `dist/site/api/ng/index.html`, `dist/site/api/ng-bootstrap/index.html`, `dist/site/storybook/ng-bootstrap/index.html`, `dist/site/index.html` and `dist/site/.nojekyll`.
- `dist/site/index.html` links to each of those three sections by relative path.
- With `dist/compodoc/ng` deleted, the script exits non-zero and names `ng`.

### S13.3.2 — The `docs` job replaces `pages.yml`

**Status:** done (2026-10-13)

In `ci.yml`, a `docs` job:

- `needs: [ci-cloud, ci-local]`; runs when one of them succeeded **and** the event is a push to `main` (or `workflow_dispatch` on `main`).
- Skips the build (job succeeds) when no project with a `compodoc` or `build-storybook` target is affected, using `nx show projects --affected --with-target <t>` against the `nx-set-shas` base. A `workflow_dispatch` run always builds.
- Steps: checkout, setup action, `pnpm exec nx run-many -t compodoc build-storybook`, `node tools/ci/assemble-site.mjs`, `actions/configure-pages`, `actions/upload-pages-artifact` (`path: dist/site`, `include-hidden-files: true`), `actions/deploy-pages`.
- Job-level `permissions: { contents: read, pages: write, id-token: write }`, `environment: github-pages`, and `concurrency: { group: pages, cancel-in-progress: false }`, so two pushes never cancel a deployment midway.

Delete `.github/workflows/pages.yml`. `ci-ok` needs `docs`.

**Acceptance:**

- `.github/workflows/pages.yml` does not exist; `actionlint` passes.
- `ci.yml`'s `docs` job names no project.
- On GitHub, a push to `main` that changes `libs/` deploys the site after `ci-cloud` or `ci-local` passes; a pull request shows `docs` skipped and `ci-ok` passing.

### S13.3.3 — Links and docs

**Status:** done (2026-10-13)

**Acceptance:**

- `README.md`, `docs/reference/index.md` and `docs/guides/building-an-app.md` link to `https://rn-forge.github.io/ngkit/storybook/ng-bootstrap/`; no current page links to `…/ngkit/storybook/` alone.
- [Release pipeline](../../../architecture/release-pipeline.md)'s "Docs site" section describes the `docs` job, the output convention and the generated index, and no longer names `pages.yml` or `tools/pages/`.
- [Development](../../../guides/development.md)'s "Adding a publishable library" step for docs says only: declare `compodoc` (and `build-storybook` if it has stories) with the output paths above.
- `CLAUDE.md`'s "Docs site" section says the site is the `docs` job in `ci.yml`.
