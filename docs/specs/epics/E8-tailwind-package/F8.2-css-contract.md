# F8.2 — Tokens, tones, base sheet and Tailwind bridge

**Status:** done · **Implemented:** 2026-10-24 · **Owner:** ngkit · **Epic:** [E8](index.md)

**Depends on:** [F8.1](F8.1-package.md).

The CSS every component and every consumer builds on: `tokens.css`, `base.css` and `tailwind.css` ([ADR-0008](../../../adr/ADR-0008.md), accepted 2026-10-24).

## Design

### Tokens

`tokens.css` declares these on `:root` inside `@layer rnf`, and nothing else. Colours are `light-dark()` pairs; the rest have one value.

| Group     | Tokens (`--rnf-` prefix)                                                                                        |
| --------- | --------------------------------------------------------------------------------------------------------------- |
| Surfaces  | `surface-0` (page), `surface-1` (panel, card), `surface-2` (raised: table header, hover), `surface-3` (overlay) |
| Text      | `text`, `text-muted`, `text-subtle`                                                                             |
| Lines     | `border` (separators), `border-strong` (control boundaries), `focus`                                            |
| Accent    | `accent`, `accent-muted`, `on-accent`                                                                           |
| Tones     | `neutral`, `info`, `success`, `warning`, `danger`                                                               |
| Shape     | `radius-control`, `radius`, `radius-lg`, `radius-pill`                                                          |
| Type      | `font-ui` (`inherit`), `font-data` (`ui-monospace, monospace`), `text-xs`, `text-sm`, `text-md`                 |
| Density   | `control-sm`, `control-md` (control block sizes)                                                                |
| Motion    | `duration-fast`, `duration`, `ease`                                                                             |
| Elevation | `shadow-raised`, `shadow-overlay`                                                                               |

The first eight groups' names are the list E8's prior art already fixed, so an application that built ahead to it renames a prefix and nothing else. Type sizes, density, motion and elevation are added because each surveyed application set them by hand, and one runs at 10–12 px type and 28 px controls that defaults alone would not give it. `info` is added because two of the three needed it.

**Contrast.** In both schemes, `text`, `text-muted` and `text-subtle` reach 4.5:1 on `surface-0`, `-1` and `-2`; `border-strong` and `focus` reach 3:1 on the same surfaces (WCAG 2.1 1.4.11); each tone's text on its own wash reaches 4.5:1. Values are checked from computed CSS in a browser ([F8.4](F8.4-acceptance.md)), not from copied constants. `border` is decorative and has no floor.

**Scheme.** Tokens follow the `color-scheme` of the element that uses them, so a CDK overlay, attached to `body`, inherits the page's scheme, and a subtree with its own `color-scheme` switches. The README shows the three settings: `dark` on `html`, `light dark` to follow the OS, and none (light).

### Tones

A tone is one custom property. A component with a `tone` input sets `--rnf-tone` on its host from the matching token, and derives its wash and border in its own stylesheet with `color-mix(in srgb, var(--rnf-tone) <n>%, transparent)`, so no `-wash` or `-border` token exists per tone. The vocabulary is `neutral | accent | info | success | warning | danger`; components that take a tone ([E9](../E9-presentation-primitives/index.md)) use it. An application with an extra hue sets `--rnf-tone` on the host itself, which the README documents as the escape hatch.

### `base.css` (opt-in)

Inside `@layer rnf`: `body` background `surface-0`, colour `text`, font `font-ui`; `:focus-visible` outline 2 px `focus` with a 2 px offset; `scrollbar-color` from `border-strong` and `surface-0`; `font-variant-numeric: tabular-nums` on `table`; and under `prefers-reduced-motion: reduce`, animations and transitions reduced to a single near-zero iteration. It sets no `box-sizing`, margin reset, `color-scheme` or font family. Visually hidden text uses the CDK's `cdk-visually-hidden` class, which the README points to; the package adds no `sr-only` class.

### `tailwind.css` (opt-in)

One `@theme inline` block, nothing else: `--color-*: initial;`, then

| Tailwind theme variable                                                                   | Maps to                                               |
| ----------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| `--color-surface-0` … `--color-surface-3`                                                 | `--rnf-surface-0` … `-3`                              |
| `--color-fg`, `--color-muted`, `--color-subtle`                                           | `--rnf-text`, `--rnf-text-muted`, `--rnf-text-subtle` |
| `--color-border`, `--color-border-strong`, `--color-focus`                                | the same names                                        |
| `--color-accent`, `--color-accent-muted`, `--color-on-accent`                             | the same names                                        |
| `--color-neutral`, `--color-info`, `--color-success`, `--color-warning`, `--color-danger` | the same names                                        |
| `--radius-control`, `--radius`, `--radius-lg`, `--radius-pill`                            | the radius tokens                                     |
| `--font-ui`, `--font-data`                                                                | the font tokens                                       |
| `--text-xs`, `--text-sm`, `--text-md`                                                     | the type-size tokens                                  |
| `--ease-rnf`, `--shadow-raised`, `--shadow-overlay`                                       | motion and elevation tokens                           |

Deviation: Tailwind v4 reads the bare `rounded` utility from `--radius` (its `theme.css` declares `--radius`, and has no `--radius-DEFAULT`), so the bridge declares `--radius`; the earlier `--radius-DEFAULT` would have mapped nothing. The `--ease-*`, `--shadow-*`, `--text-*` and `--font-*` namespaces are as in Tailwind v4's `theme.css`.

An application's stylesheet with Tailwind is, in order: `@layer theme, base, rnf, components, utilities;`, `@import "@rn-forge/ng-tailwind/tokens.css";`, its own bridge of `--rnf-*` values (and `color-scheme`), `@import "tailwindcss";` (or Tailwind's theme and utilities without preflight) with its own `@source`, then `@import "@rn-forge/ng-tailwind/tailwind.css";`. The statement fixes the layer order: `rnf` sits after `base`, so component styles beat Tailwind's preflight (which resets `button` backgrounds), and before `utilities`, so utilities beat component rules. Unlayered application CSS beats all of them.

Deviation: found by S8.4.3 (2026-10-24). Importing the package sheets before Tailwind declares `rnf` first, which puts it below `base`; preflight's `button { background-color: transparent }` then beat the button's own background. The layer statement is the fix.

### Considered and rejected

- **A `-wash` and `-border` token per tone.** Ten more tokens for values every surveyed application derived from the tone with `color-mix()`.
- **A shipped "no colour literal" lint for applications.** The bridge's `--color-*: initial` already makes default-palette utilities produce nothing, which removes the check two applications hand-wrote; literals in an application's own CSS are its own lint configuration.
- **An `sr-only` utility.** The CDK already ships `cdk-visually-hidden` ([ADR-0001](../../../adr/ADR-0001.md) principle 1).

## Stories

**Acceptance:** the owner accepts [ADR-0008](../../../adr/ADR-0008.md); its status line reads `accepted` with the date, and the [ADR index](../../../adr/index.md) row matches.

### S8.2.2 — `tokens.css`

**Status:** done (2026-10-24)

**Acceptance:**

- `css-contract.spec.ts` parses `tokens.css` with PostCSS: every rule is inside `@layer rnf`, every selector is `:root`, every declaration is a `--rnf-*` custom property, and the set of names is the table above, no more and no fewer.
- Every colour token's value is a `light-dark()` pair; no `color-scheme`, `font-family` or element selector appears.
- The contrast and scheme lines are proven in [F8.4](F8.4-acceptance.md).

### S8.2.3 — `base.css`

**Status:** done (2026-10-24)

**Acceptance:**

- A spec parses `base.css`: every rule is inside `@layer rnf`; the selectors are `body`, `:focus-visible`, `:root` (for `scrollbar-color`) and `table`, plus the reduced-motion block; no `box-sizing`, `margin` reset, `color-scheme` or `font-family` declaration other than `var(--rnf-font-ui)` appears; no colour literal appears.

### S8.2.4 — `tailwind.css`

**Status:** done (2026-10-24)

**Acceptance:**

- The file contains one `@theme inline` block and no `@import`, `@source`, `@layer` or `@tailwind` rule.
- Every `--color-*`, `--radius-*`, `--font-*`, `--text-*`, `--ease-*` and `--shadow-*` it declares, other than `--color-*: initial`, resolves to a `var(--rnf-*)`. That a consumer build emits the mapped utilities and no default-palette ones is proven by [S8.4.1](F8.4-acceptance.md#s841--consumers-build-from-the-tarball).
