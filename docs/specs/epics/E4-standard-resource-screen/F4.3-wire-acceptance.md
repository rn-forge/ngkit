# F4.3 — Accept the screen against a real backend

**Status:** elaborating · **Owner:** ngkit · **Epic:** [E4](index.md)

**Depends on:** a server library, pinned by version or git ref, that implements every row of the standards table and installs outside its own repository. The pin lives in the fixture's own manifest.

Run `ng-demo`'s e2e suite against a real backend that follows the standards in [Resource screen](../../../architecture/resource-screen.md), in place of the demo's mock `/api`. The backend serves one full resource: list with `orderBy`, get, create, patch with `ETag`, delete, `:batchDelete`, `:import` (with `validateOnly`), `:importTemplate` and export. The fixture is ngkit's own test code, like the consumer fixtures of `ng:verify-consumer`.

## Design

Recorded by S4.3.1. The owner's recommendation going in is a Django/DRF stack: its server library supplies every handler above (`:import`, `:importTemplate`, `:batchCreate`, `:batchDelete`, export). A FastAPI stack whose library supplies only export and import parsing would hand-write `:importTemplate` and the batch routes as the fixture's own code.

Either stack is Python, so the e2e job then needs Python and `uv` (S4.3.2).
