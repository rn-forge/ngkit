# F4.2 — Bootstrap renderer and demo

**Status:** done · **Implemented:** 2026-09-23 (`94faba0`) · **Owner:** ngkit · **Epic:** [E4](index.md)

`@rn-forge/ng-bootstrap/crud` renders the [F4.1](F4.1-crud-entry-point.md) controller and keeps no data logic; the demo runs on `standardDataSource()`. The two stories were written together and verified as a whole, because the old upload and download views could not stand alone on the new contract.

## Stories

### S4.2.1 — `ng-bootstrap/crud` renderer

**Status:** done (2026-09-23)

**Acceptance:**

- `AbstractCrudManager` and `CrudComponent` are rewritten over the controller: token paging with no numbered pages, sortable columns writing `orderBy`, declared filters, create, update and delete with `problemToFormErrors`, the 412 reload offer, and batch delete when the data source has it.
- The old types are deleted, and no data logic stays in `ng-bootstrap`.
- `pnpm nx run-many -t lint test build -p ng,ng-bootstrap` passes.

### S4.2.2 — Import, export and demo

**Status:** done (2026-09-23)

**Acceptance:**

- Import is two steps (`validateOnly`, then the report or 422 row errors, then commit) and handles a partial-save 200. Export and the import template are `GET` downloads through `fileNameFrom` and `saveBlob`, hidden when the data source lacks them.
- `apps/ng-demo` `products` runs on `standardDataSource()`, and its mock `/api` speaks the standards table: it is stateful, with `ETag`/`If-Match` 412, `Idempotency-Key` replay, an `orderBy` allow-list, and a `bad*.csv` import returning 422 row errors.
- The `ng-demo-e2e` spec covers sort, filter, two-step import and row errors.
- `libs/ng/README.md`, `libs/ng-bootstrap/crud/README.md` and the [building-an-app guide](../../../guides/building-an-app.md) are updated.
- `pnpm nx run-many -t lint test build -p ng,ng-bootstrap,ng-demo` passes.
- `pnpm nx e2e ng-demo-e2e` passes.
- `pnpm nx run ng:verify-consumer` passes.
